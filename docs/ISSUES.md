### No.1｜教材タイトル・育成人材の呼称 【未決】

### No.2｜研修の総量・期間 【検討中】

- **背景・くわしく**: 助成金要件は訓練 10 時間以上の OFF-JT。企画 MTG では「1日3時間×3ヶ月」案や「300時間」への言及があった（300 の単位は要確認）。長すぎても短すぎても価格と釣り合わない。
- **今のところの方向性**: できるだけ短い時間で最高の満足度に到達することを設計方針とする（2026/6/11 決定。CLAUDE.md に明記）。下限は助成金要件の 10 時間、上限の目安は 100 時間（これを超えると受講満足度が下がるとの所感）。ゴール（自分でアプリを作れる・データ分析ができる）から逆算して設計する。見積もりは多めでなく、ぴったり〜やや少なめ寄りに（AI に見積もらせると多く出がちな点に注意）。破棄済みの OUTLINE.md 初版（40 Section）時点の概算は 25〜40 時間（1 Section 30〜60 分想定、自業務適用の演習を除く）で、上限の目安には収まる見込み。確定は執筆後に積み上げる。2026/6/12 追記: 競合調査の結果、特化型研修の市場相場は 10〜20 時間に集中（AX CAMP 14時間＝動画8h＋実践6h、Uravation 2日12時間 等）。基礎タームをこの相場圏に置き、実践ターム（御社版）で上積みする配分を検討する。

### No.3｜実践（ハンズオン）の軸 【仮決】

- **背景・くわしく**: 一気通貫の実践軸を置くか。候補は「マイプロジェクト方式（受講者が自分の実業務から題材を選び、研修を通して仕様化→実行→仕組み化まで育てる）」「職種別模擬題材で統一」「章ごと独立演習のみ」。
- **今のところの方向性**: 職種別の業務アウトプット題材を多数用意する方針は確定。将来的には「講座内で作りたい題材を選べる」形が理想（企画 MTG）。2026/6/12 仮決: ターム構造に接続して三段構えを実装する。基礎ターム＝共通題材で型、実践ターム＝職種別題材の選択と自業務のマイプロジェクト化（いずれも全受講者共通の教材。御社版は上位プランの構想として No.15 で扱う）。詳細設計は OUTLINE.md（No.13）で行う。同日追記: 実業務をそのまま題材にできるかは未検証（機密情報・会社の許可・題材の粒度）のため、CLAUDE.md の表現は「自分の業務に近い題材を選ぶ」に修正済み。実業務持ち込みの可否と条件は本論点で検討する。

### No.9｜競合との差別化整理 【仮決】

- **背景・くわしく**: 国内には Claude Code 研修が複数存在（短期集中・ツール操作・プロンプト中心が主流）。「基本は同じことを教えるが、何が違うのか」の整理が必要（企画 MTG）。
- **今のところの方向性**: 2026/6/12 に正面に立てる軸を確定した。①**ハーネス**: プロンプト→コンテキスト→ハーネスの3階層のうち、競合はプロンプト中心で、コンテキストまで扱う社はあってもハーネス（AI が確実に働ける環境の設計）を体系として教える研修は調査で未確認。ただし Skill・MCP を単発機能として扱う研修は存在する（Uravation 等）ため、「体系として教える」という正確な限定で訴求する ②**御社版専用教材**: 会社単位セミオーダー。教材自体の個別生成は競合未確認 ③**風化しない研修**: 操作説明止まり・一律カリキュラム・フォロー不在による定着失敗（満足度が高くても数ヶ月で利用が止まる）が業界共通の構造。型＋仕組み化（受講者の Skill・CLAUDE.md が残る）で答える ④**Claude Code 製の自己実証**: 教材・動画・御社版教材を Claude Code のパイプラインで制作している事実を訴求に使う。従来整理の SDD 汎化・Git/GitHub・上流スキル・Web アプリ基礎（概念）は、体系の深さ＝「なぜ風化しないか」の裏付けとして③に従属させ、訴求の正面には立てない。競合比較表の作成は訴求文（No.8）とあわせて行う。2026/6/12 追記: ②御社版専用教材は MVP から外し、上位プランの構想に位置づけを変更した（差別化軸としては維持）。同日、4 軸を 2 本柱＋補強に再構成（CLAUDE.md 反映済み）: 柱①ハーネスまで扱う（持続的に活用できる知見。「風化しない」を統合）、柱②オーダーメイドとアフターサポート（個別化。MVP の職種別題材・マイプロジェクト → 御社版構想・伴走）。自己実証と体系の深さは柱の証明・裏付けに位置づけ。WHY の「浅い」「画一」と 1:1 対応させる。2026/6/12 追記: 柱②の名称は「オーダーメイドとアフターサポート」を維持する（いったん「業務に合わせる個別化」へ変更したが本人判断で差し戻し）。本文は MVP の個別化（職種別題材の選択・自業務を題材にした演習）→その先にオーダーメイド・アフターサポート、の順で記載。なお「マイプロジェクト」という呼称は分かりにくいため CLAUDE.md では使わず、「自業務を題材にした演習」と平易に書く（No.3 の方式名としては存続）。
