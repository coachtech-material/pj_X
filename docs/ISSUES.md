## 詳細

### No.1｜教材タイトル・育成人材の呼称 【未決】

- **背景・くわしく**: 「最強のビジネスマン」という表現は使わない方針。教材タイトルも仮置き（「Claude Code 業務活用カリキュラム」）。
- **今のところの方向性**: CLAUDE.md では呼称を立てず「できること」で定義している。訴求文の作成（No.8）とあわせて決める。

### No.2｜研修の総量・期間 【検討中】

- **背景・くわしく**: 助成金要件は訓練 10 時間以上の OFF-JT。企画 MTG では「1日3時間×3ヶ月」案や「300時間」への言及があった（300 の単位は要確認）。長すぎても短すぎても価格と釣り合わない。
- **今のところの方向性**: できるだけ短い時間で最高の満足度に到達することを設計方針とする（2026/6/11 決定。CLAUDE.md に明記）。下限は助成金要件の 10 時間、上限の目安は 100 時間（これを超えると受講満足度が下がるとの所感）。ゴール（自分でアプリを作れる・データ分析ができる）から逆算して設計する。見積もりは多めでなく、ぴったり〜やや少なめ寄りに（AI に見積もらせると多く出がちな点に注意）。破棄済みの OUTLINE.md 初版（40 Section）時点の概算は 25〜40 時間（1 Section 30〜60 分想定、自業務適用の演習を除く）で、上限の目安には収まる見込み。確定は執筆後に積み上げる。

### No.3｜実践（ハンズオン）の軸 【未決】

- **背景・くわしく**: 一気通貫の実践軸を置くか。候補は「マイプロジェクト方式（受講者が自分の実業務から題材を選び、研修を通して仕様化→実行→仕組み化まで育てる）」「職種別模擬題材で統一」「章ごと独立演習のみ」。
- **今のところの方向性**: 職種別の業務アウトプット題材を多数用意する方針は確定。将来的には「講座内で作りたい題材を選べる」形が理想（企画 MTG）。OUTLINE.md 初版では三段構え（Part 1〜2 は共通題材で型 → Chapter 3-3 で職種別題材を選択 → Chapter 3-4 で自業務をマイプロジェクト化）を提案中。

### No.4｜フリーミアムの範囲・価格設計 【検討中】

- **背景・くわしく**: 冒頭部分を無料で触れるようにし、基本は売り切り型とする案（企画 MTG）。
- **今のところの方向性**: Part 1（体験と全体感）を無料公開範囲の候補として設計する。価格設計・申込フォーム等の仕組み化は別途。

### No.5｜助成金（リスキリング支援コース）要件の精査 【宿題】

- **背景・くわしく**: 人材開発支援助成金「事業展開等リスキリング支援コース」の活用を想定。調査済みの要点（2026年6月時点・Web 調査ベース、申請前に要精査）:
  - 訓練 10 時間以上の OFF-JT が対象
  - 経費助成率は中小企業 75%・大企業 60%、賃金助成 1,000円/h、1事業所あたり年間上限 1億円（企画 MTG の「2,500万円」との差異は要照合）
  - **訓練開始 1 ヶ月前までに計画届の提出が必須**（最大の落とし穴）
  - 2026年3月改正で「人事・人材育成計画に基づく訓練」が対象に拡充、認定支援機関の確認が必要に
  - **制度は 2027年3月31日までの時限措置**
- **今のところの方向性**: 助成金要件を満たさないリスクが常にあるため、要件の一次情報（厚労省）での精査と、受講企業向けの申請ガイド整備が宿題。

### No.6｜docs/（旧 pjX）と README のアーカイブ整理 【未決】

- **背景・くわしく**: 事業はピボット済みで、正は CLAUDE.md / OUTLINE.md に移った。docs/ は旧 pjX の設計資産（思考法・要求整理等の参照元）として残すが、README.md と GitHub Pages（公開サイト）は旧事業の説明のまま。
- **今のところの方向性**: docs/ は当面そのまま参照元として保持。README・Pages の書き換えタイミングは新カリキュラムの公開方針とあわせて決める。

### No.7｜Claude 契約形態別のセットアップ分岐 【仮決】

- **背景・くわしく**: 受講に必要な契約は個人プラン Pro 以上でよい。ただし受講者の環境は Pro/Max から会社契約の Team/Enterprise までさまざまで、契約形態によりセットアップ手順が異なる。
- **今のところの方向性**: 教材本文は契約形態に依存しない書き方とし、セットアップ章でのみ分岐する。管理面の注意（データ保持・組織ポリシー）は教材内で補足する。

### No.8｜売りのストーリー・訴求文 【未着手】

- **背景・くわしく**: 「Claude Code を使って○○ができる人になれる」のベネフィット文型で訴求を作り込む必要がある（企画 MTG）。
- **今のところの方向性**: CLAUDE.md の WHAT（ベネフィット）を土台に、ペルソナ別の訴求例（例: 営業責任者が通話記録プロダクトを自作）へ展開する。導入企業向けベネフィットもここで議論して確定する。未議論のまま CLAUDE.md に記載していた3点（「実業務の成果物で投資を回収できる」「成果物と仕組みが組織に残り属人化しない」「安全に使う型ごと導入でき全社展開の推進者が育つ」）は 2026/6/11 に WHAT から削除済みで、合意後に書き戻す。

### No.9｜競合との差別化整理 【仮決】

- **背景・くわしく**: 国内には Claude Code 研修が複数存在（短期集中・ツール操作・プロンプト中心が主流）。「基本は同じことを教えるが、何が違うのか」の整理が必要（企画 MTG）。
- **今のところの方向性**: 差別化の核は ①ハーネスまで教える（プロンプト→コンテキスト→ハーネスの進化に対応した体系）②SDD を業務全般に汎化した委任の型 ③Git/GitHub による成果物管理 ④思考・仕様化というコンサル由来の上流スキルとの統合。競合比較表の作成は訴求文（No.8）とあわせて行う。
