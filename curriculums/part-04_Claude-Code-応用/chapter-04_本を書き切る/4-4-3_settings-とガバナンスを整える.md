# 4-4-3 settings とガバナンスを整える

!!! note "前提知識"
    このセクションは 4-4-2「サブエージェントで調査・レビューを分担する」、4-3-1「品質とコストの最適化」、4-3-2「ガバナンス」、3-1-4「権限と Plan モードで自律度を選ぶ」の内容を前提としています。

!!! note "このハンズオンで使う機能"
    `settings.json` と権限モード（acceptEdits。Part3 で学習）、モデルと努力レベル（effort）の選び分け（Part4）、機密を渡さない判断（Part4）、必要なら hooks（Part3）を使います。量産に向けて、運用の歯止めを仕組みに織り込みます。

## このセクションで学ぶこと

- `.claude/settings.json` で権限（acceptEdits）を整え、確認の手間を減らす
- 本や公開リポジトリに入れてはいけない情報の線引きを、設定に織り込む
- 章の重さに応じてモデルと努力レベル（effort）を選び分け、コストを抑える
- （任意）hooks で、章ごとの軽い自動チェックを挟む

残りの章を安心して量産できるよう、設定とガバナンスを整えます。

---

## 導入: 量産には「確認疲れ」と「うっかり混入」の対策がいる

残りの章を一気に書こうとすると、編集のたびに確認を求められて手が止まります。かといって何でも自動で通すと、本に入れたくない情報（個人的なメモ、誰かの未公開情報、鍵など）がうっかり混ざる心配があります。

ここで効くのが、Part3 で学んだ権限と、Part4 で学んだガバナンスです。確認を減らすところは減らし、危ないところは止める。この線引きを、毎回の判断に任せず `settings.json` に書いて、プロジェクトの誰が使っても同じ歯止めが効くようにします。

- [ ] 権限モード（とくに acceptEdits）の意味を理解している（Part3）

## 実践: settings とガバナンスを織り込む

### Step 1: 権限を settings.json に設定する

量産では、本文ファイルの編集をいちいち確認するのは大変です。編集を自動で受け入れる acceptEdits を既定にして、確認の手間を減らします。設定ファイル `.claude/settings.json` も、自分で手書きせず Claude に作ってもらいます。

1. Claude に次のように頼む

    ```text
    .claude/settings.json に、編集を既定で自動承認する設定（permissions.defaultMode を acceptEdits）を追加してください。ファイルが無ければ新規に作成してください。
    ```

2. Claude が `.claude/settings.json` を作る（無ければ新規作成）。中身が次のような形になっているか確認する（一例。あなたのものと細部が違ってかまいません）

    ```jsonc
    // my-book/.claude/settings.json（Claude が作る。形の一例）
    {
      "permissions": {
        "defaultMode": "acceptEdits"
      }
    }
    ```

3. 既定モード（`defaultMode`）は起動時に読み込まれるので、Claude Code を一度終了して起動し直すと効く（2026年6月時点。次の Step で足す `deny` などの権限ルールは、書いた時点で反映される）

これで、本文の編集は確認なしで進み、危険度の高い操作だけ確認が残ります（権限モードの詳しい挙動は Part3）。

### Step 2: 機密の線引きを設定に織り込む

本や公開リポジトリに入れたくない情報は、読み取り自体を禁止して、うっかり渡すことを防ぎます。これも Claude に頼んで、`settings.json` の `deny` に触ってほしくないファイルを並べてもらいます。

1. Claude に次のように頼む

    ```text
    .claude/settings.json の permissions に deny を足して、.env ファイルと secrets フォルダを読み取り禁止にしてください。
    ```

2. `.claude/settings.json` が次のような形になっているか確認する（一例）

    ```jsonc
    // my-book/.claude/settings.json（deny を足した例）
    {
      "permissions": {
        "defaultMode": "acceptEdits",
        "deny": [
          "Read(./.env)",
          "Read(./secrets/**)"
        ]
      }
    }
    ```

あわせて、「個人情報や未公開の情報は本に書かない」といった線引きは、CLAUDE.md にも一文で書いておくと、全体の前提として効きます（機密の判断は Part4、コミットしてはいけないものの扱いは Part5 で詳しく扱います）。

### Step 3: 章の重さでモデルと努力レベルを選び分ける

3-5-4 では、第1章は本の顔だからとモデルと努力レベルを上げました。全章を書くときも考え方は同じです。すべての章に最上位のモデルや最大の努力レベルを使うのは無駄なので、難しい章や設計の見直しには力を入れ、ふだんの章は軽め・速めで回します（Part4 で学んだコストの考え方）。切り替えは `/model` や `/effort` で行えます。前のセクションで作った調査役のサブエージェントには、軽いモデルを指定しておくと、調査のコストを抑えられます。

### Step 4: （任意）hooks で章ごとの軽い自動チェックを挟む

毎回手で確かめたい単純なこと（たとえば、章を保存したら禁則の用語が残っていないかを点検する）は、hooks で自動化できます（Part3）。必要なら、Claude に `settings.json` へ hooks を書いてもらい、章を書くたびに軽いチェックが走るようにします。やりすぎると重くなるので、効果の高いものを1つだけ、くらいから始めます。

## まとめ

- 量産では、確認を減らす権限（acceptEdits）と、危ない操作を止める歯止めを `settings.json` に書く
- 本に入れたくない情報は `deny` で読み取りを禁じ、線引きは CLAUDE.md にも一文で残す
- 章の重さでモデル・努力レベルを選び分けてコストを抑える。軽い自動チェックは hooks に任せられる
