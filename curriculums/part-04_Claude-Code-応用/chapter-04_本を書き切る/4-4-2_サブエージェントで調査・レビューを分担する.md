# 4-4-2 サブエージェントで調査・レビューを分担する

!!! note "前提知識"
    このセクションは 4-4-1「requirements・design・tasks で本を設計する」、3-4-2「サブエージェントで並列に任せる」、3-1-6「出力の検証と軌道修正」の内容を前提としています。

!!! note "このハンズオンで使う機能"
    サブエージェント（`/agents` と `.claude/agents/`。Part3 で学習）を使います。調査・裏取りと、完成条件との照合（レビュー）を、別の文脈で動く専用のサブエージェントに任せます。

## このセクションで学ぶこと

- 調査・裏取りを担うサブエージェントを `.claude/agents/` に作る
- 完成条件との照合（レビュー）を担うサブエージェントを作る
- それらを執筆スキルに組み込み、スキルを呼ぶだけで本文の文脈を膨らませずに質を保つ

Part3 で予告された「自分専用のサブエージェントを仕組みに組み込む」を、本づくりで実践します。

---

## 導入: 全章書くと、調査とレビューで本文が埋まる

1冊を書き切るには、章ごとに「事実を調べて裏を取る」「完成条件と照らしてレビューする」を繰り返します。3-5-4 では、このレビューをその場で組み込みサブエージェントに頼みました。1冊ぶん何度も繰り返すなら、役割を決めた専用のサブエージェントを `.claude/agents/` に用意しておくほうが、毎回頼み方を考えずに済み、質も安定します。さらに、調査やレビューをすべてメインの会話でやると、調べた大量のページやレビューのやり取りで、本文を書くための文脈がどんどん埋まっていきます。文脈が膨らむと、精度も速度も落ちます。

そこで、調査とレビューを、別の文脈で動くサブエージェントに切り出します。サブエージェントは独自の文脈で働き、結果の要約だけをメインに返すので、本文の会話はすっきり保たれます。執筆スキルや検証ゲートから呼べば、章を量産しても質が落ちにくくなります。

---

## サブエージェントを作る前の確認

- [ ] `docs/<題材>/`（要件・設計・タスク）と `output/<題材>/`（本文）がそろっている
- [ ] サブエージェントの役割（別文脈・要約だけ返る）を理解している（Part3）
- [ ] `my-book` フォルダで `claude` を起動できる

## 実践: 調査役とレビュー役のサブエージェントを定義する

### Step 1: 調査役のサブエージェントを作る

調査・裏取り専用のサブエージェントを作ります。読み取りと Web 調査だけできれば十分なので、ツールは絞り、軽くて速いモデルを選ぶとコストを抑えられます。

```text
/agents
```

`/agents` を実行すると、サブエージェントを管理するタブ付きの画面（Agents・Running・Library）が開きます（タブ構成は 2026年6月時点）。name や description を直接設定する画面に飛ぶのではなく、次の順に画面が進みます。

1. **Library** タブに切り替え、**Create new agent**（新規作成）を選ぶ
2. 保存先で **Project** を選ぶ（プロジェクトの `.claude/agents/` に保存され、リポジトリに入れてチームで共有できる）
3. **Generate with Claude**（Claude に下書きを作らせる）を選び、次の文章を貼り付ける（自分の本に合わせて言い回しを変えてもよい）

    ```text
    章の執筆に必要な事実・数字・出典を Web で調べて裏取りし、要点だけを箇条書きで返す調査専門のサブエージェントを作ってください。本文は書き換えず、調べた結果の要約だけを返します。名前は researcher にしてください。
    ```

    Claude が name（`researcher`）・description・指示文の下書きを作ります。
4. **ツール** を選ぶ: 「**Read-only tools**」を選ぶ。読み取り（`Read`・`Grep`・`Glob`）に加えて Web 調査（`WebSearch`・`WebFetch`）まで入り、書き込み（`Edit`・`Write`）・実行（`Bash`）・各 MCP サーバーは入らない安全なセットになる（特定のツールを足し引きしたいときだけ **Show advanced options** で個別調整）
5. **モデル** を選ぶ: 軽め・速めの `haiku`（調査は重い推論が要らないため）
6. **色（color）** を選ぶ: サブエージェントの見分け用。どれでもよい
7. **メモリ（memory）** を選ぶ: 学習の蓄積は使わないので `None`
8. 設定概要を確認し、`description` が「いつ使うか」を表しているかを見て、**Enter** で保存する（`e` を押すとエディタで指示文を手直しできる）

### Step 2: レビュー役のサブエージェントを作る

完成条件との照合（レビュー）を担うサブエージェントを作ります。本文を読み、`requirements.md` の完成条件と照らして、満たせていない点を指摘する役です。直接書き換えはさせず、指摘だけ返させると、採否を人が判断できます。

Step 1 と同じ手順で作ります。違うのは貼り付ける文章とモデルだけです。

1. `/agents` → **Library** タブ → **Create new agent** → **Project**
2. **Generate with Claude** を選び、次の文章を貼り付ける

    ```text
    書き上げた章を requirements.md の完成条件と照らし合わせ、満たせていない点を箇条書きで指摘するレビュー専門のサブエージェントを作ってください。本文は書き換えず、指摘だけを返します。名前は reviewer にしてください。
    ```

3. **ツール**: レビュー役も書き込み・実行は渡さないので「**Read-only tools**」
4. **モデル**: 章全体を読んで完成条件と照らすため `sonnet` など中くらいのもの（既定のままでもよい）
5. **色** を選び、**メモリ** は `None`、最後に **Enter** で保存

### Step 3: 執筆スキルに調査・レビューを組み込む

作ったサブエージェントは、メインの会話から直接呼ぶこともできますが、毎章使うなら、3-5 で作った執筆スキルの手順に組み込んでしまうのが確実です。スキル自身に「調査は researcher に、書けた章のレビューは reviewer に任せる」という段取りを持たせ、スキルを呼ぶだけでこの流れが走るようにします。

```text
.claude/skills/ の執筆スキルを、調査とレビューをサブエージェントに任せる段取りに更新してください。
- 事実・数字・出典の裏取りが要るときは、researcher サブエージェントに調べさせて要約だけ受け取る
- 章を書き終えたら、reviewer サブエージェントに requirements.md の完成条件と照らさせて、指摘を受け取る
スキルを呼ぶだけで、執筆の流れの中で調査とレビューがこの形で走るようにしてください。
```

こうしておくと、次の章からは執筆スキルを呼ぶだけで、調査役と検証（レビュー役）が執筆の流れに組み込まれて動きます。メインの会話に返るのは要約と指摘だけなので、本文の文脈は膨らみません。独立した調査なら、複数を並列に走らせることもできます。

!!! warning "注意"
    サブエージェントが詳細をそのまま大量に返すと、結局メインの文脈が埋まります。description に「要約だけを返す」「指摘の箇条書きだけ返す」と書いておくと、戻ってくる量を抑えられます。返りが多すぎたら、その旨を伝えて要約の粒度を調整します。

## まとめ

- 全章の量産では、調査とレビューを別文脈のサブエージェントに分担し、本文の文脈を守る
- 調査役・レビュー役は `.claude/agents/` に定義し、ツールは絞り、調査役は軽いモデルでコストを抑える
- 調査・レビューを執筆スキルに組み込めば、スキルを呼ぶだけで質を保ちながら章を量産できる
