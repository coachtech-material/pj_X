# 5-2-4 コミット・push・プルリクエスト

!!! note "前提知識"
    このセクションは 5-2-3「成果物をリポジトリに上げる」と 5-1-3「ブランチとマージ」の内容を前提としています。

## このセクションで学ぶこと

- 5-2-3 で行ったコミットと push が何だったのかを、言葉として整理する
- プルリクエストとは何か（ブランチの変更を取り込むよう提案する仕組み）
- プルリクエストが、変更をレビューし議論する場であること

実際に手を動かした操作を概念として整理し、その先にあるプルリクエストを押さえます。

!!! note "補足"
    このセクションのコマンドや操作は、仕組みを理解するための例です。コミットと push は 5-2-3 で実際に行いました。プルリクエストを実際に使うのは、協働を扱う 5-2-6 や Part6 の開発です。

---

## 導入: さっき行ったことを、言葉にする

5-2-3 では、Claude Code に頼んで「コミット」と「push」を実際に行い、成果物を GitHub に上げました。流れに沿って進めたので、一つひとつが何だったのかは、まだ言葉になっていないかもしれません。ここで改めて整理します。そのうえで、チームで変更を進めるときに欠かせない、プルリクエストという仕組みを押さえます。

---

## コミットと push: 記録して、リモートへ送る

5-2-3 で行ったのは、次の2つでした。

- **コミット**: 変更を、説明文（コミットメッセージ）付きで手元のリポジトリに記録すること（5-1-2）。「いつ・誰が・何を変えたか」が履歴に残ります。
- **push**: 手元（ローカルリポジトリ）に記録したコミットを、GitHub 上（リモートリポジトリ）へ送ること（5-2-1）。これでリモートに反映され、保全・共有されます。

この2つはセットで使います。手元で意味のまとまりごとにコミットを重ね、節目で push してリモートに反映する、というのが基本のリズムです。どちらも Claude Code に代行させられます。

```text
いまの変更を「○○を修正」というメッセージでコミットして、push して
```

Claude Code は変更内容を踏まえてコミットメッセージのたたき台も提案するので、人はメッセージが中身と合っているかを確認すればよいだけです。

## プルリクエスト: 変更を取り込むよう提案する

一人で作業しているなら、ブランチ（5-1-3）の変更を自分でマージすれば済みます。しかしチームで進める場合は、いきなり本体（main）を変えるのではなく、「この変更を取り込んでよいか」を提案し、他の人に確認してもらってから取り込みます。この提案の仕組みが**プルリクエスト**です。

プルリクエストは GitHub 上の機能で、GitHub 公式ドキュメント（[プルリクエストの作成](https://docs.github.com/ja/pull-requests/collaborating-with-pull-requests/proposing-changes-to-your-work-with-pull-requests/creating-a-pull-request)）は「リポジトリへの変更の提案や共同作業を行う」ものと説明しています。作業ブランチをリモートに push したうえで、次の要素を指定して作ります。

- **base ブランチ**: 変更を取り込む先（ふつう main）。「適用する**場所**」
- **compare（head）ブランチ**: 変更を持っている側（作業ブランチ）。「適用する**内容**」
- **タイトルと説明**: この変更で何を・なぜ行ったか

GitHub の画面では、作業ブランチを push すると「Compare & pull request（比較と pull request）」というボタンが現れます。または **Pull requests** タブから新規に作成し、base と compare を選んでタイトル・説明を書き、**Create pull request** で作成します。プルリクエストを作ると、その変更の差分（どの行が増え・減り・書き換わったか）が一覧で表示され、行ごとにコメントを付けられます。つまりプルリクエストは、変更を取り込む前に**レビューし、議論する場**になります。

このプルリクエストの作成も、Claude Code に頼めます。

```text
いまのブランチの変更で、プルリクエストを作って
```

Claude Code は変更内容からタイトルと説明のたたき台を用意してプルリクエストを作成します。中身を確認するのは人の役割です。レビューして取り込む具体的な流れは、協働を扱う 5-2-6 で詳しく見ます。

!!! info "ポイント"
    プルリクエストは、「変更を提案 → みんなで確認 → 取り込む」という流れを GitHub 上で回す仕組みです。これは、Claude Code が出した変更を人が確認してから取り込む、という本研修の進め方ともそのまま重なります。AI に変更を作らせ、人がプルリクエストでレビューして取り込む、という協働が成り立ちます。

---

## まとめ

- コミットは変更を説明文付きで手元に記録すること、push はそれを GitHub 上（リモート）へ送ること。セットで使い、どちらも Claude Code が代行する
- プルリクエストは、ブランチの変更を本体に取り込むよう提案する GitHub の仕組み。base（取り込み先）と compare（変更を持つ側）を指定して作る
- プルリクエストでは変更の差分が表示され、行ごとにコメントできる。変更をレビューし議論する場になる
- プルリクエストの作成も Claude Code に頼める。AI が出した変更を人がレビューして取り込む協働に使える

---

次のセクションでは、コミットや push で絶対に含めてはいけないものを扱います。APIキー・パスワード・個人情報など公開してはいけないものを 2-5-3 のセキュリティと結びつけて理解し、5-2-3 で置いた .gitignore で追跡対象から除外する考え方と、誤って含めないための確認のしかたを押さえます。
