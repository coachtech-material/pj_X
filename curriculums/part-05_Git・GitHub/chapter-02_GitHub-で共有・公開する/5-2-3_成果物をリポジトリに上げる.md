# 5-2-3 成果物をリポジトリに上げる

!!! note "前提知識"
    このセクションは 5-2-2「GitHub をセットアップする」と 5-1-2「リポジトリ・コミット・履歴」の内容を前提としています。

## このセクションで学ぶこと

- GitHub 上に新しいリモートリポジトリを作成する手順（名前・公開/非公開・README の選び方）
- 手元の成果物を Git のリポジトリにして、初回のコミットと push を Claude Code に代行させ、GitHub に上げる流れ
- 上げる前に、公開してはいけないものを .gitignore で除外すること（考え方は 5-2-5）

これまで作ってきた成果物を、初めて GitHub のリモートリポジトリに保全・共有します。

---

## 導入: 手元の成果物を、リモートに上げて守る

ここまでで、手元の Git（5-1）と、GitHub のアカウント・認証（5-2-2）がそろいました。いよいよ、これまで作ってきた成果物を GitHub に上げます。上げてしまえば、パソコンが壊れても記録は守られ、他の人と共有したり、後で公開したりする土台ができます。

このセクションでは、空のリモートリポジトリを GitHub 上に作り、手元の成果物をそこに接続して push します。実際の git 操作は Claude Code に代行させるので、あなたが手を動かすのは、GitHub の画面でリポジトリを作ることと、Claude Code に依頼することが中心です。

---

## GitHub 上のリモートリポジトリを用意する

成果物を上げる先となる、空のリモートリポジトリを GitHub 上に作ります。作成時に選ぶ主な項目は次の3つです（GitHub 公式ドキュメント[新しいリポジトリの作成](https://docs.github.com/ja/repositories/creating-and-managing-repositories/creating-a-new-repository)）。

- **リポジトリ名**: 成果物が分かる名前（例: `my-book`）
- **公開（Public）／非公開（Private）**: Public は誰でも見られる、Private は自分（と招待した人）だけが見られる
- **README の追加**: プロジェクトの説明ファイルを最初に作るかどうか

本研修では、この成果物を最後に Web サイトとして公開します（5-2-7）。無料プランで公開するには Public（公開）が必要になることが多いので、ここでは **Public** を選びます。公開リポジトリは誰でも見られるので、秘密情報を含めないことが前提です（次の節と 5-2-5 で扱います）。

!!! warning "注意"
    **README は追加しません**（チェックを外したまま作ります）。すでに手元に成果物があるので、空のリモートリポジトリを作って、そこへ手元の内容を push するのが素直です。README を追加するとリモート側に最初のコミットができてしまい、手元の最初の push とぶつかることがあります。公開したくない題材の場合は Private を選んでもかまいませんが、その場合 5-2-7 の公開手順は無料プランでは使えないことがあります。

## 上げる前に、入れてはいけないものを外す

push すると、リポジトリの中身がそのまま GitHub に上がります。公開リポジトリなら、その内容は誰でも見られます。そこで、上げてはいけないもの（APIキーやパスワードなどの秘密情報、パソコン固有の設定ファイル、自動生成される不要物など）を、あらかじめ追跡の対象から外しておきます。これを担うのが **.gitignore** というファイルです。

.gitignore に「無視するファイル」を書いておくと、Git はそれらを記録・push の対象から外します。この設計は Claude Code に任せられます。詳しい考え方は 5-2-5 で扱うので、ここでは「上げる前に .gitignore を置く」という習慣だけ押さえます。

## ローカルからリモートへ push する流れ

手元のフォルダを GitHub に上げるまでの流れは、次のようになります。これらの操作はすべて Claude Code が代行できます（[一般的なワークフロー](https://code.claude.com/docs/ja/common-workflows)）。中身は理解用として眺めてください。

```bash
git init                                              # フォルダをリポジトリにする
git add .                                             # 変更を記録対象に含める
git commit -m "最初のコミット"                          # メッセージを付けて記録する
git remote add origin https://github.com/（あなた）/my-book.git  # リモートを接続する
git branch -M main                                    # 既定ブランチ名を main にそろえる
git push -u origin main                               # リモートへ送る
```

`git remote add origin …` で、手元のローカルリポジトリと GitHub 上のリモートリポジトリを結びつけます（`origin` はリモートにつける慣例の名前）。`git push -u origin main` で、手元のコミットをリモートへ送ります。`-u` を付けて一度 push しておくと、次回からは `git push` だけで同じ送り先に送れます。

## 実践: 成果物を GitHub に上げる

### Step 1: GitHub で新しいリポジトリを作る

ブラウザで GitHub を開き、画面右上の **＋** アイコンをクリックして **New repository** を選びます。次のように設定します。

- **Repository name**: `my-book`（自分の成果物に合わせた名前でかまいません）
- **Public** を選ぶ
- **Add a README file** は **チェックを外したまま**にする

設定したら **Create repository** をクリックします。空のリポジトリができ、次にやることが書かれた Quick Setup の画面が表示されます。この画面に表示されている `https://github.com/（あなたのユーザー名）/my-book.git` のような URL を、後で使うので控えておきます。

### Step 2: 成果物のフォルダで Claude Code を起動し、.gitignore を用意する

これまで作ってきた成果物のフォルダ（このアークでは入門書のフォルダ）に移動して、Claude Code を起動します。そのうえで、上げてはいけないものを除外する .gitignore を作ってもらいます。

```text
このフォルダを GitHub に上げる準備として、.gitignore を作って。
APIキーや認証情報（.env など）、パソコン固有の設定ファイル、自動生成される不要物を除外して。
```

Claude Code は、フォルダの中身を見て .gitignore のたたき台を作ります。たとえば次のような内容になります（これは一例で、あなたのフォルダの中身によって変わります）。

```text
# 環境変数・認証情報
.env
.env.local

# Claude Code のローカル設定
.claude/settings.local.json

# OS が作る一時ファイル
.DS_Store
```

中身を確認し、秘密情報や不要物がきちんと除外対象に入っていればそのまま採用します。

### Step 3: リポジトリにして、コミットして、push する

Claude Code に、Step 1 で控えた URL を渡して、リポジトリ化からアップロードまでを一息で頼みます。

```text
このフォルダを Git のリポジトリにして、いまの内容を最初のコミットとして記録して、
https://github.com/（あなたのユーザー名）/my-book.git に push して。
```

Claude Code は、前の節で示した一連の git 操作（`git init` から `git push` まで）を順に実行します。途中で変更を加える操作には承認を求められるので、内容を確認しながら許可します。コミットメッセージも Claude Code が提案するので、成果物の内容と合っているか確認すれば十分です。「Enumerating objects…」のような進行の表示が流れ、最後にエラーなく終われば、push は成功です。

!!! warning "注意"
    push のとき、想定どおりに進まないことがあります（認証を求められる、ブランチ名が違うなど）。そのときは、エラーの表示をそのまま Claude Code に伝えて、「このエラーが出た。どうすればよいか」と相談すれば、原因の切り分けと対処をしてくれます。自分でコマンドを覚えて直す必要はありません。

### Step 4: GitHub の画面で確認する

ブラウザで、Step 1 で作った GitHub のリポジトリのページを開いて、再読み込みします。さっきまで空だったページに、成果物のファイル一覧が表示されていれば成功です。.gitignore で除外したファイル（`.env` など）が一覧に**無い**ことも確認します。これで、これまで手元だけにあった成果物が、初めて GitHub 上に保全・共有されました。

## まとめ

- 成果物を上げる先として、GitHub 上に空のリモートリポジトリを作る。名前・Public/Private を選び、既存の成果物を push する場合は README を追加しない
- push すると中身がそのまま GitHub に上がる。公開リポジトリは誰でも見られるので、秘密情報や不要物は .gitignore で先に除外する（詳しくは 5-2-5）
- リポジトリ化・コミット・リモート接続・push の一連は Claude Code が代行する。人は GitHub 画面での作成と、Claude Code への依頼・承認を行う
- うまくいかないときは、エラーの表示を Claude Code に伝えて対処してもらう
