## このセクションで学ぶこと

- ファイルとフォルダが階層構造（入れ子）で整理されていること
- 置き場所を一意に示すパスの役割と、絶対パス・相対パスの違い（表記は OS で異なる）
- カレントディレクトリを基点に相対パスが決まること、AI にどのファイルを扱うかをパスで指す意味

ファイルの階層構造を確認し、置き場所を一意に示すパス（絶対パスと相対パス）を、AI への伝え方まで結びつけて押さえます。

!!! note "補足"
    このセクションの本文に出てくるパスやコマンドは、読んで仕組みをつかむための例です。実際に手を動かすのは、セクション末尾の「やってみよう」です。

---

## 導入: 「あの資料」では伝わらない

AI に作業を任せるとき、「あの資料を直して」とだけ伝えても、対象のファイルが一つに定まりません。人間どうしなら文脈で察してくれることも、AI には置き場所を正確に伝える必要があります。その「置き場所の正確な伝え方」が、このセクションで扱うパスです。

!!! quote "現場での考え方"
    自分が一度やらかしたのは、似た名前のファイルがいくつも並ぶフォルダで作業していて、AI に意図と違うほうを編集させてしまったことです。「あの資料、いい感じに直しておいて」のように置き場所をあいまいに伝えると、「どれですか」と聞き返されるか、別のファイルに手が入ってしまいます。それ以来、扱ってほしいファイルはパスで一意に指すようにしています。

## ファイルとフォルダの階層構造

**ファイル** は、文書・画像・データなどを保存する一つひとつの入れ物です。**フォルダ** （ディレクトリ）は、ファイルをまとめて整理する箱で、フォルダの中にさらにフォルダを入れられます。この入れ子の構造を **階層構造** と呼びます。

たとえば、ある記事プロジェクトのフォルダは、このように整理されているかもしれません。

```text
projects/
├── article/
│   ├── draft.md
│   └── images/
│       └── cover.png
└── budget/
    └── 2026.csv
```

projects の中に article と budget があり、article の中に draft.md というファイルと images というフォルダがある、という階層です（末尾の `.md`・`.png`・`.csv` はファイルの種別を示す拡張子で、次の 2-1-3 で扱います）。

## パス: 置き場所を一意に示す住所

この階層のどこにファイルがあるかを、文字で正確に表したものが **パス** です。フォルダをたどる順に、区切り文字でつないで「このファイルはここにある」を一意に示します。パスは住所のようなもの、と考えると分かりやすいです。

区切り文字は、2-1-1 で見たとおり OS で異なります（macOS／Linux は `/` 、Windows は `\` ）。そしてパスには、出発点の違いで2つの示し方があります。

## 絶対パスと相対パス

**絶対パス** は、出発点（ルート）からの完全な道順です。どのフォルダで作業していても、つねに同じ場所を指します。表記は OS で異なり、2-1-1 で示したパス区切りの違いがそのまま表れます。

- macOS／Linux: `/Users/yourname/projects/article/draft.md`
- Windows: `C:\Users\yourname\projects\article\draft.md`

**相対パス** は、いまいる場所（カレントディレクトリ。2-1-1 参照）を基点にした道順です。基点が変われば、同じ相対パスでも指す先が変わります。

- カレントディレクトリが `projects` のとき、`article/draft.md` は先ほどの draft.md を指します。
- `.` は現在地、`..` は一つ上のフォルダを表します（2-1-1 の `cd ..` の「..」がこれです）。たとえばカレントが `article` のとき、`../budget/2026.csv` は budget の中の 2026.csv を指します。

絶対パスは「住所をフルで言う」、相対パスは「いまいる場所からの道案内」と考えると分かりやすいです。

## AI にパスで「どのファイルか」を伝える

ここまでの話が、AI への委任に直結します。Claude Code は、起動したフォルダ（カレントディレクトリ）を作業場所にし、相対パスもそこを基点に解釈します。だから AI に「どのファイルを扱うか」を伝えるとき、パスで一意に指せば取り違えが起きません。

たとえば「`article/draft.md` を読んで、結論を3行で要約して」と伝えれば、対象が一つに定まります。「あの資料」と違い、AI が迷う余地がありません。

この考え方は、ふだんの仕事の整理にもつながります。一つのテーマに関わる資料を一つのフォルダにまとめておき、そのフォルダで Claude Code を起動すれば、AI は関係するファイルをまとめて見渡せます。逆に、必要なファイルがあちこちに散らばっていると、その都度どこにあるかを伝える手間が増えます。作業のまとまりを一つのフォルダにそろえておくほど、AI に任せやすくなります（この「プロジェクトのフォルダ」を起点に作業する進め方は、Part3 以降でも繰り返し出てきます）。

!!! note "補足"
    実際の操作では、`@` を使ってファイルやフォルダを直接 AI に渡す方法もあります。これは Part3（3-1-2）で扱います。いまは「対象はパスで一意に指す」という考え方を押さえれば十分です。

## やってみよう: 移動してパスの変化を見る

カレントディレクトリ（現在地）が変わると、パスの表示がどう変わるかを確かめてみましょう。ここでも書き換えは行いません。

**1. ターミナルを開く**

2-1-1 の「やってみよう」と同じ手順で開きます（macOS: `command`（⌘）キー + スペースキーで Spotlight 検索を開き `terminal` と入力して Enter／Windows: `Windows`（⊞）キー + `X` キーのメニューから「ターミナル」または「Windows PowerShell」をクリック）。

**2. いまの絶対パスを確認する**

`pwd` と打って Enter。いまいるフォルダの絶対パスが表示されます。

```text
/Users/yourname
```

macOS なら `/Users/...` 、Windows なら `C:\Users\...` のような表示です。これが「住所をフルで言った」状態です。

**3. 一つ下のフォルダに移動する**

`ls` で中身を確認し、その中のフォルダ名を一つ選んで移動します。たとえば `Documents` に入る場合は、次のように打って Enter を押します。

```bash
cd Documents
```

**4. もう一度パスを確認する**

再び `pwd` と打って Enter。手順2の絶対パスの末尾に `Documents` が足されているはずです。これは、移動によってカレントディレクトリ（相対パスの基点）が変わったことを表しています。

**5. 元のフォルダに戻る**

`cd ..` と打って Enter。「..」（一つ上）に移動して、手順2の場所に戻ります。`pwd` で戻れたことを確認できます。

!!! success "確認"
    移動するたびに `pwd` の表示（絶対パス）が変わり、`cd ..` で元に戻れれば、カレントディレクトリを基点に場所が決まる感覚をつかめています。

## まとめ

- ファイルとフォルダは入れ子の階層構造で整理され、その置き場所を一意に示す文字列がパス
- 絶対パスはルートからの完全な道順（表記は OS で異なる）、相対パスはカレントディレクトリを基点にした道順（`.` は現在地、`..` は一つ上）
- Claude Code は作業場所を基点に相対パスを解釈するため、AI にはパスで対象を一意に伝えると取り違えが起きない
