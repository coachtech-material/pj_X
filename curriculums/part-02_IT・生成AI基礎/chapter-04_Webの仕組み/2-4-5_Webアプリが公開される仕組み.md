## 導入: 作ったアプリを「世に出す」とは

自分のパソコンの中だけで動くアプリは、自分しか使えません。同僚や顧客に使ってもらうには、誰でもアクセスできる場所にアプリを置く必要があります。この「世に出す」ひと手間が、これから学ぶデプロイ（公開）です。Part6 では、自分のパソコンで動かしたアプリを、ここで学ぶ仕組みで実際にインターネットへ公開します。

---

## デプロイ（公開）とホスティング（置き場＝Cloudflare）

作ったアプリを、誰でも使える形でインターネットに置くことを **デプロイ** （公開）と呼びます。そして、その置き場（アプリを動かし続けてくれる場所）を **ホスティング** と呼びます。

デプロイが済むと、2-4-1 で見たような公開 URL が手に入り、その URL を知っていれば誰でもアプリにアクセスできるようになります。手元のパソコンで動かしていたものが、世界中から使える状態になる、ということです。

本研修では、このホスティングに **Cloudflare** というサービスを使います（2026年6月時点）。Cloudflare は、アプリの置き場とデータベースなどを一つの基盤でまとめて提供していて、すべて無料枠の範囲で試せます。

## Part6 で使う道具に名前を結びつける

ここまで概念で見てきた「画面・処理・保存」（2-4-2）と「データベース」（2-3-1）が、Part6 では具体的な道具の名前を持ちます。いま全部を理解する必要はありません。「この役割は、この道具が担う」と名前だけ結びつけておきます。

| 役割（これまでの言葉） | Part6 で使う道具 |
|---|---|
| 画面（フロント）とサーバ処理 | Next.js（ネクストジェイエス） |
| 保存（データベース） | Cloudflare D1（2-3-1） |
| 置き場（ホスティング） | Cloudflare |

**Next.js** は、画面とサーバ処理の両方を1つでまかなえる道具（フレームワーク）です。2-4-2 で「画面」と「処理」は別の要素だと見ましたが、Next.js を使うとこの2つを一そろいで作れます。これらの道具を実際に組み立て、Cloudflare に公開する作業は、Part6 で Claude Code に任せて行います。

## 秘密の値は環境変数・シークレットでコードと分ける

アプリの中では、2-4-4 で触れた API キーのような、人に見られてはいけない秘密の値を扱うことがあります。これをコードの中に直接書いてしまうと、問題が起きます。コードを公開したり共有したりしたときに、秘密の値まで一緒に見えてしまうからです。

そこで、秘密の値はコードに直接書かず、コードとは別の場所に分けて持ちます。この「分けて持つ秘密の値」を **環境変数** や **シークレット** と呼びます。コードは「秘密の値は外から受け取る」という形にしておき、実際の値は別に安全に保管する、という分け方です。

この扱いも Part6 で AI に任せて設定します。なお、秘密の値を誤って共有しないための具体的な手立て（`.gitignore` で記録対象から外す）は Part5（5-2-3）で、何を秘密として扱うべきかの線引きは次の 2-5-3 で扱います。

## まとめ

- 作ったアプリを誰でも使える形でインターネットに置くことがデプロイ（公開）、その置き場がホスティング（本研修では Cloudflare）
- Part6 では、画面とサーバ処理を Next.js、データベースを Cloudflare D1、置き場を Cloudflare が担う。組み立てと公開は AI に任せる
- API キーなどの秘密の値は、コードに直接書かず、環境変数・シークレットとしてコードと分けて持つ
