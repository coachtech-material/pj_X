# 6-1-3 cc-sdd を導入して仕様駆動の土台を作る

!!! note "前提知識"
    このセクションは、開発環境と Cloudflare の用意（6-1-2）、仕様駆動を要件・設計・タスクの3段で固める考え方（4-2-2）、本づくりでその3段を手で固めた経験（4-4-1）、CLAUDE.md でプロジェクトの前提を渡すこと（3-3-1）を前提とします。

!!! note "このハンズオンで使うもの"
    仕様駆動を進める国産ツール **cc-sdd** を新しく導入します。あわせて、Part3 で学んだスキル（スラッシュコマンドでの呼び出し）と CLAUDE.md の考え方を使います。cc-sdd は、本づくりで手で固めた仕様の「形」を、道具として自動で生成してくれます。

## このセクションで学ぶこと

- cc-sdd を日本語設定で導入し、何がプロジェクトに入るかを確認する
- 作るアプリを伝えて steering（プロジェクト全体の前提ドキュメント）を生成し、中身を読む
- cc-sdd がコマンドと生成物の「形」を揃えること、steering が CLAUDE.md の役割を担う関係を理解する

本づくりで手で固めた仕様の形を、ここでは道具に作らせる土台を整えます。

---

## 導入: 仕様を道具に固めさせる

本づくりでは、いきなり書き始めるとズレが積み重なるのを避けるため、要件・設計・タスクを手で固めてから書き進めました。アプリ開発でも同じです。違うのは、その3段を手で書くのではなく、道具に決まった形で生成させられることです。

その道具が cc-sdd です。cc-sdd は Claude Code 向けに作られていて、スラッシュコマンドで「プロジェクト全体の前提（steering）」と「機能ごとの仕様（要件・設計・タスク）」を、決まった形で生成・管理します。手で固めるときに迷っていた「どんな見出しで、何を、どの順で書くか」を、道具があらかじめ決めてくれるので、出力が毎回ぶれず、同じ手順で進められます。

このセクションでは、cc-sdd を導入し、最初の土台である steering を作ります。機能ごとの仕様（要件・設計・タスク）を作るのは次の章です。

---

## 導入前の確認

- [ ] `ai-minutes` フォルダ（Next.js × Cloudflare の雛形）ができている
- [ ] そのフォルダで `npm run dev` が動き、`claude` を起動できる
- [ ] 仕様駆動の3段（要件・設計・タスク）の考え方を理解している（Part4）

## 実践: cc-sdd で仕様駆動の土台を作る

### Step 1: cc-sdd を導入する

ターミナルで `ai-minutes` フォルダにいることを確認し、次のコマンドを実行します（これは Claude Code の外、ふだんのターミナルで打ちます）。`--claude-skills` で Claude Code のスキルとして入れ、`--lang ja` で日本語設定にします。

```bash
npx cc-sdd@latest --claude-skills --lang ja
```

導入が終わると、スキルと設定ファイルが一式作られます（2026年6月時点で cc-sdd v3.0.2。「○件のファイルを書き込みました」のような結果が表示されます）。

!!! warning "注意"
    cc-sdd はバージョンで導入方法やコマンド名が変わることがあります。うまく進まないときは、表示されたメッセージをそのまま Claude Code に貼り付けて相談してください。`--claude-skills` の代わりに別の指定を案内された場合は、画面の案内に従います（2026年6月時点では `--claude-skills` が推奨です）。

### Step 2: 入ったものを確認する

VS Code で `ai-minutes` フォルダを開くと、新しく次のものが増えています（主なものだけ示します）。

```text
ai-minutes/
├── .claude/
│   └── skills/
│       ├── kiro-steering/           # 前提（steering）を作る・更新する
│       ├── kiro-spec-init/          # 仕様づくりを始める
│       ├── kiro-spec-requirements/  # 要件を作る
│       ├── kiro-spec-design/        # 設計を作る
│       ├── kiro-spec-tasks/         # タスクに分解する
│       ├── kiro-impl/               # タスクを実装する
│       └── …（ほかにレビュー・検証用のスキル）
├── .kiro/
│   ├── steering/    # プロジェクト全体の前提（このあと生成する）
│   ├── specs/       # 機能ごとの仕様（次の章で作る）
│   └── settings/    # スキルが使うテンプレート
└── CLAUDE.md        # cc-sdd の使い方（進め方のルール）
```

`.claude/skills/` に入った `kiro-` で始まるスキルは、Claude Code の中で `/kiro-steering` のように `/` を付けて呼び出せます。それぞれが「前提を作る」「要件を作る」「設計を作る」というように、仕様駆動の各段を担当します。

ここで2種類のファイルの役割を押さえます。

- **CLAUDE.md** （cc-sdd が作ったもの）: cc-sdd の進め方そのものを書いたファイルです。「要件→設計→タスク→実装の順で、各段で人がレビューしてから次へ進む」といったワークフローのルールが書かれていて、Claude Code が起動時に読みます。
- **steering** （このあと作る）: あなたのプロジェクト固有の前提です。何を作るか・どんな技術で・どう並べるかを書きます。

### Step 3: 作るアプリを伝えて steering を生成する

`ai-minutes` フォルダで Claude Code を起動します。

```bash
claude
```

起動したら、steering を作るスキルを呼び出します。このとき、`/kiro-steering` に続けて、これから作るアプリを一言で伝えます。スキルの呼び出しと前提の説明を、次のように1つのメッセージで送ります（説明は自分の言葉に変えてもかまいません）。

```text
/kiro-steering
これから「AI 議事録アプリ」を作ります。会議のメモを貼り付けると、AI が要約・決定事項・ToDo に整形して保存し、あとから一覧・検索できる社内向けのツールです。技術は、画面とサーバ処理を Next.js（Route Handler を API に使う）、データの保存を Cloudflare D1、要約の AI を Cloudflare Workers AI（無料枠の日本語対応モデル）で作ります。認証やログインは作らず、1人で使うシンプルな構成にし、機密の会議メモは入れずデモ用の内容で試す前提です。この前提で steering を作ってください。
```

前提を具体的に書いておくほど、Claude Code が迷わず steering を作れます。それでも前提について確認の質問をしてきたら（たとえば「どの AI を使うか」「保存した記録の公開範囲は」など）、上の説明の範囲で答えます（このアプリはログインを作らず、要約には Cloudflare Workers AI を使い、まずは1人で使うデモとして公開します）。

すると Claude Code は、雛形（package.json や設定ファイル）と、いま伝えたアプリの内容をもとに、`.kiro/steering/` に3つのファイルを作ります。これは Claude が生成するものなので、中身の細部はあなたのものと違ってかまいません。大事なのは、3つの前提ドキュメントがそろうことです。

- `product.md`: 何を作るか（製品の概要・主な機能・対象・価値）
- `tech.md`: どんな技術で作るか（Next.js・Cloudflare などの構成や標準）
- `structure.md`: ファイルやフォルダをどう並べるか（構成・命名の方針）

### Step 4: steering の中身と CLAUDE.md との関係を確認する

生成された `.kiro/steering/product.md` を開いて、AI 議事録アプリの概要が書かれているか確認します。`tech.md` には Next.js や Cloudflare が、`structure.md` には雛形のフォルダ構成が反映されているはずです。狙いと違う部分があれば、Claude Code に「product.md の対象利用者を社内の会議参加者に直して」のように伝えて直してもらい、最終的に自分が「これでよい」と判断したものを正（よりどころ）にします。

ここで、Part3 とのつながりを押さえます。Part3 では、プロジェクトの前提（用語・ルール・進め方）を CLAUDE.md に書いて Claude Code に渡しました。cc-sdd を使うと、その「プロジェクト固有の前提」を steering（product/tech/structure）が担います。CLAUDE.md は cc-sdd の進め方を書いたファイルに役割が移り、プロジェクトの中身は steering に集まります。

!!! note "補足"
    steering は、本づくりで言えば「誰に・何を」を書いた前提や、技術・構成の決めごとにあたります。次の章で作る機能ごとの仕様（要件・設計・タスク）は、この steering を土台にして組み立てられます。土台がぶれないほど、その上に積む仕様も安定します。

## まとめ

- cc-sdd は `npx cc-sdd@latest --claude-skills --lang ja` で導入し、仕様駆動の各段を担うスキル（`/kiro-steering` など）が `.claude/skills/` に入る
- `/kiro-steering` で、プロジェクト全体の前提を表す steering（product・tech・structure）を生成できる
- cc-sdd はコマンドと生成物の「形」を揃えるので、本づくりで手で固めた仕様の形を、道具が自動で作ってくれる
- プロジェクト固有の前提は steering が担い、CLAUDE.md は cc-sdd の進め方を持つ
