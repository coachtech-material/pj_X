# 6-1-2 開発環境とCloudflareを用意する

!!! note "前提知識"
    このセクションは、Part6 で作るものの全体像（6-1-1）、Part1 で行ったターミナル・VS Code・Claude Code のセットアップ、コマンドライン（2-1-1）と、Web アプリが公開される仕組み（2-4-5）を前提とします。

!!! note "このハンズオンで使うもの"
    Part1 で用意したターミナル・VS Code・Claude Code を使います。あわせて、開発に必要な3つの土台を新しく用意します。プログラムを動かす **Node.js** とパッケージ管理の **npm**、Cloudflare 用の雛形を作る **create-cloudflare**、Cloudflare を操作するコマンド **wrangler** です。

## このセクションで学ぶこと

- Node.js とパッケージマネージャを用意し、Cloudflare の無料アカウントを作る
- Next.js を Cloudflare 上で動かすアプリの雛形を作成し、ローカルで起動して画面をブラウザに出す
- 各コマンドをどのフォルダで打つか（作業場所）と、無料枠で完結することを確認する

アプリ開発の最初の関門である環境準備を、一つずつ確実に越えます。

---

## 導入: 開発の最大のつまずきは環境準備

アプリ開発で最初につまずきやすいのは、コードではなく環境の準備です。必要な道具がそろっていなかったり、どのフォルダで何を打つか分からなくなったりして、本題に入る前に止まってしまいます。

このセクションでは、その足場を先に固めます。やることは、プログラムを動かす土台（Node.js）を入れ、Cloudflare の無料アカウントを作り、Next.js を Cloudflare 上で動かすアプリの雛形を1つ作って、自分のパソコンで起動して画面が出るところまでです。ここを越えれば、あとは Claude Code に実装を委ねていけます。

---

## 環境を整える前の確認

始める前に、次がそろっているか確認します。

- [ ] Part1 で Claude Code をインストール・ログインし、ターミナルで `claude` を起動できる
- [ ] Part1 で VS Code を入れ、`code .` でフォルダを開ける
- [ ] ふだん受信できるメールアドレスがある（Cloudflare の登録に使う）
- [ ] インターネットに接続している（ツールのダウンロードに必要）

## 実践: 開発環境と Cloudflare を用意する

### Step 1: Node.js とパッケージマネージャを用意する

Node.js は、JavaScript で書かれたプログラムをパソコン上で動かすための実行環境です。Next.js も Cloudflare の道具も Node.js の上で動きます。Node.js を入れると、パッケージ（部品）を管理する **npm** も一緒に入ります。

Part1 で使ったターミナル（macOS は Terminal、Windows は PowerShell）を開き、OS に合わせて次のいずれかで導入します。

=== "macOS"

    パッケージ管理ツール Homebrew を使っている場合は、次のコマンドを実行します。

    ```bash
    brew install node
    ```

    Homebrew が無い、または分からない場合は、公式サイト（nodejs.org）から macOS 用のインストーラ（LTS 版）をダウンロードして実行します。

=== "Windows"

    次のコマンドを実行します（`winget` は Windows 10／11 に標準で備わっています）。

    ```powershell
    winget install OpenJS.NodeJS.LTS
    ```

    `winget` が使えない場合は、公式サイト（nodejs.org）から Windows 用のインストーラ（LTS 版）をダウンロードして実行します。

導入できたら、ターミナルで次の2つを実行して、バージョンが表示されることを確認します（以降のコマンドは macOS／Windows 共通です）。

```bash
node --version
npm --version
```

`v22.x.x` のように Node.js のバージョンが表示されれば成功です。本研修は **Node.js 20 以降** （できれば LTS）を前提とします（2026年6月時点）。

!!! warning "注意"
    バージョンが表示されない、または「コマンドが見つからない」と出る場合は、ターミナルをいったん閉じて開き直してから再度試します。それでも出ないときは、表示されたメッセージをそのまま Claude Code に貼り付けて「Node.js を入れたのにこう出る。どうすればよいか」と相談すれば、原因の切り分けと対処を教えてくれます。

### Step 2: Cloudflare の無料アカウントを作る

アプリの公開先である Cloudflare のアカウントを作ります。無料枠の範囲で進めるので、料金はかかりません。

1. ブラウザで Cloudflare のダッシュボード（`dash.cloudflare.com`）を開く
2. **Sign up** （新規登録）を選び、メールアドレスとパスワードを入力する
3. 届いた確認メールのリンクを開いて、メールアドレスを確認する
4. ログインして、ダッシュボードのトップ画面が表示されることを確認する

アカウントを作ると、`あなたの名前.workers.dev` のような自分用のサブドメイン（アプリを公開する住所）が自動で割り当てられます。ダッシュボードの **Workers & Pages** の画面（Account Details など）で確認できます。あとでアプリを公開すると、この下に公開 URL ができます（登録の操作は不要です）。

!!! note "補足"
    Workers AI などの無料枠には1日あたりの上限があります（2026年6月時点で Workers AI は1日 10,000 Neurons まで無料）。本研修のデモはこの範囲で完結します。上限や無料枠の条件は変わることがあるため、最新はダッシュボードで確認してください。

### Step 3: Next.js × Cloudflare の雛形を作る

アプリの土台（雛形）を作ります。`create-cloudflare`（C3 と呼ばれる雛形作成ツール）を使うと、Next.js を Cloudflare 上で動かす構成が一式そろった状態で作られます。

作る場所は、**まだ git で管理されていない場所** （ホームフォルダの直下など）にします。Part5 で作った本のフォルダ（`my-book`）の中や、その親フォルダは避けてください。このアプリは独立した1つのプロジェクトとして git で管理し、あとで GitHub に上げて公開するためです。

その場所に移動してから、次のコマンドを実行します。ここでは `ai-minutes` という名前でアプリを作ります。

```bash
npm create cloudflare@latest -- ai-minutes --framework=next --platform=workers
```

実行すると、いくつか質問が表示されます。質問の文言はバージョンで変わりますが、次の2つは意識して選びます。

- **Do you want to use git for version control?** （git で管理するか）と聞かれたら **Yes** を選ぶ。このアプリを、Part5 で学んだ git で管理する独立したプロジェクトにします
- 最後に **Do you want to deploy your application?** と聞かれたら、ここでは **No** （あとで自分で行います）を選ぶ

そのほかの質問（TypeScript を使うかなど）は、そのまま Enter（デフォルト）で進めて問題ありません。しばらく待つと、`ai-minutes` というフォルダが作られ、必要な部品（パッケージ）が自動でインストールされます。

!!! warning "注意"
    git について聞かれたとき、**You're in an existing git repository** （既存の git リポジトリの中にいます）と表示されて、初期選択が **No** になっていることがあります。これは、いま作業している場所が別の git の管理下にあるサインです。このアプリは独立して管理・公開するので、その場合はいったん中止し（`Ctrl + C`）、git で管理されていない別の場所（ホームフォルダの直下など）に移動してから作り直してください。

    質問の意味が分からないときは、表示された質問文をそのまま Claude Code に貼り付けて「これはどう答えるべきか」と聞けます。コマンドが途中で失敗したときも、エラーの表示をそのまま伝えれば、原因と対処を教えてくれます。

### Step 4: 作られたものを確認する

できた `ai-minutes` フォルダに移動して、VS Code で開きます。以降の作業はこのフォルダの中で行います。ターミナルで次を実行します。

```bash
cd ai-minutes
code .
```

左のファイルツリーに、次のようなものが並んでいます（主なものだけ示します）。

```text
ai-minutes/
├── src/
│   └── app/            # 画面（ページ）のファイルが入る
├── public/             # 画像などの静的ファイル
├── package.json        # 使う部品と、npm で実行できるコマンドの一覧
├── wrangler.jsonc      # Cloudflare の設定（このあと D1・AI をここに足す）
├── next.config.ts      # Next.js の設定
├── open-next.config.ts # Next.js を Cloudflare で動かすための設定
├── .dev.vars           # ローカル用の秘密の値（Git に上げない設定済み）
└── .gitignore          # Git に上げないものの一覧
```

中身を今すべて理解する必要はありません。これらのファイルは、このあと Claude Code が読み書きします。いまは「画面は `src/app/`、Cloudflare の設定は `wrangler.jsonc`」という対応だけ頭に入れておけば十分です。

!!! note "補足"
    雛形の `.gitignore` には、最初から `.dev.vars`（ローカル用の秘密の値）や `.env`（環境変数）が「Git に上げない」設定として入っています。秘密の値が誤って公開されないよう、土台の段階で守られています。秘密の扱いは、あとのデプロイのセクションで詳しく扱います。

### Step 5: ローカルで起動して画面を見る

雛形が動くか、自分のパソコンで起動して確かめます。VS Code の統合ターミナル（または同じフォルダで開いたターミナル）で、`ai-minutes` フォルダにいることを確認してから実行します。

```bash
npm run dev
```

ターミナルに `Ready`（起動完了）と表示され、`http://localhost:3000` のような URL が出ます。ブラウザでその URL を開くと、Next.js の初期画面（Next.js のロゴと案内が並んだページ）が表示されます。これは、あなたのパソコンの中だけで動いている、まだ中身が空のアプリです。

確認できたら、ターミナルで `Ctrl + C` を押して、いったん起動を止めます。

!!! success "確認"
    ブラウザで `http://localhost:3000` を開いて、Next.js の初期画面が表示されれば、ローカルで起動できています。

### Step 6: wrangler でログインする

`wrangler` は、Cloudflare をコマンドから操作するための道具です（雛形に最初から入っています）。あとで Claude Code が、このコマンドを使ってデータベースを作ったりアプリを公開したりします。そのために、このパソコンの wrangler を自分の Cloudflare アカウントとつなぎます。

`ai-minutes` フォルダで次を実行します。

```bash
npx wrangler login
```

ブラウザが開き、Cloudflare の認証画面が出ます。**Allow** （許可）を押すと、ターミナルに「Successfully logged in」と表示されます。つながったか確認するには、次を実行します。

```bash
npx wrangler whoami
```

自分のアカウントのメールアドレスが表示されれば、このパソコンから Cloudflare を操作できる状態です。
