# 6-3-3 業務成果に接続して締めくくる

!!! note "前提知識"
    このセクションは、ハーネスに残して保守できるようにしたアプリ（6-3-2）と、Part1 から積み上げてきた進め方の全体を前提とします。

!!! note "このセクションで活かす概念"
    新しい機能は学びません。作ったアプリを業務の成果に結びつけて価値を見積もり、研修全体（課題を定め・AI に実行させ・確かめて仕上げ・残し共有し・仕組みにする、という流れと、プロンプト→コンテキスト→ハーネスの3階層）を振り返って締めくくります。

## このセクションで学ぶこと

- 作ったアプリで削減できる時間・件数を見積もり、内製ツールの価値に接続する
- 題材を自分の業務ツールに置き換える道筋を具体化する
- 研修全体で身につけた進め方を振り返り、次のステップにつなげる

作って終わりにせず、業務の成果につなげるところまでを考えます。

---

## 導入: 作ったアプリは、どの成果につながるか

ここまでで、会議メモを整形する AI 議事録アプリを作り、公開し、保守できる仕組みまで整えました。最後に考えるのは、このアプリが業務のどんな成果につながるか、です。動くものを作れたこと自体も大きな前進ですが、本当の価値は、それが日々の仕事の時間や量を実際に変えるところにあります。

このセクションでは、作ったアプリの価値を自分の言葉と数字で見積もり、そこから「次に自分の業務で何を作るか」を具体化します。そして、研修全体で何を身につけたかを振り返ります。

---

## 内製ツールの価値を見積もる

アプリの価値は、「それを使うと、何が・どれだけ変わるか」で測れます。議事録アプリなら、たとえば次のように見積もれます。

- これまで、会議のあとに議事録を整える時間が1回あたり何分かかっていたか（Before）
- アプリを使うと、その時間が何分になるか（After）
- 1か月にその会議が何回あるか

「1回 20 分 → 5 分」で「月 20 回」なら、月に 5 時間ぶんの時間が空く、という見積もりになります。こうした「削減できた時間」や「処理できる件数」は、内製ツールの価値を表す分かりやすい指標です。外注していた作業を社内で回せるようになった、属人化していた手順が誰でも使える形になった、という変化も価値に含まれます。

大事なのは、完璧な数字を出すことではなく、「このツールはどの成果に効くのか」を自分で説明できることです。

---

## 自分の業務へ広げる

議事録アプリは、題材のひとつにすぎません。ここで身につけた作り方（仕様を固める→データ・処理・AI・画面を実装する→検証する→公開する→仕組みに残す）は、入力と出力がはっきりした業務なら、そのまま応用できます。

- 問い合わせメールを、要点と必要な対応に整形して記録するツール
- 日報を集めて、今週の動きと気になる点にまとめるツール
- 商品情報を渡すと、説明文の下書きを作るツール

題材を自分の業務に置き換え、同じ進め方（cc-sdd で仕様を固め、Cloudflare で動かす）でたどれば、二つ目のアプリは一つ目より速く作れます。技術スタックは教材で固定したものをそのまま使ってもよいですし、業務の事情に合わせて Claude Code と相談して変えても構いません。

---

## 実践: 自分のアプリの価値を見積もる

### Step 1: Before/After で削減を見積もる

作った議事録アプリ（または自分の業務に置き換えたアプリ）について、価値を見積もります。Claude Code に手伝ってもらっても構いません。

```text
この議事録アプリを業務で使うと、どれくらい時間が削減できそうかを一緒に見積もりたいです。会議後の議事録づくりの Before（いまの時間）と After（アプリ利用後）、月の回数から、月あたりの削減時間を計算する手伝いをしてください。
```

「1回あたりの削減時間 × 月の回数」で、月あたりどれだけの時間が空くかを出します。数字は概算で構いません。自分の業務での価値を、具体的な量として言えるようにします。

### Step 2: 次に作るものを1つ決める

修了後に、自分の業務で次に作るアプリを1つ決めます。「入力（渡すもの）」「出力（返してほしいもの）」「それで何が楽になるか」を一言で書き出します。これが、次に同じ進め方を回すときの出発点になります。

!!! success "確認"
    「このアプリは、自分の業務の○○を△△分減らせそう」と数字で言え、「次は□□を作る」と1つ決められれば、このセクションは達成です。

## まとめ: 研修全体の振り返り

最後に、この研修全体で何を身につけたかを振り返ります。

あなたはこの研修を通して、一つの流れを二度たどりました。一度目は、関心のあるテーマで「自分の入門書」を書き、GitHub で公開するまで。二度目は、この Part6 で、AI 議事録アプリを作り、Cloudflare に公開するまでです。どちらも、同じ進め方でした。

- **課題を定める**: 何を作るか、何ができたら完成かを決める
- **AI に実行させる**: 必要な情報を調べさせ、実装を委ねる
- **確かめて仕上げる**: 完成条件と照らし、検証ゲートで一段ずつ収束させる
- **残し・共有する**: Git・GitHub で保全し、公開する
- **仕組みにする**: 手順を Skill・CLAUDE.md・設定として残し、再現できるようにする

この一連を、資料づくり（書籍）でも、実際に動くアプリ開発でも回せたことが、この研修の到達点です。

そして、その土台にあったのが、AI に思いどおり働いてもらう工夫の3階層でした。

- **プロンプト**: その場の指示で動かす
- **コンテキスト**: 前提を渡して動かす（CLAUDE.md・rules・steering）
- **ハーネス**: 確実に働ける環境を組む（Skill・MCP・サブエージェント・hooks・設定）

Part6 では、この3階層をすべて動員して、一つのアプリを作り切りました。

コードを自分で書かなくても、Claude Code に委任して、動くアプリを作り、世に出せます。ここで身につけたのは、特定のツールの操作ではなく、AI に仕事を任せて成果を出し、それを再現可能な仕組みにする進め方です。次は、あなた自身の業務がその題材です。今日作った議事録アプリのように、目の前の業務を一つずつ Claude Code に委ね、仕組みに変えていってください。

---

これで、AI 研修の全カリキュラムは修了です。生成AIに業務を任せる動機から始まり、IT と生成AI の基礎、Claude Code の操作と応用、Git・GitHub、そして実アプリの開発・公開までを通して、AI に委任して成果を出し続ける力を身につけました。ここからは、学んだ進め方を自分の現場で繰り返し、成果を積み上げていく番です。
