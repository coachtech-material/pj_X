# 6-2-2 データ基盤を作る

!!! note "前提知識"
    このセクションは、cc-sdd で固めた仕様（6-2-1）、データベースとは何か（2-3-1）、テストと TDD（2-2-3）、完成条件で確かめる検証ゲート（3-1-6）を前提とします。

!!! note "このハンズオンで使う機能"
    cc-sdd の実装スキル（`/kiro-impl`）で、tasks の該当タスクを Claude Code に実装させます。あわせて、Cloudflare D1（データベース）と Next.js の Route Handler（API）、そして「Claude に検証手段を与える」検証ゲート（テストを先に書かせて通るまで直す）を使います。

## このセクションで学ぶこと

- tasks の該当タスクから、データベース（D1）とメモを登録・取得する API を Claude Code に実装させる
- API の期待する動きをテストで先に決め、通るまで直させる検証ゲートを体験する
- メモを保存・取得できることをローカルで確認する

アプリの土台になる「データの置き場と出し入れ」を、検証しながら作ります。

---

## 導入: まず土台となるデータの保存と出し入れ

アプリは、画面・処理・保存・AI の4部品でできていました。このうち最初に作るのは「保存」と、その出し入れをする「処理（API）」です。ここが動かないと、AI で要約しても残せず、画面に出すデータもありません。

このセクションでは、tasks に沿って、データベース（Cloudflare D1）と、メモを保存・取得する API（Next.js の Route Handler）を Claude Code に作らせます。そして、ここで初めて「Claude に検証手段を与える」進め方を実地で使います。API が期待どおり動くかを確かめるテストを Claude Code に書かせ、実行させ、通るまで直させます。コードは AI が書き、人は「何が確かめられれば完成か」を決めて、結果を確認します。

## 実践: データ基盤（D1）とメモ API を作る

### Step 1: データ基盤のタスクを実装させる

`tasks.md` を開き、データの保存・取得に当たるタスクの番号を確認します。その番号を指定して、実装スキルを呼びます。番号に決まった意味はなく、`tasks.md` が作られた順の通し番号です。同じアプリ・同じ設計なら似た並びになりますが、固定ではないので、その都度 `tasks.md` で確認して指定します。

```text
/kiro-impl （機能名） 1
```

すると Claude Code は、そのタスクの完成条件に沿って実装を進めます。データ基盤では、おおむね次のことを行います。

1. データベース（D1）を作る。Claude Code が `npx wrangler d1 create ai-minutes-db` のようなコマンドを実行します
2. 作られたデータベースの ID を `wrangler.jsonc` のバインディング設定に書く
3. メモを保存するテーブル（表）を、マイグレーション（テーブルを作る手順書）として用意し、ローカルのデータベースに適用する
4. メモを保存・取得する API（Route Handler）を作る

!!! note "補足"
    auto モードでも、データベースの新規作成のような操作は分類器が確認を求めることがあります。表示された内容を読み、`ai-minutes` のための操作だと確認できたら承認します。取り返しのつかない操作（本番への反映など）はこの章ではまだ行いません。

`wrangler.jsonc` のバインディングは、次のような形になります（Claude が書きます。`binding` の `DB` という名前で、コードからデータベースを呼び出せます）。

```jsonc
// ai-minutes/wrangler.jsonc（D1 のバインディングを追加した例）
{
  "d1_databases": [
    {
      "binding": "DB",
      "database_name": "ai-minutes-db",
      "database_id": "（作成時に発行される ID）"
    }
  ]
}
```

### Step 2: テーブルとデータの形を確認する

Claude Code が作ったマイグレーションを開いて、メモをどんな列で保存するかを確認します。design で決めた形に沿っているか（たとえば、メモ本文・要約・決定事項・ToDo・作成日時の列があるか）を見ます。これは Claude が生成するので、列名や型はあなたのものと違ってかまいません。大事なのは、design で決めたデータの持ち方になっていることです。

ローカルのデータベースへの適用は、Claude Code が次のようなコマンドで行います（`--local` は、本番ではなく自分のパソコンの中のデータベースに適用する指定です）。

```bash
npx wrangler d1 migrations apply ai-minutes-db --local
```

!!! warning "注意"
    テーブル設計（どんな列で持つか）は、あとから変えにくいアプリの骨格です。生成された列が、保存したい内容（本文と、AI が作る要約・決定事項・ToDo）をカバーしているかを、ここで確認します。気になる点があれば、design に戻して直してから進めます。

### Step 3: メモ API の形を読む

メモを保存・取得する API（Route Handler）は、`src/app/api/` の下に作られます。中身は次のような形です（これは一例で、あなたのものは違ってかまいません）。Route Handler から、Step 1 で設定した `DB` バインディングを通じてデータベースを読み書きします。

```typescript
// src/app/api/memos/route.ts（Claude が書く。形の一例）
import { getCloudflareContext } from "@opennextjs/cloudflare";

// メモの一覧を返す
export async function GET() {
  const { env } = getCloudflareContext();
  const { results } = await env.DB.prepare(
    "SELECT * FROM memos ORDER BY created_at DESC"
  ).all();
  return Response.json(results);
}

// メモを1件保存する
export async function POST(request: Request) {
  const { env } = getCloudflareContext();
  const { body } = await request.json();
  await env.DB.prepare("INSERT INTO memos (body) VALUES (?)").bind(body).run();
  return Response.json({ ok: true });
}
```

コードを一行ずつ理解する必要はありません。「`/api/memos` という窓口に、一覧を返す処理（GET）と、保存する処理（POST）がある」「データベースは `env.DB` を通じて読み書きする」という形が読み取れれば十分です。

### Step 4: 検証ゲート: テストで期待する動きを確かめる

ここが「Claude に検証手段を与える」進め方の実地です。API が期待どおり動くかを、テストで確かめます。人が「何を確かめたいか」を決め、テストは Claude Code に書かせて回します。次のように頼みます。

```text
メモを保存する API と取得する API について、保存したメモが取得できることを確かめるテストを書いて、実行してください。成功したと言うだけでなく、テストの実行結果を見せてください。通らなければ、原因を直して、通るまで繰り返してください。
```

Claude Code はテストを書き、実行し、結果を読んで、通るまで直します。最後にテストの実行結果（何件中何件成功したか）を示します。あなたは、その結果を見て「保存したメモが取得できる」という完成条件が確かめられたかを判断します。これが検証ゲートです。出力を一致させるのではなく、テストという証拠で合否を決めます。

!!! info "ポイント"
    データベースと API は、同じ入力なら同じ結果が返る（決定論的）ので、テストで合否がはっきり決まります。次のセクションで作る AI 要約は出力が毎回変わるため、テストの当て方が変わります。その違いは次のセクションで扱います。

### Step 5: ローカルで保存・取得を確認する

最後に、自分でも動きを確かめます。`ai-minutes` フォルダで開発サーバーを起動します。

```bash
npm run dev
```

画面はまだ作っていないので、Claude Code に動作確認を頼みます。

```text
開発サーバーが動いている状態で、メモを1件保存して、その後に一覧を取得して、結果を見せてください。
```

保存したメモが一覧に出てくれば、データの保存と出し入れができています。確認できたら `Ctrl + C` で開発サーバーを止めます。

!!! warning "注意"
    想定どおり動かないときは、期待した結果（保存したメモが一覧に出る）と、実際に起きたこと（エラーの表示や、空の一覧が返るなど）を Claude Code に伝えて直してもらいます。エラーの文面はそのまま貼り付けて構いません。

## まとめ

- `/kiro-impl` で tasks の該当タスクを実装させると、Claude Code が D1 の作成・設定・テーブル・API を一通り作る
- データベースは `wrangler.jsonc` のバインディング（`DB`）を通じて、Route Handler から読み書きする
- 「Claude に検証手段を与える」進め方で、API のテストを書かせ・実行させ・通るまで直させ、結果という証拠で合否を決める
- データベースと API は決定論的なので、テストで合否がはっきり決まる

---

次のセクションでは、このデータ基盤の上に、メモを要約・決定事項・ToDo に整形する AI 機能（Cloudflare Workers AI）を作ります。AI の出力は毎回変わるため、検証はテストの一致ではなく「決定事項と ToDo が項目として返る」という挙動で確かめます。無料枠の消費にも気を配ります。
