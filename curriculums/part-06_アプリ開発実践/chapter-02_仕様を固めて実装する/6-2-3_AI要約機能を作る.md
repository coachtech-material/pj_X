# 6-2-3 AI要約機能を作る

!!! note "前提知識"
    このセクションは、データ基盤とメモ API（6-2-2）、生成AIの限界とリスク（2-5-2）を前提とします。

!!! note "このハンズオンで使う機能"
    Cloudflare Workers AI（クラウド上で動く AI）を使います。あわせて、cc-sdd の実装スキル（`/kiro-impl`）と、AI の出力が毎回変わることを踏まえた検証（出力の一致ではなく挙動で確かめる）を使います。

## このセクションで学ぶこと

- メモを要約・決定事項・ToDo に整形する AI 機能（Workers AI）を Claude Code に実装させる
- AI の出力は毎回変わるため、検証を「3項目が返る」という挙動で行う（決定論的テストとの違い）
- 無料枠の消費に気を配りながらデモを成立させる

データ基盤の上に、このアプリの中心である AI 要約をのせます。

---

## 導入: メモを要約・決定事項・ToDo に整形する

前のセクションで、メモを保存・取得する土台ができました。ここに、このアプリの主役を加えます。貼り付けた会議メモを、AI が「要約・決定事項・ToDo」の3つに整形する機能です。

要約には Cloudflare の Workers AI を使います。用意した Cloudflare アカウントの無料枠で動き、別の AI サービスの契約や API キーは要りません。tasks の該当タスクを Claude Code に実装させ、メモを渡すと整形結果が返って保存されるところまでを作ります。

ひとつ大事な前提があります。Workers AI は、自分のパソコンで動かすとき（`next dev`）も、実際の処理（推論）は Cloudflare 上で行われます。データベース（D1）はパソコンの中で模擬できますが、AI の推論は模擬できないためです。そこで、AI のバインディングだけは「ローカルで動かしていても実際の Cloudflare につなぐ」設定（remote bindings）にします。この設定は次の Step で行います（これをしないと、AI を呼ぶ段階で設定が足りないと止まります）。

ここで、前のセクション（データ基盤）とは検証のしかたが変わります。データベースは同じ入力なら同じ結果が返りましたが、AI の出力は毎回少しずつ変わります。だから「この文字列が返る」ではなく「要約・決定事項・ToDo の3項目がそろって返る」という挙動で確かめます。

## 実践: AI 要約機能（Workers AI）を作る

### Step 1: Workers AI を使えるようにする

まず、アプリから Workers AI を呼べるようにします。`wrangler.jsonc` に AI のバインディングを足し、あわせて、ローカル開発でも実際の Cloudflare の AI につなぐ設定（`experimental_remote`）も付けます。Claude Code に頼みます。

```text
wrangler.jsonc に Workers AI のバインディング（binding は AI）を足してください。Workers AI はローカルでは模擬できないので、next dev でも実際の Cloudflare につながるように、この AI バインディングを remote bindings（experimental_remote を true）にしてください。設定の細かい書き方は、いまの wrangler のバージョンに合わせてください。
```

`wrangler.jsonc` が次のような形になります（一例。設定の名前は版で変わることがあるので、細部は Claude Code に合わせてもらいます）。

```jsonc
// ai-minutes/wrangler.jsonc（AI を remote bindings で追加した例）
{
  "ai": {
    "binding": "AI",
    "experimental_remote": true
  }
}
```

これで、自分のパソコンで動かしていても、AI の処理だけは実際の Cloudflare で行われます（D1 などほかのバインディングはローカルのままで大丈夫です）。

次に、要約に使うモデルを決めます。Workers AI には多くのモデルがあり、無料枠で使える日本語対応のモデルを選びます。技術の判断なので、Claude Code に相談して決めます。

```text
Workers AI で日本語の会議メモを要約・決定事項・ToDo に整形したいです。いま無料枠で使える日本語対応のテキスト生成モデルの候補を、context7 で最新の情報も確認したうえで挙げてください。
```

2026年6月時点では、`@cf/meta/llama-3.2-3b-instruct` のような軽量で多言語対応のモデルが候補になります。軽いモデルは速く無料枠に優しい一方、日本語の要約品質が物足りないこともあります。まず軽量モデルで試し、品質が足りなければ少し大きいモデルに変える、という進め方で選びます。

!!! warning "注意"
    モデルは入れ替わりが速く、古いものは利用終了（非推奨）になります。本文のモデル名は2026年6月時点の例です。「選択肢に出てこない」「使えない」と出たら、その時点で無料枠にある日本語対応モデルを Claude Code に確認して選び直してください。

### Step 2: 整形処理を実装させる

AI 要約のタスクを実装させます。`tasks.md` で該当タスクの番号を確認し、実装スキルを呼びます。

```text
/kiro-impl （機能名） 2
```

Claude Code は、メモを Workers AI に渡して要約・決定事項・ToDo に整形し、その結果をデータベースに保存する処理を作ります。中身は次のような形です（これは一例で、あなたのものは違ってかまいません）。`env.AI` を通じて、選んだモデルにメモを渡します。

```typescript
// src/app/api/memos/route.ts（AI 要約を加えた例の一部）
import { getCloudflareContext } from "@opennextjs/cloudflare";

export async function POST(request: Request) {
  const { env } = getCloudflareContext();
  const { body } = await request.json();

  // メモを要約・決定事項・ToDo に整形してもらう
  const ai = await env.AI.run("@cf/meta/llama-3.2-3b-instruct", {
    messages: [
      { role: "system", content: "会議メモを、要約・決定事項・ToDo の3つに整形し、JSON で返してください。" },
      { role: "user", content: body },
    ],
  });

  // 整形結果を本文と一緒に保存する（一例）
  // ai.response を要約・決定事項・ToDo に分けて保存する
  // ...
  return Response.json({ ok: true });
}
```

コードの一行ずつを理解する必要はありません。「メモを `env.AI.run` でモデルに渡し、整形結果を受け取って保存する」という流れが読み取れれば十分です。

### Step 3: 挙動で検証する

データ基盤づくりではテストで「保存したメモが取得できる」ことを確かめました。AI 要約は出力が毎回変わるので、同じやり方は使えません。代わりに、形がそろっているかを確かめます。

```text
メモを渡したとき、要約・決定事項・ToDo の3つがそろって返ってくることを確かめてください。決定事項と ToDo は、項目（リスト）の形で返るのが期待です。実際にいくつかのメモで試して、結果を見せてください。
```

ここで確かめるのは「要約・決定事項・ToDo がそろう」「ToDo がリストで返る」といった挙動や形です。要約の文面そのものは毎回変わってよい、と考えます。これが、決定論的なデータベースの検証（出力の一致）と、AI の検証（挙動・形）の違いです。

!!! info "ポイント"
    AI の出力が期待した形で返らないとき（JSON が崩れる、3項目に分かれないなど）は、system のプロンプトを具体的にする（「必ず summary・decisions・todos の3つのキーを持つ JSON で返す」など）と安定します。崩れた実例を Claude Code に見せて、プロンプトを調整してもらいます。

### Step 4: 無料枠の消費を意識する

Workers AI の無料枠は1日あたりの上限があります（2026年6月時点で1日 10,000 Neurons）。要約を何度も実行すると消費が増えるので、開発中の試し過ぎに気をつけます。短いメモで動作を確かめ、長文での大量実行は必要なときだけにします。上限に達したら、翌日（協定世界時の 0 時）にリセットされるのを待つか、必要なら有料プランを検討します。

## まとめ

- メモの整形には Cloudflare Workers AI を使い、`wrangler.jsonc` の `AI` バインディングと `env.AI.run` で呼び出す
- モデルは無料枠の日本語対応モデルから選ぶ。軽いモデルで試し、品質が足りなければ大きめに変える
- AI の出力は毎回変わるので、検証は出力の一致ではなく「要約・決定事項・ToDo がそろう」という挙動・形で行う
- 無料枠には1日の上限があるので、試し過ぎに気を配る
