# 6-2-4 画面を作ってつなぐ

!!! note "前提知識"
    このセクションは、AI 要約機能（6-2-3）、Web アプリの仕組み（2-4-2）、コンテキストを整える手段（3-2-2）を前提とします。

!!! note "このハンズオンで使う機能"
    Next.js の画面（フロント）を Claude Code に作らせ、これまでに作った API・データベースにつなぎます。あわせて、長いビルドに備えて、セッションとコンテキストの衛生（`/rename`・`/resume`・`/clear`・`/compact`）を実地で使います。

## このセクションで学ぶこと

- メモの入力・整形結果の表示・記録の一覧と検索ができる画面を Claude Code に作らせ、API・DB とつなぐ
- ブラウザで「メモを貼る→要約が出る→保存され一覧・検索できる」一連がローカルで動くことを確認する
- 長いビルドを通して、セッションとコンテキストの衛生を実地で使う

部品（保存・処理・AI）を、人が触れる画面につなぎます。

## 導入: 画面でメモを貼り、結果を見て、残す

ここまでで、データの保存（D1）・出し入れ（API）・AI 要約（Workers AI）ができました。残るは、人が実際に触る画面です。画面ができて初めて、メモを貼り付けて要約を見て保存する、という一連の体験が成立します。

このセクションでは、画面を Claude Code に作らせ、これまでの API・データベースにつなぎます。完成すると、ブラウザでメモを貼り付けてボタンを押すと、要約・決定事項・ToDo が表示され、保存され、過去の記録を一覧・検索できるようになります。これがローカルで動けば、アプリの中身は完成です（公開は次の章）。

## 実践: 画面を作って API につなぐ

### Step 1: 入力と結果表示の画面を作らせる

画面のタスクを実装させます。`tasks.md` で該当タスクの番号を確認し、実装スキルを呼びます。

```text
/kiro-impl （機能名） 3
```

Claude Code は、`src/app/` の画面ファイル（雛形にある `src/app/page.tsx` など）を編集して、次の要素がある画面を作ります。

- 会議メモを貼り付けるテキスト入力欄
- 「整形する」ボタン
- 結果を表示する欄（要約・決定事項・ToDo の3つ）

画面のコードは Claude が書くので、見た目やコードの細部はあなたのものと違ってかまいません。大事なのは、これらの要素がそろい、ボタンを押すと AI 要約の処理が呼ばれることです。

### Step 2: 記録の一覧と検索を作らせる

続けて、保存した記録を見返せるようにします。

```text
/kiro-impl （機能名） 4
```

過去の記録を新しい順に並べる一覧と、キーワードで絞り込む検索ボックスができます。一覧は先に作った「一覧を返す API（GET）」を、画面から呼んで表示します。

### Step 3: つないで一連を通す

画面と API・データベースがつながったら、ブラウザで通しで動かします。`ai-minutes` フォルダで開発サーバーを起動します。

```bash
npm run dev
```

ブラウザで `http://localhost:3000` を開き、次を順に試します。

1. テキスト欄に会議メモ（架空のもので構いません）を貼り付ける
2. 「整形する」ボタンを押す
3. 要約・決定事項・ToDo が表示される
4. 記録が保存され、一覧に出てくる
5. キーワードで検索すると、その記録が絞り込まれる

!!! success "確認"
    ブラウザでメモを貼る→要約が表示される→保存され一覧に出る→検索できる、までが通れば、アプリの中身はローカルで完成です。

### Step 4: 完成条件で照合し、ずれを直す

動かしてみて、仕様づくりで固めた完成条件（requirements.md の「○○のとき△△できる」）と照らします。たとえば「整形すると3項目が表示される」「保存すると一覧に出る」「検索で絞り込める」が満たされているかを、一つずつ確認します。

ずれていたら、その場で直します。Claude Code が見当違いの方向に進み始めたら `Esc` で止めて言い直し、作りかけが思っていたものと違ったら `/rewind` で前の状態に戻してやり直します（Part3 で学んだ操作を、ここで実際に使います）。期待した動きと実際の様子を具体的に伝えるほど、収束が速くなります。

### Step 5: セッションとコンテキストを整える

ここまでで、仕様づくりから画面まで長いビルドになりました。会話のコンテキストも膨らんでいます。Part3 と土台づくりで確認した手段を、区切りのよいこの場で実際に使います。

- `/context` で、いまのコンテキストの使用量を確認する
- 区切りがよいので `/rename` でセッションに名前を付ける（例: `ai-minutes-app`）。`exit` で一度終えても、あとで `claude --resume` を選べば同じ文脈から再開できます
- 会話が長く重くなってきたら `/compact` で要約して圧縮する（「アプリの構成と残タスクを残して」のように観点を添えると要点が残ります）
- アプリ開発と関係のない調べ物などをするときは、`/clear` でいまの会話を捨ててリセットできます。ただし `/clear` は今の文脈を消すので、あとで開発を続けたいときは使わず、`exit`→`claude --resume` で戻る方が安全です

こうして区切りごとに整えると、長い開発でも Claude Code の精度を保てます。

## まとめ

- 画面（入力・結果表示・一覧・検索）を Claude Code に作らせ、これまでの API・データベースにつないだ
- ブラウザで「メモを貼る→要約が出る→保存・一覧・検索」の一連がローカルで動けば、アプリの中身は完成
- ずれは `Esc`・`/rewind` で早めに直し、完成条件で一つずつ照合する
- 長いビルドの区切りでは `/rename` で名前を付け、`exit`→`claude --resume` で再開し、`/compact` で圧縮する（無関係な作業に移るときだけ `/clear` でリセット）

この章では、cc-sdd で要件・設計・タスクを固め（仕様を正にし）、その地図に沿ってデータ基盤・AI 要約・画面を順に実装し、検証ゲートで確かめながら、ローカルで一通り動くアプリを作りました。アプリの中身ができあがりました。

次の章では、このローカルで動くアプリを Cloudflare に公開して公開 URL を得ます。秘密の値の扱い（環境変数・シークレット）と本番データベースへの反映を済ませてデプロイし、公開後のアプリを Claude Code から操作して動作を検証します。そのうえで、開発の手順をハーネスに残して保守できるようにし、最後に作ったアプリが業務成果にどうつながるかを見積もって研修を締めくくります。
