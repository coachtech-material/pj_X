# 3-1-5 中断・巻き戻し・再開

!!! note "前提知識"
    このセクションは 3-1-4「権限と Plan モードで自律度を選ぶ」の内容を前提としています。

## このセクションで学ぶこと

- 実行を途中で止めて、方向を言い直す方法
- チェックポイント（/rewind）で前の状態に巻き戻す方法と、その限界
- 端末を閉じても、中断した作業をセッション再開で続ける方法

途中で止める・戻す・再開するという、安心して任せるための立て直しの手段を押さえます。

!!! note "補足"
    このセクションのコマンド名・キー操作は、2026年6月時点のものです（変わりうるため、実際の表示はお手元の画面で確認してください）。本文の操作は読んで仕組みをつかむための説明で、実際に手を動かすのは Chapter 3-5 の記事づくり（3-5-1）や以降のハンズオンです。

---

## 導入: 違う方向に進んだら、すぐ戻せる

AI に任せていると、途中で「これは思っていた方向と違う」と気づくことがあります。そのまま最後まで進ませてしまうと、できあがってからやり直すことになり、無駄が大きくなります。

ずれに気づいた時点で、すぐに止めて、前の状態に戻せる。この立て直しの手段があると、危なそうなことも気軽に任せて、だめなら戻る、という進め方ができます。実行を止める・状態を巻き戻す・中断したところから再開する、という3つの方法を押さえます。

---

## 実行を途中で止める

AI が動いている最中に止めたいときは、**Esc** キーを押します。実行中の動作がそこで止まります。

止めても、それまでのやり取り（文脈）は保たれます。つまり、いったん止めてから「いや、そっちじゃなくて、こうしてほしい」と方向を言い直せます。最初からやり直すのではなく、途中で軌道を変えられるのが利点です。違う方向に進み始めたら、進みきるのを待たずに Esc で止めて言い直す、という小さな立て直しを、こまめに使ってください。

## チェックポイントで巻き戻す

止めるだけでなく、加えられた変更そのものを前の状態に戻したいこともあります。そのための仕組みが **チェックポイント** です。

チェックポイントとは、Claude Code がファイルを編集する前に自動でとっておく、コードのその時点の状態（スナップショット）です。こちらが依頼を送るたびに記録されるので、「あの依頼を出す前の状態」に後から戻れます。自分で操作しなくても、裏で自動的に積み重なっていきます。

巻き戻すには、**`/rewind`** と入力するか、入力欄が空のときに **Esc を2回** 押して、巻き戻しメニューを開きます。メニューには、それまでに送った依頼の一覧が出ます。戻りたい時点を選ぶと、何を戻すかを次の3つから選べます（2026年6月時点）。

- **コードと会話を両方戻す**: ファイルの変更も、やり取りの履歴も、その時点に戻します。
- **会話だけ戻す（コードは保持）**: 今のファイルの状態は残したまま、やり取りだけをその時点に戻します。
- **コードだけ戻す（会話は保持）**: やり取りは残したまま、ファイルの変更だけを取り消します。

「コードだけ戻したいのか、話の流れごと戻したいのか」を場面で選べるので、たとえば「ファイルは戻したいが、そこに至った相談の流れは残しておきたい」といった戻し方もできます。

!!! warning "注意"
    チェックポイントで戻せるのは、AI が **ファイル編集ツールで行った変更** だけです。次のものは戻せません。

    - AI がターミナルのコマンドで行った変更（たとえば `rm` でファイルを削除する、`mv` でファイル名を変える、といった操作）
    - Claude Code のセッションの外で、あなたが手で行った変更や、別のセッションからの変更

    コマンドで消したファイルは巻き戻しでは戻らない、という点に注意してください。チェックポイントは「AI の編集を手元で取り消す」ための機能であって、すべての変更を記録しているわけではありません。

## 中断した作業を再開する

作業の途中で端末（ターミナル）を閉じてしまっても、やり取りは手元に保存されているので、続きから再開できます。再開には2つの方法があります（2026年6月時点）。

- **直前の続きから再開する**: `claude --continue` で起動すると、いちばん最近のセッションをそのまま再開できます。「さっきの続きをやろう」というときに使います。
- **一覧から選んで再開する**: `claude --resume` で起動すると、過去のセッションの一覧が出て、どれを再開するか選べます。複数の作業を並行していて、特定のものに戻りたいときに使います。

```bash
# 直前のセッションをそのまま再開する
claude --continue

# 過去のセッション一覧から選んで再開する
claude --resume
```

再開すると、それまでの文脈を説明し直さずに続けられます。チェックポイントもセッションをまたいで保たれるので、再開したあとで前の状態に巻き戻すこともできます。

## 巻き戻しは「その場の取り消し」、永続的な記録は Git へ

ここまでの中断・巻き戻し・再開は、いずれもセッションの中での手元の立て直しです。便利ですが、できることには境目があります。

チェックポイントは、あくまで自分の手元で、セッション中の編集を素早く取り消すための仕組みです。「いつ・何を・なぜ変えたか」を意味のあるまとまりで永続的に残し、他の人と共有したり、ずっと先の時点から過去をたどったりする用途には向きません。公式にも、チェックポイントはバージョン管理の代わりではないと位置づけられています。チェックポイントは「手元の取り消し」、変更を永続的に記録して共有する仕組みは別にある、と分けて覚えてください。

その「永続的に記録して共有する仕組み」が、**Git** です。Git は、変更を履歴として積み重ね、いつでも過去に戻れて、チームで共有しながら安全に作業を進められるようにします。本研修では Part5 で扱います。いまは、手元の立て直し（チェックポイント）と、永続的な記録（Git）は別物だ、と押さえておけば十分です。

---

## まとめ

- 実行中の動作は Esc で止められる。文脈は保たれるので、止めてから方向を言い直せる
- チェックポイントは、AI がファイルを編集する前に自動でとる状態。`/rewind`（または入力欄が空のときに Esc を2回）でメニューを開き、「コードと会話を両方／会話だけ／コードだけ」から戻し方を選べる
- 巻き戻せるのは AI のファイル編集だけ。ターミナルのコマンドによる変更や、セッション外で手で変えた分は戻せない
- 端末を閉じても、`claude --continue` で直前のセッションを、`claude --resume` で一覧から選んでセッションを再開できる
- チェックポイントはセッション内・手元の取り消しで、バージョン管理の代わりではない。永続的に記録して共有する仕組みは Part5 の Git で学ぶ

---

止める・戻す・再開するで作業の足場が整ったら、最後は、出てきたものが本当に狙いどおりかを確かめる工程です。次のセクションでは、AI の出力が完成条件（1-3-4）を満たすかを一項目ずつ照合し、数字や出典は一次情報で裏取りし、ずれていたら軌道修正を指示し、タスクを小さく刻んで一段ごとに照合する検証ゲートを扱います。
