## このセクションで学ぶこと

- 依頼を投げると、Claude Code が自分でファイルを読み・調べ・編集まで進める一連の流れ

## 導入: チャットとの違いは「自分で動く」こと

1-1-2 で、回答を返すだけのチャット AI と、自分で手を動かして成果物を仕上げる AI エージェントの違いを学びました。Claude Code は後者です。この違いは、実際に動かしてみると一気にはっきりします。

チャット AI に「このファイルのバグを直して」と頼むと、返ってくるのは「こう直すとよい」という説明や、直したコードの一部です。実際にファイルを開いて直すのは、あなた自身です。Claude Code は違います。「このファイルのバグを直して」と頼むと、Claude Code は自分でそのファイルを探し、中身を読み、直し方を考え、ファイルそのものを書き換えます。あなたがコピー＆ペーストでファイルに反映する手間は要りません。

この「自分で動く」という性質が、Claude Code を業務の道具にするうえでの出発点です。あなたの役割は、コードや文章を一文字ずつ書くことではなく、何をしてほしいかを伝え、出てきたものを確かめることに移ります。

## 依頼を投げると、AIが自分で進める

Claude Code への依頼は、やりたいことを普通の文章で書いて伝えるだけです。たとえば次のように頼みます。

```text
ログインフォームで、入力が空でも送信できてしまうバグがあります。直してください。
```

この一文を受け取ると、Claude Code は次の順で作業を進めます（Anthropic「クイックスタート」2026年6月時点）。

1. **適切なファイルを見つける**: バグに関係しそうなファイルを、自分で探し出す
2. **提案された変更を表示する**: どこをどう変えるか（変更案）を画面に示す
3. **承認を求める**: 「この変更を加えてよいか」とあなたに確認する
4. **編集する**: あなたが承認して初めて、実際にファイルへ手を入れる

```mermaid
flowchart LR
    A["あなたが<br>文章で依頼する"]
    B["適切なファイルを<br>見つける"]
    C["変更案を<br>表示する"]
    D["承認を<br>求める"]
    E["承認後に<br>編集する"]
    A --> B --> C --> D --> E
```

ここで注目したいのは、最初の「適切なファイルを見つける」を Claude Code が自分でやる点です。あなたが「このファイルを見て」と一つひとつ指定しなくても、依頼の内容から関係しそうなファイルを判断し、必要なものを読み込みます。公式ガイドも「Claude Code は必要に応じてプロジェクトファイルを読み込みます。コンテキストを手動で追加する必要はありません」と説明しています（Anthropic「クイックスタート」2026年6月時点）。**コンテキスト** （AI に踏まえてほしい前提や情報）を毎回そろえて渡す手間が省けるということです。コンテキストの仕組みと、それを意図的に整える方法は、この後の Chapter 3-2 でくわしく扱います。

そして、3つ目の「承認を求める」は、1-2-2 で最初の成果物を作ったときにすでに体験しています。Claude Code は、ファイルを変更する前に必ずあなたの許可を求め、勝手に進めることはありません。「いちいち確認されると遅いのでは」と感じるかもしれませんが、この承認の範囲は場面に応じて調整できます（たとえば、確認を求めずに自動で編集を進めるよう切り替えることもできます）。その仕組みと使い分けは 3-1-4 で扱うので、ここでは「依頼すると、AI が自分で動き、変更の前に確認が入る」という全体の流れをつかんでおけば十分です。

!!! quote "現場での考え方"
    自分が最初に驚いたのは、ファイルの場所を一つも教えていないのに、Claude Code が関係するファイルを自分で見つけてきたことでした。チャット AI を使っていた頃は、該当のコードをこちらでコピーして貼り付け、直された結果をまた貼り戻す、という往復が当たり前でした。その往復がまるごと消えて、頼んだら成果物が手元で更新されている。この「往復が消える」感覚が、チャットとの一番大きな違いだと感じています。

## 依頼には画像やスクリーンショットも渡せる

依頼は、文章だけとは限りません。Claude Code には、画像やスクリーンショットも一緒に渡せます。文章で説明しづらいものや、見せたほうが早いものに向いています。たとえば次のような場面です。

- エラー画面のスクリーンショットを見せて「この画面が出る原因を教えて」と頼む
- 手書きの構成案やワイヤーフレームの写真を渡して「このイメージで作って」と頼む
- 作りたい画面のデザイン案（モック）を見せて「これに近い見た目にして」と頼む

画像を渡す方法は、主に次の3つです（Anthropic「一般的なワークフロー」2026年6月時点）。

1. **ドラッグ＆ドロップ**: 画像ファイルを、Claude Code を動かしているウィンドウの中へマウスでドラッグして落とす
2. **コピーして貼り付け**: 画像をコピーした状態で、入力欄に貼り付ける
3. **パスで渡す**: 画像ファイルの置き場所（パス）を文章で伝える。たとえば「この画像を見て: /Users/you/Desktop/error.png」のように書く

2つ目の貼り付けには、注意点があります。画像を貼り付けるキー操作は、ふだんの文字の貼り付けとは違います。Claude Code では、macOS でも `Ctrl+V` を使います（文字を貼り付けるときの `Cmd+V` ではありません）。Windows では文字の貼り付けと同じ `Ctrl+V` です。

!!! warning "注意"
    macOS で画像を貼り付けるときは `Cmd+V` ではなく `Ctrl+V` を使います。文字を貼り付ける感覚で `Cmd+V` を押すと、画像が貼り付かないことがあります。うまく貼り付かないときは、`Ctrl+V` を試すか、ドラッグ＆ドロップやパスで渡す方法に切り替えてください。

3つ目の「パスで渡す」に出てくるパス（ファイルの置き場所を示す住所）は、2-1-2 で学んだものです。画像がどこにあるかをパスで指し示せば、Claude Code はその画像を読み込みます。

画像を渡せると、伝えられることの幅が広がります。エラーの様子、作りたい見た目、紙に書いた案など、言葉にしづらいものをそのまま見せて任せられます。

## まとめ

- Claude Code は、依頼を受けると自分でファイルを探し・読み・変更案を示し・承認後に編集する。チャット AI のようにコードを貼り付けて往復する手間が要らない
- 必要なファイルは自動で読み込まれるため、コンテキストを手で足す必要はない（コンテキストの整え方は 3-2）
- 変更の前には必ず承認が入る。確認を求める範囲は場面に応じて調整できる（仕組みは 3-1-4）
- 依頼は文章だけでなく、画像やスクリーンショットでも渡せる（ドラッグ＆ドロップ／貼り付け／パス）。エラー画面・手書きの案・デザイン案などに有効
