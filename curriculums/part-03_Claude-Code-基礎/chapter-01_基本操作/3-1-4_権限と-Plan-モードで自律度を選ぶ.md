# 3-1-4 権限と Plan モードで自律度を選ぶ

!!! note "前提知識"
    このセクションは 3-1-3「モデル・effort・コスト」の内容を前提としています。

## このセクションで学ぶこと

- 確認なしで実行できる範囲が変わる権限モードを Shift+Tab で切り替えられること
- 自律度を「確認を求める（既定）→ 編集を自動承認する acceptEdits → 高リスク操作だけを止める auto」と段階的に上げられること、対に Plan モードがあること
- 既定で読み取り優先・変更前に承認を求める組み込み保護があり、権限などの設定は settings.json に残して再利用できること

確認の頻度を場面に応じて選ぶ権限モードと、編集前に計画を立てさせる Plan モードを押さえます。

!!! note "補足"
    このセクションのコマンド名・キー操作・モードの名称は、2026年6月時点のものです（変わりうるため、実際の表示はお手元の画面で確認してください）。本文の操作は読んで仕組みをつかむための説明で、実際に手を動かすのは Chapter 3-5 の記事づくり（3-5-1）や以降のハンズオンです。

---

## 導入: 確認の多さは、選べる

3-1-1 から 3-1-3 まで、Claude Code に依頼すると、ファイルを変更したりコマンドを実行したりする前に承認を求めてくる場面を見てきました。毎回すべてを承認するのは安全ですが、作業が長くなると手数が増え、何度目かの承認では中身を見ずにただ通すだけ、ということも起こります。

この確認の頻度は、固定ではありません。場面に応じて自律度（確認なしで AI に任せる範囲）を選べます。慎重に進めたいときは一手ごとに確認し、信頼できる作業はまとめて任せる。その選び方を、ここで押さえます。

---

## 権限モードで自律度を選ぶ

確認なしで実行できる範囲を決めるのが **権限モード** です。モードを切り替えると、AI が一時停止して承認を求める頻度が変わります。

切り替えは、入力欄で **Shift+Tab** を押します。押すたびにモードが順番に切り替わり、いま選んでいるモードは画面下部のステータスバーに表示されます（2026年6月時点）。代表的なモードは、自律度の低い順に次の3つです。

| モード | 確認なしで実行されるもの | 向いている場面 |
|---|---|---|
| `default`（既定） | 読み取りのみ | 開始時、慎重に進めたい作業 |
| `acceptEdits` | 読み取り＋作業フォルダ内のファイル編集・一般的なファイル操作 | 差分を見ながら反復する作業 |
| `auto` | 上記に加え、高リスク以外の操作（背景の安全チェック付き） | 長時間のタスク、確認疲れの軽減 |

- **default** （既定）では、ファイルの読み取りは確認なしで進みますが、ファイルを編集する・コマンドを実行するといった変更を伴う操作の前には、毎回承認を求めます。最初はこのモードで、何が起きるかを一手ずつ確かめながら進めるのが基本です。
- **acceptEdits** では、作業フォルダの中のファイル編集と、フォルダ作成・移動・コピーといった一般的なファイル操作を、いちいち確認せず自動で承認します。出てきた変更はあとから差分（3-1-2）でまとめて見直せるので、AI に手を動かしてもらいながら反復する作業に向きます。本研修のハンズオンは、この acceptEdits を既定として進めます。
- **auto** では、別の安全チェック（背景で動く分類器）が高リスクな操作だけを止め、それ以外は確認なしで進めるため、承認の回数がさらに減ります。長く自律的に作業させたいとき（Part6 のアプリ開発のような長丁場）に、確認疲れを減らす場面で活きます。

!!! warning "注意"
    auto モードは、2026年6月時点では研究プレビュー（試験的に提供される段階）の機能で、公式に「プロンプトは減らすが、安全を保証するものではない」とされています。利用には対応するバージョン・モデル・アカウントの条件があり、満たさないと選択肢に現れません。機密に関わる操作の確認を、これに置き換えてはいけません。本研修では、まず acceptEdits を使い、auto は Part6 で長時間の自律作業の文脈とあわせて触れます。

自律度は、低いほうから高いほうへ段階的に上げられます。慣れないうちは default で一手ずつ、勝手がわかってきたら acceptEdits でまとめて、というように、作業への信頼度に合わせて選んでください。

!!! note "補足"
    上の3つのほかにも、用途を絞ったモード（事前に許可した操作だけを通す `dontAsk`、すべての確認を飛ばす `bypassPermissions` など）があります。これらは隔離された環境や自動実行といった特定の用途向けで、本研修では扱いません。日常の作業では、default → acceptEdits → auto の段階と、次に説明する Plan モードを覚えておけば十分です。

## Plan モードで「先に計画」を立てさせる

権限モードと対になるのが **Plan モード** です。これは、編集を始める前に、AI に関連するファイルを読んで調べさせ、これからどう進めるかの計画を提示させ、こちらが承認するまで変更を加えさせないモードです。

大きめの作業や、不慣れな対象を触る作業では、AI がいきなり作り始めると、的外れな方向のまま手が進んでしまうことがあります。Plan モードを使うと、まず「何を・どの順で変えるか」という計画を見て、ずれていれば直してから実行に移せます。作り始めてからやり直すより、手戻りが小さくて済みます。

Plan モードにも Shift+Tab で入れます（2026年6月時点では default → acceptEdits → plan の順で切り替わります）。計画が提示されたら、その内容を承認して実行に移すか、フィードバックを返して計画を練り直させるかを選べます。

逆に、ひとことで説明できる小さな修正（誤字直し・一行追加など）では、計画の段は手間が増えるだけなので、Plan モードを使わず直接依頼するほうが速いです。「アプローチに迷う」「複数のファイルにまたがる」「触る対象に不慣れ」というときに、Plan モードが効きます。

この「作る前に要件と段取りを固める」進め方は、大きな仕事を破綻なく仕上げる方法として、Part4 の仕様駆動（SDD）で体系立てて扱います。ここでは、編集前に計画を挟めるモードがある、という操作として押さえてください。

## 既定の組み込み保護

2-5-3 のセキュリティで、「渡したあとを守る Claude Code の組み込み保護は Part3 で扱う」と予告しました。それがこの仕組みです。

Claude Code は、既定で次の2つの保護を備えています（2026年6月時点）。

- **読み取りを基本とし、変更前に承認を求める**: default モードでは、勝手にファイルを書き換えず、変更を加える操作の前に必ず承認を求めます。これが、いま見てきた権限モードの土台です。
- **保護されたパスは自動承認しない**: 設定ファイルや、変更履歴を管理する `.git` フォルダなど、壊れると影響の大きい場所への書き換えは、acceptEdits を選んでいても自動では承認されず、確認を挟みます。誤って大事な設定を上書きしてしまうのを防ぐ安全網です。

ここで、2-5-3 の話と並べて整理しておきます。2-5-3 で押さえたのは「何を AI に渡すか」という、渡す前の線引きでした。この組み込み保護は「渡したあと、AI が手元で何をしてよいか」を守る仕組みです。両者は別の層にあり、片方だけでは十分ではありません。渡す中身は人が線を引き、渡したあとは組み込み保護が守る。この2つがそろって、安全に任せられます。

## 設定は settings.json に残せる

権限モードのような設定は、毎回選び直さなくても、**settings.json** というファイルに書いておけば、次回から自動で効かせられます。たとえば「このプロジェクトは最初から acceptEdits で始める」といった既定を、ファイルに残して再利用できます。

設定ファイルは、効かせたい範囲によって置き場所を選べます（2026年6月時点）。

- **自分だけの設定**: 自分のユーザー全体に効かせたいものは、ホームフォルダの設定（`~/.claude/settings.json`）に置きます。どのプロジェクトで作業しても効きます。
- **チームで共有する設定**: プロジェクトのメンバー全員に同じ設定を効かせたいものは、プロジェクト内（`.claude/settings.json`）に置きます。このファイルはプロジェクトと一緒に共有でき、チームの標準になります。

!!! note "補足"
    settings.json には権限のほかにも、モデルの既定や、後の Part で学ぶフックなど、さまざまな設定をまとめられます。組織として標準ルールを全員に効かせる（管理者が決めた設定を上から被せる）といったガバナンスの仕組みは、4-3 で扱います。いまは「設定はファイルに残して再利用できる」「自分用とチーム共有用で置き場所が分かれる」とだけ押さえれば十分です。

---

## まとめ

- 確認なしで実行できる範囲を決めるのが権限モード。Shift+Tab で切り替え、現在のモードはステータスバーに表示される（2026年6月時点）
- 自律度は default（読み取りのみ確認なし）→ acceptEdits（作業フォルダ内の編集を自動承認）→ auto（高リスク以外を自動承認・研究プレビュー）と段階的に上げられる。本研修のハンズオンは acceptEdits を既定とする
- 対になる Plan モードは、編集前に計画を立てさせ承認するまで変更させない。大きめ・不慣れな作業で手戻りを防ぐ（体系化は Part4 の仕様駆動）
- 既定で読み取り優先・変更前に承認を求め、保護されたパスは自動承認しない組み込み保護がある。2-5-3 の「渡す前の線引き」と、この「渡したあとの保護」は別の層で、両方そろって安全になる
- 権限などの設定は settings.json に残して再利用でき、自分用はユーザー全体に、チーム共有用はプロジェクトに置ける

---

権限モードで自律度を選べても、AI が進んだ方向が違っていたら、いったん止めて戻したくなります。次のセクションでは、実行を途中で止める方法と、チェックポイント（/rewind）で前の状態に巻き戻す方法、そして中断した作業をセッション再開で続ける方法を扱います。これらは手元の取り消しで、いつ・何を・なぜ変えたかを永続的に残す Git は Part5 で学びます。
