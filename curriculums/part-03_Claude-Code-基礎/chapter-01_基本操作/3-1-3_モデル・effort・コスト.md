# 3-1-3 モデル・effort・コスト

!!! note "前提知識"
    このセクションは 3-1-2「ファイル編集と差分の確認」の内容を前提としています。

## このセクションで学ぶこと

- 使う AI（モデル）を選び分けられること、その違いとコストの関係
- どれだけ考えてから答えるかの深さ（努力レベル＝effort）を切り替えられること
- かかったコストを確認する方法と、その数字の読み方

タスクの重さに道具を合わせるために、何をどこで切り替えられるかという地図を持ちます。

!!! note "補足"
    このセクションに出てくるスラッシュコマンドは、何をどこで切り替えられるかを理解するための例です（読みながら打つ必要はありません）。実際に切り替えながら作業するのは、この Chapter の 3-5（記事を作る）の 3-5-1 や、以降の各ハンズオンです。

---

## 導入: タスクの重さに、道具を合わせる

同じ「書く」でも、付箋に一言メモするのと、契約書を起草するのとでは、向き合い方が違います。AI に任せる仕事も同じです。ちょっとした文章の整形と、複雑な設計の検討では、ふさわしい道具と力の入れ方が変わります。

Claude Code では、この「道具」と「力の入れ方」を自分で選べます。具体的には、使う AI（モデル）と、どれだけ深く考えさせるか（努力レベル）です。重い道具を常に使えば結果はよくなりそうですが、そのぶん時間とコストがかかります。軽い仕事に重い道具は過剰です。このセクションでは、何をどこで切り替えられるかを把握し、タスクに合わせて選べるようにします。なお、ここで紹介するモデル名や既定値は 2026年6月時点のもので、今後変わりえます。

---

## モデルを選ぶ

**モデル** とは、AI の頭脳にあたるものです。同じ Claude Code でも、中で動かすモデルを切り替えられます。一般に、重く賢いモデルほど複雑な仕事に強い一方で、コストが高く、応答もやや遅くなります。軽いモデルはその逆で、速くて安いぶん、難しい仕事では力不足になることがあります。

2026年6月時点で、Claude Code では主に次のモデルを選べます（Anthropic「モデル設定」2026年6月時点）。

| 呼び名 | 位置づけ | 向く仕事 |
|---|---|---|
| `opus` | 複雑な推論に強い高性能モデル（Opus 4.8 に対応） | 込み入った設計の検討、多段階の推論 |
| `sonnet` | 日常的な作業をバランスよくこなすモデル（Sonnet 4.6 に対応） | ふだんの文章作成・コード編集の大半 |
| `haiku` | 高速で効率のよい軽量モデル | 単純で量の多い処理 |
| `fable` | 最上位のモデル（Fable 5）。1回のセッションより大きな仕事に向く | 長時間の自律作業、大きめのタスク |

モデルを切り替えるには、スラッシュコマンドの `/model` を使います。`/model` だけを打つと、選べるモデルの一覧（ピッカー）が出て、そこから選べます。`/model sonnet` のように呼び名を続ければ、直接そのモデルに切り替わります。

どのモデルが最初から使われるか（既定）は、契約しているプランによって異なります。2026年6月時点では、Pro プランは Sonnet 4.6 が既定、Max プランや API 利用では Opus 4.8 が既定です。`fable`（Fable 5）は、どのプランでも既定ではなく、`/model fable` で選んだときだけ使われます（Anthropic「モデル設定」2026年6月時点）。

使い分けの目安はシンプルです。公式ガイドも「Sonnet はほとんどのコーディングタスクをうまく処理し、Opus よりもコストが低くなります。複雑なアーキテクチャの決定または複数ステップの推論のために Opus を予約します」と述べています（Anthropic「コストを効果的に管理する」2026年6月時点）。つまり、ふだんの作業は Sonnet で十分に低コストでこなし、込み入った設計や難しい判断のときに Opus へ上げる、という考え方です。

!!! note "補足"
    モデルには世代があり、`opus`・`sonnet` といった呼び名（エイリアス）は、その時点の最新世代を指す仕組みになっています。ここに書いた「Opus 4.8」「Sonnet 4.6」という具体的な世代名や、プランごとの既定は、今後の更新で変わります。最新の対応関係は、Claude Code の公式ドキュメント（モデル設定）で確認してください。

---

## 努力レベル（effort）を選ぶ

モデルを選んだうえで、もう一段の調整ができます。それが **努力レベル（effort）** です。努力レベルとは、モデルが答えを出す前に、どれだけ深く考えるかの度合いです。同じモデルでも、努力レベルを上げれば、より時間をかけてじっくり考えてから答え、下げれば、軽く考えて素早く答えます。

努力レベルは、低い順に次の段階があります（Anthropic「モデル設定」2026年6月時点）。

- `low`（低い）
- `medium`（中くらい）
- `high`（高い）
- `xhigh`（さらに高い）
- `max`（最大）

選べる段階はモデルによって少し異なります。`low` から `max` まで使えるモデルが多い一方、モデルによっては `xhigh` がなく `low`・`medium`・`high`・`max` の段階になります。既定は `high` です（モデルによっては別の既定が設定されている場合があります）。

切り替えには、スラッシュコマンドの `/effort` を使います。`/effort` だけを打つと、段階を選ぶスライダーが出ます。`/effort high` のように段階名を続ければ、直接そのレベルに切り替わります。

選び方の目安は、モデルと同じ考え方です。軽い作業や急ぎの作業では低めにして速さとコストを優先し、難しい作業や正確さが要る作業では高めにして、じっくり考えさせます。

## コストの見方

Claude Code は、内部的に **トークン** という単位でやり取りの量が数えられ、その量に応じて費用がかかります。トークンは、ざっくり言えば、AI が読み書きする文章の量を表す単位です。長い文章をやり取りするほど、また重いモデルを使うほど、消費するトークンは増えます。

いまどれだけ使ったかは、スラッシュコマンドで確認できます。

- `/usage`: いま行っているセッションのトークン使用量と、それを元にした推定コストを表示します
- `/context`: いまコンテキスト（AI が一度に読んでいる情報）を何がどれだけ占めているかの内訳を表示します（コンテキストの仕組みは 3-2 で扱います）

ここで、表示される金額の読み方に注意が要ります。`/usage` に出るドル額は、トークンの量から計算した推定値です。そして、Pro や Max などのサブスクリプション（月額制のプラン）では、使った量はもともとプランの利用枠に含まれています。そのため、画面に出る推定額は、実際にそのぶん請求されるという意味ではなく、あくまで使用量の目安として見るものです（Anthropic「コストを効果的に管理する」2026年6月時点）。

!!! info "ポイント"
    モデル・努力レベル・コストは、いずれも「重く・深くするほど結果はよくなりうるが、時間とコストがかかる」という同じ天秤の上にあります。だから、タスクの重さに合わせて選びます。ふだんは軽め・速めで回し、難しいところだけ力を入れる。この感覚を持っておくと、無駄なく成果を出せます。

このセクションで扱ったのは、「何をどこで切り替えられるか」という地図です。実際の業務で、どんなタスクにどのモデル・努力レベルを当てると効率がよいか、コストをどう抑えて仕組みに織り込むかという、選び分けの運用は、Part4 の 4-3（品質・コスト・ガバナンス）で扱います。料金や利用枠は変動が速いので、最新の条件は公式の情報で確認してください。

---

## まとめ

- モデルは AI の頭脳。`opus`（高性能）・`sonnet`（バランス）・`haiku`（軽量）・`fable`（最上位）から `/model` で選ぶ。重いほど複雑な仕事に強いが、コストが高く応答も遅め
- 既定のモデルはプランで異なる（2026年6月時点で Pro は Sonnet 4.6、Max・API は Opus 4.8）。ふだんは Sonnet、込み入った仕事で Opus が目安
- 努力レベル（effort）は考える深さ。`/effort` で low から max の段階を切り替える（既定は high。選べる段階はモデルで少し異なる）。軽い作業は低く、難しい作業は高く
- コストはトークンの量で決まる。`/usage` で使用量と推定コスト、`/context` で内訳を確認できる。サブスクリプションでは推定額は請求とは別の目安（選び分けの運用は 4-3）
