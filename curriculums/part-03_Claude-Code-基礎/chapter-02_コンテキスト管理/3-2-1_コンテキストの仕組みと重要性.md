## 導入: AIの「机の広さ」には限りがある

2-5-2 で、生成AI の限界は「前提をコンテキストとして渡す」ことで補えると触れ、その **コンテキスト** の具体的な使い方は Part3 で扱うと約束しました。3-1-6 の最後でも、やり取りが長くなると AI が前の指示を取りこぼすこと、文脈を整える手段は本 Chapter で扱うことに触れました。その正体を、ここで掘り下げます。

コンテキストとは、AI がいま考慮できる情報のひとまとまりです。机にたとえると分かりやすくなります。人が作業するとき、机の上に資料を広げます。広い机ならたくさんの資料を一度に見渡せますが、机には大きさの限りがあり、無限には広げられません。AI も同じで、一度に見渡せる情報の範囲には限りがあります。この「机の広さ」にあたるものを、コンテキストウィンドウと呼びます。

---

## コンテキストウィンドウとは

**コンテキストウィンドウ** とは、AI が一度に読み込んで考慮できる情報の範囲です。AI は、このウィンドウに入っている情報だけを手がかりに、次の応答を組み立てます。ウィンドウの外にある情報は、存在しないのと同じです。

Claude Code を使っているとき、このウィンドウには次のようなものが入っています。

- **あなたと AI のやり取り**: これまでの依頼と、AI の応答の履歴
- **読み込んだファイルの中身**: AI が作業のために読んだファイルの内容
- **コマンドの出力**: AI が実行したコマンドが返してきた結果
- **CLAUDE.md の内容**: プロジェクトに置いた前提・ルール（次の Chapter 3-3 で扱います）
- **呼び出したスキルの手順**: 使ったスキル（同じく 3-3 で扱います）の中身
- **システムの指示**: Claude Code が AI に与える、振る舞いの基本的な指示（普段は目に見えません）

机の上に、これらの資料がすべて広げられている状態を思い浮かべてください。AI は、この机の上にあるものを見ながら作業します。だから、机に何が乗っているかが、AI の仕事の質を決めます。

!!! info "ポイント"
    コンテキストウィンドウの大きさは、トークンという単位で表されます。トークンは、AI が文章を扱うときの最小のかたまりで、おおよそ単語や文字のまとまりにあたります（生成AI が次のトークンを予測して文章を作ることは 2-5-1 で扱いました）。Claude Code が扱えるコンテキストウィンドウは、2026年6月時点でおおよそ20万トークン規模が基本で、モデルによってはさらに大きいものもあります。具体的な数値はモデルや時期で変わるため、目安として捉えてください。

---

## 作業を続けると埋まっていく

机の広さに限りがある以上、作業を続けて資料が増えていくと、机はだんだん埋まっていきます。コンテキストウィンドウも同じです。

やり取りを重ねるほど、過去の依頼と応答が積み上がります。AI にファイルを読ませれば、その中身がウィンドウに入ります。コマンドを実行させれば、その出力も入ります。一つひとつは小さくても、長い作業を続けるうちに、ウィンドウは少しずつ埋まっていきます。とくに、大きなファイルを何個も読ませたり、長い調べ物をさせたりすると、一気に埋まります。

ここで押さえておきたいのが、**各セッションは、新しいコンテキストウィンドウで始まる** という点です。Claude Code を起動するたびに、机は空の状態からスタートします。前回のセッションでやり取りした会話は、引き継がれません。前の作業の続きをしたいなら、何の話だったかを改めて渡す必要があります（前提を毎回渡し直す手間を減らす CLAUDE.md は、3-3 で扱います）。

机が埋まりに近づくと、Claude Code は古い情報を自動でまとめて圧縮し、空きを作る仕組みを持っています。これを自動コンパクションと呼びます。机に乗りきらなくなる前に、過去のやり取りを要約して場所を空けるイメージです。この仕組みと、自分から整える手段は、次の 3-2-2 で詳しく扱います。今は「埋まっていくが、自動で圧縮もされる」と把握すれば十分です。

## 文脈の量が、精度・速度・コストを左右する

コンテキストウィンドウは、ただ広ければよいというものではありません。机に何でも乗せればよいわけではないのと同じで、入れる情報の量は、AI の仕事の質に三方向で効いてきます。

```mermaid
flowchart TD
    A["コンテキストに詰め込みすぎる"] --> B["精度が落ちる<br>効かせたい指示が埋もれる"]
    A --> C["速度が落ちる<br>多くの情報を処理して重くなる"]
    A --> D["コストが増える<br>トークンの消費が増える"]
```

**精度** から見ます。机の上に資料が山積みだと、人でも本当に大事な一枚を見落とします。AI も同じで、ウィンドウに情報を詰め込みすぎると、本当に効かせたい指示が大量の情報に埋もれて、取りこぼされやすくなります。3-1-6 で見た「やり取りが長くなると前の指示を取りこぼす」のは、これが理由です。関係ない情報が多いほど、AI は何に注目すべきか分かりにくくなります。

**速度** も変わります。AI は、ウィンドウに入っている情報をすべて考慮して応答を組み立てます。情報が多いほど処理することが増え、応答が返るまでが重くなります。

**コスト** にも直結します。Claude Code は、扱うトークンの量に応じてコストがかかります（コストの見方は 3-1-3 で扱いました）。ウィンドウに多くの情報を入れるほど、毎回のやり取りで消費するトークンが増え、コストが膨らみます。古い無関係なやり取りを残したまま作業を続けると、それが以後ずっとコストを生み続けます。

逆に言えば、**必要なものだけを渡せば、AI は速く・正確に・安く動きます**。だから、Claude Code を使ううえでは「何を入れて、何を入れないか」を選ぶことが大切になります。これは、その場限りの小技ではなく、Claude Code を業務で使い続けるための要です。次のセクションでは、この「整える」ための具体的な手段を扱います。

---

## まとめ

- コンテキストウィンドウとは、AI が一度に読み込んで考慮できる情報の範囲。ここに、やり取りの履歴・読んだファイル・コマンド出力・CLAUDE.md・呼び出したスキルなどが入る
- 机の広さに限りがあるように、ウィンドウにも上限がある。作業を続けると埋まっていき、各セッションは新しいウィンドウで始まる（前のセッションの会話は引き継がれない）
- 埋まりに近づくと、古い情報を自動でまとめて圧縮する自動コンパクションが働く
- 詰め込みすぎると、効かせたい指示が埋もれて精度が落ち、処理が重くなって速度が落ち、トークンが増えてコストも上がる。必要なものだけを渡すことが活用の要

---

次のセクションでは、このコンテキストを意図的に整える手段を扱います。無関係な作業に切り替えるときに会話を空にして新しく始める `/clear`、これまでの会話を要約して圧縮する `/compact`、いま何にどれだけ使っているかを見る `/context` という3つの手段と、必要な情報だけを絞って渡す進め方を押さえます。
