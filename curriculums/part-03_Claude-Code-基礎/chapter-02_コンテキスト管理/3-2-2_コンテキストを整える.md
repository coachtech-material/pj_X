# 3-2-2 コンテキストを整える

!!! note "前提知識"
    このセクションは 3-2-1「コンテキストの仕組みと重要性」の内容を前提としています。

## このセクションで学ぶこと

- 無関係な作業に切り替えるときに会話を空にする `/clear`
- これまでの会話を要約して圧縮し、コンテキストを解放する `/compact`
- いま何にどれだけコンテキストを使っているかを見る `/context`
- 曖昧な依頼を避け、必要な情報だけを絞って渡す進め方

埋まっていくコンテキストを意図的に整える手段と、そもそも無駄に埋めない渡し方を押さえます。

!!! note "補足"
    本文に出てくるコマンド（`/clear`・`/compact`・`/context`）は、何ができるかを理解するための例です（読みながら打つ必要はありません）。実際にこれらを使ってコンテキストを整えながら作業するのは、Chapter 3-5 の記事づくり（3-5-1）や、以降の各ハンズオンです。コマンドの表記や挙動は変わりうるため、2026年6月時点のものとして読んでください。

---

## 導入: 埋まってきたら、整える

3-2-1 で、コンテキストウィンドウには限りがあり、作業を続けると埋まっていくこと、詰め込みすぎると精度・速度・コストが悪化することを見ました。では、埋まってきたとき、あるいは作業を切り替えるとき、どうすればよいのでしょうか。

Claude Code には、コンテキストを整えるための手段がそろっています。机が散らかってきたら片付けるように、不要になった文脈を空にしたり、膨らんだ会話を要約して圧縮したりできます。あわせて、いまどれだけ使っているかを確認する手段もあります。ここでは、その3つのコマンドと、そもそも机を無駄に散らかさない渡し方を押さえます。

---

## /clear で新しいタスクに切り替える

いま進めていた作業とは無関係な、別の作業に移るとき。たとえば、提案書を作り終えて、次は採用の求人票に取りかかるとき。このとき使うのが `/clear` です。

`/clear` は、それまでの会話を空にして、新しく始めるためのコマンドです。机の上に広げていた前の作業の資料を、いったんすべて片付けるイメージです。これにより、前の作業の文脈がウィンドウから消え、新しい作業のためのスペースが空きます。

ここで大切なのは、**会話は空になるが、プロジェクトの前提は保持される** という点です。CLAUDE.md に書いたプロジェクトの前提（用語・ルール・進め方。次の Chapter 3-3 で扱います）は、`/clear` しても引き続き効きます。消えるのは、その作業でのやり取りの履歴だけです。

なぜ `/clear` が大切かというと、前の作業の古い文脈を残したまま次の作業を続けると、その文脈が以後ずっとウィンドウに居座り、トークンを浪費し続けるからです。3-2-1 で見たとおり、これは精度・速度・コストのすべてに効きます。無関係な作業に移るときは、`/clear` で区切るのが基本です。

!!! tip "ヒント"
    `/clear` で会話を空にすると、それまでのやり取りは消えます。後でその作業に戻りたい場合に備えて、セッションに名前を付けておく方法や、巻き戻し・再開の手段は 3-1-5（中断・巻き戻し・再開）で扱いました。やり取りそのものを記録として永続的に残すのは、Part5 で扱う Git の役割です。

## /compact で会話を要約して圧縮する

`/clear` は無関係な作業に切り替えるときの手段でした。一方で、**同じ作業を続けたいけれど、会話が膨らんできた** ときがあります。長い記事を何度も直してもらううちに、やり取りの履歴が積み上がってウィンドウを圧迫してきた、というような場面です。

このとき使うのが `/compact` です。`/compact` は、これまでの会話を要約して圧縮し、コンテキストに空きを作るコマンドです。机の上の資料を、要点をまとめた1枚のメモに置き換えるイメージです。作業の文脈は要約として引き継がれるので、同じ作業を続けながら、占めていた場所を解放できます。

`/compact` には、残してほしい観点を添えることもできます。

```text
/compact 認証まわりの修正点に注目してまとめて
```

このように指示を渡すと、要約のときに何を重点的に残すかを AI に伝えられます。何も指定しないと、AI が重要そうな箇所を推測して要約しますが、観点を渡せば、あなたが大事だと思う部分を確実に残せます。

3-2-1 で触れた自動コンパクションは、この `/compact` が自動で働くものです。ウィンドウが上限に近づくと、Claude Code が自動で会話を要約して空きを作るので、ウィンドウがいっぱいになって作業が止まることはありません。自分から `/compact` を打つのは、自動で働く前に、長い新しいタスクに入る前などに、自分の選んだ観点で整えたいときです。

!!! warning "注意"
    要約は便利ですが、万能ではありません。主要なやり取りは残るものの、初期に出した細かい指示やニュアンスは、要約の過程で失われることがあります。だから、**毎回踏まえてほしい大事な前提は、会話の中だけに置かず、CLAUDE.md に書いておく** のが安全です。CLAUDE.md に書いた前提は、圧縮されてもディスクから読み直されて効き続けます（この CLAUDE.md は次の Chapter 3-3 で扱います）。会話に流れる一時的な文脈と、常に効かせたい前提を分けて持つ、という考え方です。

## /context で使用状況を見る

整える前に、まず現状を見たいことがあります。いまコンテキストをどれだけ使っているのか、何が場所を食っているのか。それを確認するのが `/context` です。

`/context` を実行すると、いまのコンテキストの使用状況が、カテゴリ別の内訳として一覧で表示されます。会話の履歴・読み込んだファイル・CLAUDE.md・呼び出したスキルなどが、それぞれどれだけウィンドウを占めているかが分かります。机の上の何が場所を取っているかを、一目で見渡すイメージです。

これは、整える判断のための道具です。`/context` で見て、特定のファイル読み込みが大きく場所を食っているなら整理する、会話が膨らんでいるなら `/compact` する、別の作業なら `/clear` する、といった判断ができます。やみくもに整えるのではなく、現状を見てから手を打つために使います。

## 必要な情報だけを渡す

ここまでは、埋まってきたものを整える手段でした。ですが、いちばん効くのは、**そもそも机を無駄に散らかさない** ことです。

無駄に埋まる大きな原因のひとつが、曖昧な依頼です。「このプロジェクトをいい感じにして」のような漠然とした頼み方をすると、AI は当たりをつけるために広い範囲のファイルを次々と読み込みます。その読み込んだ中身がすべてウィンドウに入り、関係の薄い情報で机が埋まります。1-3-2 で学んだ「曖昧な指示は AI が解釈で埋める」という話は、コンテキストの観点でも効いてきます。

対して、対象を絞って具体的に渡せば、AI は必要なファイルだけを読めばよく、ウィンドウを無駄に埋めずに済みます。「`proposal.md` の結論部分だけを、もっと具体的に直して」のように、どこを・何のために扱うかを絞ると、読み込みも応答も無駄が減ります。具体的に渡すことは、出力の精度（1-3-2）だけでなく、コンテキストの節約にもつながる、というわけです。

もうひとつの方法として、重い調べ物を切り出すやり方があります。長い Web 調査や大量のログの確認など、たくさんの情報を読む必要がある作業は、メインの会話で直接やらせると、その中身がすべてウィンドウに入って埋まります。これをサブエージェントという別の文脈に切り出すと、調べ物の細かい中身はそちらに留まり、メインの会話には結果だけが返ってきます。メインの机を散らかさずに調べ物を任せられる、というわけです。この方法は 3-4-2（サブエージェントで並列に任せる）で扱います。今は「重い作業は別の文脈に逃がせる」と把握すれば十分です。

## まとめ

- `/clear`: 無関係な作業に切り替えるとき、会話を空にして新しく始める。CLAUDE.md などプロジェクトの前提は保持される。古い文脈を残すとトークンを浪費し続けるので、作業の区切りで使う
- `/compact`: 同じ作業を続けつつ、膨らんだ会話を要約して圧縮し、コンテキストを解放する。`/compact 〇〇に注目して` のように残す観点を渡せる。上限が近づくと自動でも働く（自動コンパクション）
- 要約では初期の細かい指示が失われうるので、大事な前提は CLAUDE.md に置く
- `/context`: いま何にどれだけ使っているかを内訳で見る。整える前に現状を確認する道具
- そもそも無駄に埋めないことが最も効く。曖昧な依頼は広い読み込みを誘発する。対象を絞って具体的に渡し、重い調べ物はサブエージェント（3-4-2）に切り出す

---

これで Chapter 3-2 は終わりです。この Chapter では、AI が一度に保持できる文脈であるコンテキストを扱いました。コンテキストウィンドウには限りがあり、作業を続けると埋まること、詰め込みすぎると精度・速度・コストが悪化すること（3-2-1）、そしてそれを整える `/clear`・`/compact`・`/context` と、必要な情報だけを渡す進め方（本セクション）を押さえました。何を入れて何を入れないかを意識して扱えることが、Claude Code 活用の土台になります。

このなかで、繰り返し顔を出したのが CLAUDE.md でした。要約で失われたくない前提を置く場所として、`/clear` しても効き続ける前提として、何度も登場しました。次の Chapter 3-3 では、この CLAUDE.md を正面から扱います。最初のセクション 3-3-1 では、毎回説明していた前提（用語・ルール・進め方）を CLAUDE.md に書いて渡すと、AI がそれを踏まえて動くこと、`/init` で雛形を生成できること、大きくなったら `@import` で rules ファイルに分割できることを押さえます。
