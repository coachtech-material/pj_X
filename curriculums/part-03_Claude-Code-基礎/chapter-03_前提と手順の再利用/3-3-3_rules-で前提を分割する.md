## このセクションで学ぶこと

- 文体・規約・各業務の進め方を `.claude/rules/` に役割ごとのファイルへ分けられること。置いたファイルは各セッションで自動的に読み込まれること
- `paths` を指定すると、特定のファイルを扱うときだけ効くルールにできること
- 役割ごとに分けて、CLAUDE.md 本体を簡潔（200行目安。3-3-1）に保てること

CLAUDE.md に積み上がった前提を、役割ごとのルールファイルに分けて整理する方法を押さえます。

!!! note "補足"
    本文の `.claude/rules/` の例や `paths`・`@import` の記法は、仕組みを理解するための例です（読みながら書く・打つ必要はありません）。実際に手を動かすのは、セクション末尾の「やってみよう」です（本格的に文体ルールを用意するのは 3-5-3、仕組みとして固めるのは Part4）。記法は 2026年6月時点のものとして読んでください。

## 導入: CLAUDE.md が長くなって読みにくい

3-3-1 で、毎回説明していた前提を CLAUDE.md に書いて渡す方法を学びました。使い込むほど、書きたいことは増えます。用語の定義、文体のルール、表記の決まり、提案書の進め方、調査の進め方。気づくと、性質の違うルールが1枚の CLAUDE.md に積み上がって、どこに何が書いてあるのか探しにくくなります。

困るのは見た目だけではありません。3-3-1 で、CLAUDE.md は長すぎると肝心の指示が埋もれて従われにくくなると学びました。文体のルールを直したいだけなのに、長い1枚を上から探す。提案書のルールを足すと、関係のない調査のルールの間に紛れる。1枚に詰め込むほど、編集しづらく、効きづらくなります。

そこで、増えたルールを役割ごとのファイルに分けて整理します。その仕組みが rules、置き場が `.claude/rules/` です。

!!! quote "現場での考え方"
    最初は短かった CLAUDE.md に、思いついたルールを足し続けていたら、いつのまにか何百行にもなっていました。新しく入れたルールほど下の方に埋もれて効きが悪くなり、肝心なときに守られない。役割ごとにファイルへ分けてからは、直したいルールにすぐたどり着けて、CLAUDE.md 本体も見通しよく保てるようになりました。

## 役割ごとにファイルへ切り出す

**rules** は、CLAUDE.md に書いていたルールを、役割ごとの別ファイルに分けて整理する仕組みです。`.claude/rules/` というフォルダに、1ファイル1トピックで、中身がわかる名前のファイルを置きます。

```text
my-project/
├── CLAUDE.md                  # 全体に効かせる前提（短く保つ）
└── .claude/
    └── rules/
        ├── writing-style.md   # 文体・表記のルール
        ├── terms.md           # 用語の定義
        └── proposal.md        # 提案書の進め方
```

ここに置いたファイルは、**起動するたびに自動的に読み込まれます**。3-3-1 で `@import` という取り込み方に触れましたが、`.claude/rules/` のファイルは `@import` を書かなくても、CLAUDE.md と一緒に毎回効きます。分ける対象は、3-3-1 で CLAUDE.md に書いていたもののうち、量が増えてきたまとまりです。

- **文体・表記のルール**: 敬体で書く、1文は60字を目安にする、数字には出典を付ける
- **用語の定義**: 「案件」と「商談」の違いなど、自社特有の言葉
- **各業務の進め方**: 提案書の作り方、競合調査の段取りなど、業務ごとの決まり

置き場は、CLAUDE.md と同じ考え方で2つあります。そのプロジェクトで共有したいルールは `.claude/rules/`、どのプロジェクトでも効かせたい自分のルールは `~/.claude/rules/` に置きます。`.claude/rules/` は、Claude Code が決まったルールの置き場として扱う、`.claude/` 配下の主要な構成要素です。

## 必要なときだけ効かせる（paths 指定）

ルールには、常に効かせたいものと、特定の作業のときだけ効かせたいものがあります。提案書を書くときの文体ルールを、別の資料を直すときにまで読み込む必要はありません。

そこで、ルールファイルの先頭に `paths` を書くと、指定した場所のファイルを扱うときだけ、そのルールが読み込まれます。たとえば、提案書フォルダ向けのルールファイルの先頭にこう書きます。

```markdown
---
paths:
  - "proposals/**/*.md"
---

# 提案書の文体ルール

- 結論から先に書く
- 一文を短く保つ
```

この例では、`proposals` フォルダの Markdown ファイルを扱うときだけ、このルールが効きます。`paths` を書かないルールは、これまでどおり常に読み込まれます。指定したルールは関係ない作業のときには読み込まれないので、そのぶんコンテキスト（3-2-1）を節約できます。AI が多くのファイルを横断して扱う場面（Part6 のアプリ開発でコードを扱うときなど）で、特に効いてきます。今は、こういう絞り込みができると把握すれば十分です。

## CLAUDE.md から @import で取り込む

`.claude/rules/` に置けば自動で効きますが、その外にある特定のファイルを名指しで取り込みたいときは、3-3-1 で触れた `@import` を使います。CLAUDE.md の中に `@パス` と書くと、その場所のファイルの内容が一緒に読み込まれます。

```text
# ホーム配下の共有ルールを取り込む（複数プロジェクトで使い回す）
@~/.claude/rules/company-terms.md
```

パスは、それを書いたファイルの場所が基点です（相対パスでも絶対パスでも書けます）。取り込んだファイルがさらに別を取り込む入れ子は、最大4段までです（2026年6月時点）。

このカリキュラムの教材も、同じ作りです。執筆ルール（文体・用語・テンプレート）は CLAUDE.md に直接書かず、`.claude/rules/writing.md` という別ファイルに分けて置き、各セッションで自動的に読み込ませています。

## 分けると何が良くなるか

rules に分ける一番の効きどころは、**CLAUDE.md 本体を簡潔に保てる** ことです。3-3-1 で見た200行の目安どおり、本体が短いほど肝心の指示が埋もれず、AI が従いやすくなります。役割ごとに整理されるので、直すときも探しやすく、チームでの保守も楽になります。

ひとつ正確に押さえます。常に効かせるルール（`paths` を書かないもの）は、別ファイルに分けても起動時にすべて読み込まれます。つまり、ただ分けるだけでは、その場のトークン消費は減りません。減らしたいときは、さきほどの `paths` で必要なファイルのときだけ読ませるか、決まった手順ならスキル（3-3-2）にして呼んだときだけ読ませます。

## 前提・手順・ルールの棲み分け

これで Chapter 3-3 の3つの機能がそろいました。最後に棲み分けを整理します。

| 置き場 | 何を置くか | いつ読まれるか |
|---|---|---|
| CLAUDE.md | 全体に常に効かせたい最小限の前提（基本方針・主要な用語）。短く保つ | 毎セッション |
| `.claude/rules/` | 文体・規約・各業務のルールなど、量のある前提を役割ごとに | 毎セッション（`paths` 指定なら一致するファイルのときだけ） |
| スキル | 議事録整形・競合調査のような決まった作業手順 | 呼んだときだけ |

判断の軸は2つです。まず「常に効かせたい前提・ルール」か「必要なときに呼ぶ手順」か。前提・ルールなら CLAUDE.md と rules、手順ならスキルです。次に、前提・ルールのうち量が増えてきたものは、CLAUDE.md 本体に置いたままにせず `.claude/rules/` に役割ごとに切り出します。これらを束ねて、ゼロ指示で再現できる仕組みに固める設計は Part4 で扱います。

## やってみよう: 文体ルールを rules に切り出す

CLAUDE.md に書いた文体ルールを `.claude/rules/` に切り出し、会話を空にしても自動で効き続けることを確かめます。

**1. Claude Code を起動して、前提を書いた CLAUDE.md を用意する**

任意の練習用フォルダで起動します（3-1-1 で作った練習用フォルダを使ってもかまいません）。まず、分割の元になる CLAUDE.md を用意します。

```text
このフォルダに CLAUDE.md を作って、次のルールを書いてください。
・文章は敬体（です・ます調）で書く
・1文は60字を目安にする
・専門用語には初出でカッコ書きの説明を付ける
```

**2. 文体ルールを .claude/rules/ に切り出す**

```text
CLAUDE.md の文体ルールを .claude/rules/writing-style.md に切り出して、
CLAUDE.md 本体は短く保ってください。
```

できた `CLAUDE.md`（短くなる）と `.claude/rules/writing-style.md`（文体ルールの本体）を開いて、役割ごとに分かれたことを確かめます。`.claude/rules/` のファイルは自動で読み込まれるので、CLAUDE.md に取り込みの行を書く必要はありません。

**3. /clear のあとも効くことを確かめる**

`/clear` で会話を空にしてから、短い文章を書かせてみます（例:「来週の打ち合わせの案内文を2文で書いて」）。切り出したあとも敬体・60字目安といった文体が効いていれば、`.claude/rules/` に分けた文体ルールが自動で読み込まれて働いていることを確認できます。

!!! warning "注意"
    文体が効いていないように見えるときは、ファイルが `.claude/rules/` の中にあるか、`paths` を付けていないか（付けると一致するファイルのときだけ効きます）を確認します。その様子を Claude Code に伝えて、置き場所を一緒に見直しましょう。

!!! success "確認"
    CLAUDE.md が短くなり、文体ルールが `.claude/rules/writing-style.md` に分かれ、`/clear` のあとも文体が効いていれば成功です。本格的に本の文体ルールを rules で用意するのは 3-5-3、ハーネスとして仕組みに固めるのは Part4 で扱います。

## まとめ

- 増えてきたルールは `.claude/rules/` に役割ごとのファイル（1ファイル1トピック）へ切り出す。置いたファイルは各セッションで自動的に読み込まれる（`@import` は不要）
- `paths` を指定すると、一致するファイルを扱うときだけ効くルールになり、コンテキストを節約できる。`paths` なしは常に読み込まれる（2026年6月時点）
- 置き場はプロジェクト `.claude/rules/`、自分専用 `~/.claude/rules/`。rules の外のファイルを名指しで取り込みたいときは CLAUDE.md から `@import`（基点は書いたファイル、入れ子は最大4段）
- 分けると CLAUDE.md 本体を簡潔（200行目安。3-3-1）に保てる。ただし常時ルールは起動時に読まれる（総量は減らない）。必要なときだけ読ませたいのは `paths` 指定かスキル（3-3-2）
- 棲み分けは、常に効かせる前提・ルールは CLAUDE.md と rules、必要なときに呼ぶ手順はスキル

---

これで Chapter 3-3 は終わりです。毎回説明していた前提を渡す CLAUDE.md（3-3-1）、繰り返す作業手順を再利用するスキル（3-3-2）、そして増えた前提を役割ごとに分けて整理する rules（本セクション）で、一度きりの指示を、次回からも効く前提・手順・ルールに変えられます。

ここまでは Claude Code の中で完結する機能でした。次の Chapter 3-4「外部連携と拡張」では、Claude Code を外に広げる機能を扱います。最初の 3-4-1 で、MCP という仕組みで AI を社内外のサービス（カレンダー・スプレッドシート・各種SaaS など）につなぎ、その場でデータを読み書きさせられることを押さえます。あわせて、外部サービスのデータを扱うときは、2-5-3 で学んだ「AI に渡してよいもの・いけないもの」の線引きを前提に持つことを確認します。
