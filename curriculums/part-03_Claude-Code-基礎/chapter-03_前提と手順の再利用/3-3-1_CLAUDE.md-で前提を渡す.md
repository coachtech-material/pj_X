# 3-3-1 CLAUDE.md で前提を渡す

!!! note "前提知識"
    このセクションは 3-2-2「コンテキストを整える」の内容を前提としています。

この Chapter では、繰り返しを効率化する2つの主要機能を扱います。毎回踏まえてほしい前提を渡す CLAUDE.md と、繰り返す作業手順を再利用するスキルです。どちらも「一度きりの指示」を「次回からも効くもの」に変える機能です。

| セクション | テーマ | 種類 |
|---|---|---|
| 3-3-1 | CLAUDE.md で前提を渡す | 概念 |
| 3-3-2 | Skills で手順を再利用する | 概念 |

**この Chapter の進め方**: まず 3-3-1 で、毎回説明していた前提を CLAUDE.md に書いて渡す方法を押さえ、3-3-2 で、繰り返す作業手順をスキルとして保存し呼び出す方法へ進みます。最後に、この2つの使い分けを整理します。これらを束ねて仕組みとして固める設計は Part4 で扱います。

## このセクションで学ぶこと

- 毎回説明していた前提（用語・ルール・進め方）を CLAUDE.md に書いて渡すと、AI が踏まえて動くこと
- `/init` で CLAUDE.md の雛形を生成できること
- 大きくなったら `@import` で rules ファイルに分割できること

毎回同じ説明を繰り返す手間を、CLAUDE.md という前提の置き場でなくす方法を押さえます。

!!! note "補足"
    本文に出てくる CLAUDE.md の記述例やコマンド（`/init` など）は、仕組みを理解するための例です（読みながら書く・打つ必要はありません）。実際に CLAUDE.md を書いて作業に効かせるのは Chapter 3-5 の記事づくり（3-5-1）で、仕組みとして本格的に固めるのは Part4 です。コマンドの表記は変わりうるため、2026年6月時点のものとして読んでください。

## 導入: 毎回同じ前提を説明していないか

3-2-1 で、各セッションは新しいコンテキストウィンドウで始まり、前のセッションの会話は引き継がれないと学びました。これは裏を返すと、**毎回まっさらな状態から始まる** ということです。

すると、こういうことが起きます。昨日、AI に「うちの会社では『案件』と『商談』は別の意味で使う」「文章は常体ではなく敬体で書く」「数字には必ず出典を付ける」と伝えて、ようやく狙いどおりに動いてくれた。ところが今日また起動すると、AI はそれを覚えていないので、同じ説明を最初からやり直すことになります。3-2-2 で見たように、`/compact` の要約でも、こうした細かい前提は失われがちでした。

毎回同じ前提を説明し直すのは、無駄です。この前提を、会話の中ではなく、AI が毎回必ず読む場所に置いておければ、説明は一度きりで済みます。その置き場が CLAUDE.md です。

!!! quote "現場での考え方"
    自分が CLAUDE.md を書く前は、新しいセッションのたびに「結論から書いて」「箇条書きを多用しないで」と同じ注文を毎回付けていました。書いた前提を CLAUDE.md にまとめてからは、起動した直後から狙いどおりの文体で返ってくるようになり、毎回の前置きがまるごと要らなくなりました。一度きりの説明が、ずっと効き続ける前提に変わった感覚です。

## CLAUDE.md に前提を書いて渡す

**CLAUDE.md** とは、プロジェクトに置く、AI への永続的な前提・指示を書いた Markdown ファイルです。Claude Code は、各セッションの開始時にこのファイルを読み込みます。つまり、ここに書いておけば、起動するたびに AI がその内容を踏まえた状態で始まります。

何を書くかは、毎回 AI に説明し直していたことです。たとえば次のようなものです。

- **用語の定義**: 自分の会社やチームで特有の意味を持つ言葉（「案件」と「商談」の違いなど）
- **守ってほしいルール**: 文体（敬体で書く）、表記の決まり、出典の付け方など
- **進め方**: どういう順序で作業してほしいか、何を確認してから進めてほしいか

こうした前提を一度書いておけば、毎回伝えなくても、AI がそれを踏まえて動きます。3-2-2 で「要約で失われたくない大事な前提は CLAUDE.md に置く」と触れたのは、このことです。CLAUDE.md に書いた前提は、`/clear` で会話を空にしても、`/compact` で会話を圧縮しても、ディスクから読み直されて効き続けます。

ただし、ひとつ大事な性質があります。CLAUDE.md の内容は、AI が **必ず踏まえる前提** として渡されますが、機械的に強制されるルールではありません。Claude Code の公式ドキュメントも、これを「強制的な設定ではなくコンテキストとして扱われる」と説明しています（2026年6月時点）。AI はそれを読んで従おうとしますが、書き方が曖昧だと、解釈の余地が生まれて従いきれないことがあります。

だから、CLAUDE.md は **具体的に書く** ほど効きます。これは 1-3-2 で学んだ「曖昧な指示は AI が解釈で埋める」と同じ話です。

| 曖昧な書き方 | 具体的な書き方 |
|---|---|
| 丁寧に書く | 敬体（です・ます調）で書く |
| 読みやすく整える | 見出しは2スペース字下げ、箇条書きは3項目まで |
| きちんとテストする | コミット前に `npm test` を実行する |

左のような書き方では、AI は「丁寧とは何か」を自分の解釈で埋めます。右のように、検証できるくらい具体的に書くと、解釈の余地が狭まり、狙いどおりに効きます。

## /init で雛形を作る

CLAUDE.md は、ゼロから手で書き起こす必要はありません。`/init` というコマンドを使うと、AI が **いまのプロジェクトを分析して、CLAUDE.md の雛形を自動で作ってくれます**。

`/init` を実行すると、AI はプロジェクトのファイルを見て、どんなプロジェクトか、どういう構成か、どんな決まりごとがありそうかを読み取り、その内容を盛り込んだ CLAUDE.md を生成します。まず雛形を作ってもらい、そこに自分の前提（AI が自力では分からない用語の定義やルール）を書き足していくのが、現実的な始め方です。

すでに CLAUDE.md がある場合、`/init` は上書きせず、改善の提案をします。一からやり直すのではなく、いまあるものをよりよくする方向で働きます。

## 大きくなったら @import で分割する

使い込むうちに、CLAUDE.md に書きたいことが増えていきます。用語、文体、各業務の進め方と、前提が積み上がると、1つのファイルが長くなりすぎて見通しが悪くなります。

そこで、`@import` という仕組みで、別のファイルを取り込めます。CLAUDE.md の中に `@パス` と書くと、その場所にあるファイルの内容が読み込まれます。

```text
# 文体のルールは別ファイルにまとめる
@.claude/rules/writing-style.md

# 各業務の進め方も分けておく
@.claude/rules/sales-workflow.md
```

このように書くと、役割ごとに分けた別ファイルが、CLAUDE.md と一緒に読み込まれます。役割別のルールを置く場所として、`.claude/rules/` というフォルダがよく使われます（このカリキュラムの執筆ルールも、`.claude/rules/` に分けて置かれています）。

!!! note "補足"
    `@import` のパスは、それを書いたファイルの場所を基点に解釈されます（コマンドを実行する場所ではありません）。取り込んだファイルが、さらに別のファイルを取り込むこともでき、その入れ子は最大4段までです（2026年6月時点）。最初のうちは1つの CLAUDE.md で十分で、増えてきたら分ける、という順番で構いません。

CLAUDE.md を置く場所には、いくつかの選択肢があります。代表的なのは次の2つです。

- **プロジェクト直下の `./CLAUDE.md`**: そのプロジェクトでの前提。チームで共有したいものはここに置きます
- **自分専用の `~/.claude/CLAUDE.md`**: どのプロジェクトでも効かせたい、自分個人の好み（文体の好みなど）を置きます

どちらに置くかは、その前提を「このプロジェクトだけのものにしたいか」「自分のすべての作業で効かせたいか」で決めます。

最後に、効かせるためのコツをひとつ。CLAUDE.md は、長く書けば効くというものではありません。3-2-1 で見たとおり、CLAUDE.md の内容は毎回コンテキストウィンドウに読み込まれ、それ自体がトークンを消費します。長すぎると、かえって肝心の指示が埋もれて従われにくくなります。公式ドキュメントも、1ファイルあたり **200行以下** を目安にし、本当に必要なものだけを書くことを勧めています（2026年6月時点）。簡潔に保つことが、効きやすさにつながります。

なお、ここで扱うのは「前提を渡すと AI が踏まえて動く」という使い方までです。一度うまくいった仕事を CLAUDE.md やスキル・設定として書き出し、ゼロ指示で再現できる仕組みとして固める設計は、Part4（4-1-2）で扱います。

## まとめ

- CLAUDE.md は、プロジェクトに置く AI への永続的な前提・指示。Claude Code が各セッションの開始時に読むので、毎回説明し直さなくても AI が踏まえて動く（`/clear`・`/compact` でも効き続ける）
- 内容はコンテキストとして渡され、機械的に強制されるわけではない。だから「丁寧に」ではなく「敬体で書く」のように、検証できるくらい具体的に書くと効きやすい
- `/init` で、いまのプロジェクトを分析した雛形を生成できる（既にあれば改善を提案する）
- 増えてきたら `@パス` の記法で別ファイルを取り込み、`.claude/rules/` に役割ごとに分けられる。配置はプロジェクト直下の `./CLAUDE.md`、自分専用は `~/.claude/CLAUDE.md`。200行以下を目安に簡潔に保つと効く
