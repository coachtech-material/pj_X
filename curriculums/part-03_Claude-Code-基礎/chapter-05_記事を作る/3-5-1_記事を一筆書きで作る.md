# 3-5-1 記事を一筆書きで作る

この Chapter は、Part3 で学んだ基本操作と主要機能を、共通題材の記事1本に注いで使い切る章です。Section は 3-5-1 の1つだけで、1-3-1 で段取りせず丸投げして失敗した同じ記事を、今度は手順立てて作り直します。

!!! note "前提知識"
    このセクションは 1-3-4「構造化とアウトカムから決める完成条件」、3-1-6「出力の検証と軌道修正」、3-2-2「コンテキストを整える」、3-3-2「Skills で手順を再利用する」の内容を前提としています。

!!! note "このハンズオンで使う機能"
    Part3 までに学んだ次の考え方・機能を、ここで実際に使います。

    - 仮説・構造化・アウトカムから逆算する完成条件の1枚（1-3-3／1-3-4 で学習）
    - 依頼して実行・ファイル編集と差分の確認、`@` でファイルを文脈に渡す（3-1-1／3-1-2 で学習）
    - 出力を完成条件と照らし、ずれたら軌道修正する検証ゲート、一次情報での裏取り（3-1-6 で学習）
    - 会話を空にする `/clear` と、必要な情報だけを渡す進め方（3-2-2 で学習）

    題材は、1-3-1 で丸投げに失敗した記事（あなたが 1-2-2 で `theme.md` に決めたテーマ）です。今回作る記事は、4-4 で仕様駆動と仕組み化により完成させ、5-2-5 で公開する、同じ題材として使い続けます。

## このセクションで学ぶこと

- 仮説・構造化・完成条件を実際に1枚のファイルに書き出すこと
- 完成条件に必要な材料を Claude に調べさせ、一次情報で裏取りすること
- たたき台を出させ、完成条件と一項目ずつ照らして、軌道修正で狙いに収束させること

1-3 で学んだ「AIに渡す思考」と、Part3 で学んだ操作・検証を一つの流れにつなぎ、記事を1本作り切ります。

## 導入: 丸投げした記事を、今度は手順立てて作り直す

1-3-1 で、テーマを一息に丸投げして「ちゃんとした記事を書いて」と頼み、浅い・狙いからずれる記事が返ってくることを体験しました。あのとき書き出したズレが、このハンズオンの出発点です。

今回は、同じテーマを段取りを立てて作り直します。狙うのは、立派に見える記事をただ完成させることではありません。その記事の先にあるアウトカム（読者に何が伝わり、どう動いてほしいか）から完成条件を逆算して先に渡し、出てきたものを完成条件と照らしながら直して、狙いに収束させる。この一連の流れを、自分の手で通すことが目的です。

!!! quote "現場での考え方"
    自分も最初は、丸投げで返ってきた記事を「もっと良くして」と何度も突き返していました。けれど何が良いのかを先に決めていないので、いつまでも収束しません。完成条件を4つだけ箇条書きにして先に渡すように変えたら、直しの回数が半分以下になりました。先に「何ができたら完成か」を決めておくと、AI もそこへ向けて出力をそろえてくれます。

## 記事づくり前の確認

始める前に、次がそろっているか確認します。

- [ ] Claude Code にログイン済みで、`claude` で起動できる（1-2-1）
- [ ] 1-2-2 で決めたテーマを書いた `theme.md` が、`claude-practice` フォルダにある（1-2-2）
- [ ] 1-3-1 で丸投げして作った `article-draft1.md` が、`claude-practice` フォルダに残っている（最後に読み比べます）

ターミナルを開きます（多くは、あなたのユーザーフォルダ＝ホームで開きます）。今回は記事づくりに集中するので、`theme.md` のある `claude-practice` フォルダの中に移動してから起動します。フォルダの移動には、2-1 で学んだ `cd` を使います。

```bash
cd claude-practice
claude
```

`claude-practice` の中で起動すると、この中にあるファイルを `@theme.md` のようにフォルダ名を付けずに渡せます（`@` でのファイルの渡し方は 3-1-2 で学びました）。起動の詳細は 1-2-1 で扱いました。

!!! warning "注意"
    このあと作るファイルが `claude-practice` の中に見当たらない、または別の場所にできてしまうときは、Claude Code を起動した場所が `claude-practice` と違っている可能性があります（起動した場所を基点にファイルが作られます。カレントディレクトリの考え方は 2-1 で扱いました）。そのときは、いったん `/exit` で終了し、`claude-practice` フォルダに移動してから起動し直すか、「`claude-practice` の中に作ってほしい」と Claude にそのまま伝えれば、置き直してくれます。

## 実践: 完成条件を先に決めて、記事を1本作り切る

このハンズオンは、5つの Step で進めます。仮説・構造化・完成条件を1枚にまとめ（Step 1）、材料を調べて裏取りし（Step 2）、たたき台を出させ（Step 3）、完成条件と照らし（Step 4）、軌道修正して仕上げる（Step 5）という流れです。

各 Step で Claude が返してくる文章・調査結果・対話は、毎回違ってよいものです。大事なのは、文面を例とそろえることではなく、Step ごとに示す「観察できる達成状態」に到達することです。

### Step 1: 仮説・構造化・完成条件を1枚にまとめる

まず、1-3-4 で「1枚にまとめる」と学んだ準備を、実際に1つのファイルとして書き出します。`theme.md` を Claude に読ませ、仮説（この角度で進める）・構造（記事をどの小単位に分けるか）・完成条件（アウトカムから逆算した点検できる条件）を整理させ、`article-spec.md` という1枚のファイルにまとめてもらいます。

入力欄に、次のように頼みます（これは依頼の一例です。あなたのテーマやアウトカムに合わせて言葉を変えてかまいません）。

```text
@theme.md を読んでください。このテーマで記事を1本書く準備として、次の3つを
article-spec.md という1つのファイルにまとめてください。

1. 仮説: このテーマは、誰に向けて・どの角度で書くのが良さそうか（1つに絞る）
2. 構造: 記事を「角度を決める・材料を集める・構成を組む・本文・見直し」のような
   小さな単位に分けるなら、どう分かれるか
3. 完成条件: この記事で読者にどうなってほしいか（アウトカム）を先に置き、そこから
   逆算して「何ができたら完成か」を、点検できる箇条書きにする
   （例: 想定読者がつまずく一点が具体例つきで解説されている／2000字程度／
   専門用語にひとこと説明がある、など）
```

`@theme.md` と打つと、`theme.md` の中身がそのまま文脈に渡ります（`@` でファイルを渡す方法は 3-1-2 で学びました）。Claude は `theme.md` を踏まえて、仮説・構造・完成条件を `article-spec.md` に書き、確認を求めてきます。承認して、ファイルを作成させます。

できあがった `article-spec.md` を開いて読み、完成条件が「できているかどうかを一つずつ確かめられる形」になっているかを見ます。「読者に役立つ」のような曖昧な言葉ではなく、「○○が具体例つきで書かれている」「2000字程度」のように点検できる形になっているのが望ましい状態です。曖昧なままなら、「完成条件の3つ目が曖昧なので、点検できる形に書き直して」のように直してもらいます。

!!! success "確認"
    `claude-practice` の中に `article-spec.md` ができ、仮説・構造・完成条件の3つが書かれていれば、この Step は完了です。完成条件が、後で一項目ずつ照合できる箇条書きになっていることが要点です（中身の文面は Claude が出す一例で、あなたのものとは違ってかまいません）。

### Step 2: 材料を調べさせて、一次情報で裏取りする

完成条件を満たすには、一般論ではなく、具体例・データ・事例といった材料が要ります。これを Claude に Web で調べさせ、出てきた事実を一次情報で確かめます（調べさせて材料を集めることと、裏を取ること＝一次情報の確認をセットで行うことは、3-1-6 で学びました）。

同じ会話の続きで、次のように頼みます（依頼の一例です）。

```text
article-spec.md の完成条件を満たすために必要な材料を、Web で調べて集めてください。
とくに、本文で使えそうな具体例・データ・事例を探してください。
集めた事実には、それぞれ出典（元のページの URL）を必ず添えてください。
```

Claude が調べた結果を返してきます。ここで止めずに、数字・固有名詞・出典は、そのまま信じずに確かめます。2-5-2 と 3-1-6 で見たとおり、生成AI は「出典がありそうな形」をもっともらしく作ることがあり、実在しない書名や URL を返すこともあります。

示された出典のうち、本文の根拠として使う重要なものは、自分でその URL を開いて、本当にその内容が書かれているかを確かめます。実在しない・内容が違うものがあれば、「この出典が開けない（内容が違う）ので、確かな一次情報に差し替えて」と伝えて直してもらいます。

!!! success "確認"
    完成条件を満たすのに使えそうな材料がそろい、本文の根拠に使う事実については、出典を自分で開いて裏が取れていれば、この Step は完了です。調査結果の中身は毎回違ってよく、大事なのは「裏づけのある材料が手元にある」ことです。

### Step 3: 完成条件を渡して、たたき台を出させる

ここでようやく、本文のたたき台を書かせます。Step 1 の1枚（`article-spec.md`）と Step 2 で裏取りした材料をもとに、記事のたたき台を `article-draft2.md` という別ファイルに書いてもらいます。

!!! note "補足"
    ファイル名を `article-draft2.md` とするのは、1-3-1 で丸投げして作った `article-draft1.md` と区別するためです。`article-draft1.md` は最後に読み比べるので消さず、別ファイルとして新しく作ります。この `article-draft2.md` は 4-4 で土台にするので、こちらも残します。

同じ会話の続きで、次のように頼みます（依頼の一例です）。

```text
@article-spec.md の仮説・構成・完成条件と、いま調べてくれた材料をもとに、
記事の本文のたたき台を article-draft2.md として書いてください。
完成条件を満たすことを意識し、裏取りした事実には本文中で出典がたどれるようにしてください。
```

Claude が `article-draft2.md` を書き、確認を求めてきます。承認してファイルを作成させ、できあがった本文を開いて、ひととおり読みます。

この本文は、Claude が出すたたき台の一例です。文面があなたの想像と一致する必要はありません。この段では「完成条件に照らして直していける、本文の出発点ができた」ことが大事です。

!!! success "確認"
    `claude-practice` の中に `article-draft2.md` ができ、`article-spec.md` の構成に沿った本文のたたき台になっていれば、この Step は完了です。

### Step 4: 完成条件と、一項目ずつ照らす（検証ゲート）

たたき台を、`article-spec.md` の完成条件と一項目ずつ照らします。3-1-6 で学んだ検証ゲートです。「なんとなく良い／立派に見える」という曖昧な感想でまとめて評価するのではなく、点検できる条件に分けて、一つずつ「できているか」を見ます。

自分で読んで照合してもよいですし、Claude に照合を手伝わせることもできます。同じ会話の続きで、次のように頼みます（依頼の一例です）。

```text
@article-spec.md の完成条件を一項目ずつ、article-draft2.md が満たしているかを点検してください。
満たしている項目と、満たしていない項目を分けて、満たしていない項目については
どこがどう足りないかを具体的に挙げてください。
```

Claude の点検結果を鵜呑みにせず、自分でも本文を読んで突き合わせます。最終的に大事なのは、「どの完成条件が、どこで、どう未達か」を自分の言葉で言えるようになることです。たとえば「具体例つきで解説する、という条件に対して、3つ目の見出しが一般論で終わっている」のように、ずれを具体的に特定します。

!!! success "確認"
    完成条件の各項目について「満たしている／満たしていない」を判定でき、未達の項目はどこがどう足りないかを具体的に言葉にできていれば、この Step は完了です。

### Step 5: 軌道修正して仕上げ、丸投げ版と読み比べる

Step 4 で洗い出した未達の点を、軌道修正の指示で直していきます。3-1-6 で学んだとおり、「もっと良くして」では AI は何をどう直すか分からず、また解釈で埋めて的を外します。**期待した結果と、実際にどうずれているかを具体的に伝える** のがこつです。

同じ会話の続きで、未達の項目ごとに具体的に頼みます（依頼の一例です）。

```text
3つ目の見出しが、完成条件の「実務に踏み込んだ具体例つきで解説する」を満たしていません。
一般論で終わっているので、Step 2 で調べた事例を1つ使って、具体例に書き換えてください。
```

直してもらったら、その項目が完成条件を満たしたかを、もう一度照合します（Step 4 に戻る）。満たすまで、この「具体的に直す → 照合する」を未達の項目ごとに繰り返します。指示が具体的であるほど、必要な直しは少なくて済みます。

!!! info "ポイント"
    同じ箇所を何度直しても収束しないときや、やり取りが長くなって Claude が迷い始めたと感じたときは、いったん `/clear` で会話を空にして仕切り直すほうが速いことがあります（3-2-2 で学びました）。`/clear` してもプロジェクトの前提は保持されるので、空にしたあと `@article-spec.md` で完成条件だけを渡し直し、「この記事をこの完成条件に合わせて直したい。いまの本文は @article-draft2.md」のように、整理した文脈で出し直すと、収束が早まります。

完成条件をひととおり満たしたら、最後に、1-3-1 で丸投げして作った `article-draft1.md` と、今回手順立てて作った `article-draft2.md` を並べて読み比べます。Finder／エクスプローラーで `claude-practice` フォルダを開き、両方のファイルを開いて見比べてください。

丸投げ版が「浅い・狙いからずれる・過不足がある」だったのに対し、完成条件を先に決めて検証しながら作った今回のほうが、狙いに近づいているはずです。この差が、丸投げと「AIに渡す思考」の差です。

読み比べが済んだら、`/exit` で Claude Code を終了します。`article-draft2.md` と `article-spec.md` は、4-4 で記事を仕様駆動と仕組み化により完成させるときに土台として使うので、消さずに残しておいてください（`article-draft1.md` も読み比べ用に残します）。

!!! warning "注意"
    思ったように直らない、調査が的外れ、ファイルが想定の場所にできない、といったつまずきは起こりえます。そのときは、期待した結果（どうなってほしいか）と、実際にどうなったか（何が起きているか）を具体的に Claude に伝えて、直してもらいます。この「うまくいかない様子を具体的に伝えて直してもらう」進め方そのものが、3-1-6 で学んだ軌道修正です。エラー文や画面の様子をそのまま貼って渡すのも有効です。

- [ ] `article-spec.md` に、仮説・構造・点検できる完成条件の1枚を書き出せた
- [ ] 完成条件に必要な材料を Claude に調べさせ、本文の根拠に使う事実を一次情報で裏取りした
- [ ] `article-draft2.md` にたたき台を作り、完成条件と一項目ずつ照合して未達の点を特定した

- [ ] `article-spec.md`・`article-draft2.md` を `claude-practice` に残した（4-4 で使う）

## まとめ

- 記事づくりは、完成条件を先に1枚にまとめてから渡すと、丸投げとはまるで違う精度で進む。仮説・構造化・完成条件（1-3）が、その準備になる
- たたき台を出させる前に材料を調べさせ、数字・固有名詞・出典は一次情報で裏取りする。立派に見える出力ほど確かめる（3-1-6）
- 出てきた本文は、完成条件と一項目ずつ照らして未達を特定し、期待と実際のずれを具体的に伝えて直す。これを繰り返して狙いに収束させる検証ゲートが背骨
- やり取りが膨らんだら `/clear` で仕切り直し、`@` で必要な情報だけを渡し直す（3-2-2）。AI の出力は毎回違ってよく、確認するのは文面ではなく完成条件を満たしたかどうか

次の Part4 では、ここで個別に使った工夫を、より深い形へ束ねます。AIに思い通り働いてもらう工夫は、「その場の指示（プロンプト）→前提を渡す（コンテキスト）→確実に働ける環境を組む」の3階層で深まっていきます。Part3 で別々に使った CLAUDE.md・Skills・MCP・サブエージェント・hooks・設定・プラグインは、この最上層にあたる、AI が確実に働ける環境を成すものでした。Part4 ではこの最上層を一枚の地図として俯瞰し、一度うまくいった仕事を仕組みとして残して再現する力を身につけます。その仕上げとして、1-3-1 で丸投げに失敗し、今回手順立てて作ったのと同じ記事題材を、Part4 では仕様駆動と仕組み化でさらに破綻なく仕上げ直し、研修前半からの伏線を回収します（4-4）。
