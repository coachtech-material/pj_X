# 3-4-3 hooks で自動化する

!!! note "前提知識"
    このセクションは 3-4-2「サブエージェントで並列に任せる」の内容を前提としています。

## このセクションで学ぶこと

- フックで、特定のタイミング（実行前・完了時など）に決めた処理を自動で挟み込めること
- 「人が毎回覚えて手でやる」を「決めたタイミングで自動で挟む」に変えられること
- どんなタイミングで挟めるか（代表例）と、設定をどこに書くか

毎回くり返す確認や整形を、決まったタイミングで自動実行するフックという仕組みを把握します。

!!! note "補足"
    このセクションの本文に出てくる設定やイベント名は、仕組みを理解するための例です（読みながら打つ必要はありません）。自動化を実際に組み込むのは Part4 で、ここでは「決まったタイミングで自動で挟める」と知るのが目的です。

---

## 導入: 毎回の決まった処理を、自動で挟む

AI に作業を任せていると、毎回きまって手でやる処理が出てきます。ファイルを直してもらったあとに体裁を整える、ある操作の前に念のため内容を確かめる、といったことです。一つひとつは小さくても、毎回となると地味に手間ですし、人がやる以上は忘れることもあります。「ファイルを直したら整形する」と決めているのに、整形を忘れたまま先に進んでしまう、というたぐいです。決まりきった処理なら、人が覚えておくのではなく、決めたタイミングで自動的に挟まってほしい。これを実現するのがフックです。

---

## フックとは

**フック** は、Claude Code の作業の流れの特定の時点で、あらかじめ決めておいた処理を自動で実行する仕組みです。公式ドキュメントの言葉では、「ライフサイクル内の特定のポイントで自動的に実行されるユーザー定義の処理」と説明されています。ライフサイクルとは、Claude Code が依頼を受けて作業を進めていく一連の流れのことです。その流れの中の決まった地点に、自分が決めた処理を仕込んでおけます。

フックの値打ちは、「人が毎回覚えて手でやる」を「決めたタイミングで自動で挟む」に変えられることです。一度仕込んでおけば、その地点を通るたびに、忘れることなく処理が走ります。やり忘れや、人によるばらつきがなくなります。

## どんなタイミングで挟めるか

処理を挟めるタイミング（イベント）は何種類も用意されています。代表的なものは次のとおりです。

- **ツールの実行前** （PreToolUse）: AI がファイル編集やコマンド実行などの操作をする直前
- **ツールの実行後** （PostToolUse）: その操作が終わった直後
- **応答の完了時** （Stop）: AI が一連の応答を終えたとき

このほかにも、セッションの開始時や終了時など、多くのタイミングが用意されています。ここでは、代表的なものを押さえれば十分です。

これらを使うと、たとえば次のような自動化ができます。

- ファイルを編集した **後** （PostToolUse）に、自動で体裁を整える
- 特定のコマンドの **前** （PreToolUse）に、念のため確認の処理を挟む

設定は、3-1-4 で触れた settings.json に書きます。settings.json の中の `hooks` という項目に、「どのタイミングで」「どの処理を」走らせるかを記述しておくと、その地点を通るたびに自動で実行されます。

!!! note "補足"
    ここで挙げたイベント名（PreToolUse・PostToolUse・Stop など）は2026年6月時点のもので、種類は今後も増減します。実際に使うときは、最新の公式ドキュメントで、どんなタイミングが用意されているかを確認してください。

フックは「決まったタイミングで決まった処理を自動で挟む」仕組みだと押さえれば、ここでは十分です。どんな自動化を、どう組み込むと業務が楽になるか、という設計の話は Part4 で扱います。

## まとめ

- フックは、Claude Code の作業の流れの特定の時点で、決めておいた処理を自動で実行する仕組み。「人が毎回覚えて手でやる」を「決めたタイミングで自動で挟む」に変える
- 挟めるタイミングには、ツールの実行前（PreToolUse）・実行後（PostToolUse）・応答の完了時（Stop）などがある（ほかにも多数）。ファイル編集後に自動で整形する、特定のコマンドの前に確認を挟む、といった使い方ができる
- 設定は settings.json の `hooks` に書く。ここでは「決まったタイミングで自動で挟める」と知れば十分で、自動化を組み込む設計は Part4
