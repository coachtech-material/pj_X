# 3-5-4 プロンプトと検証ゲートで第1章を書く

!!! note "前提知識"
    このセクションは 3-5-3「rules で文体を用意する」、1-3-2「プロンプトのフレームワークとAIに任せるリスク」、3-1-6「出力の検証と軌道修正」、3-1-3「モデル・effort・コスト」、3-4-2「サブエージェントで並列に任せる」の内容を前提としています。

!!! note "このハンズオンで使う機能"
    プロンプトの型（役割・文脈・指示・制約・出力形式。Part1 で学習）、モデルと努力レベル（effort）の選び分け（3-1-3 で学習）、Web 調査・裏取り・検証ゲート（Part3 で学習）、組み込みサブエージェントによるレビュー（3-4-2 で学習）を使います。前提・目次・文体はすでに CLAUDE.md と rules にあるので、毎回書く必要はありません。

## このセクションで学ぶこと

- 完成条件を、自分が照合するためのチェックリストにする
- 第1章は本の顔なので、モデルと努力レベル（effort）を上げて力を入れて書かせる
- いきなり書かせず、まず見出し構成を提案させて方向を合わせ、固まってから一次情報を踏まえて書かせる
- 検証ゲートでは、サブエージェントに下見レビューさせ、自分が完成条件で最終判断して作り切る（`chapters/01-….md`）

最初の丸投げ版と読み比べ、良い文脈があれば短い指示でも、深さ・狙い・正しさが上がることを確かめます。

---

## 導入: 前提が効いていれば、指示は短くていい

最初の丸投げでは、長い一文に「ちゃんとした本を」と詰め込んでも外れました。いまは違います。誰に・何を・狙い（CLAUDE.md）も、文体（rules）も、章立て（OUTLINE.md）も、すでにプロジェクトに置いてあります。

だから、第1章を書く指示はむしろ短くなります。役割や文体を毎回書き直す必要はなく、「どの章を・どんな狙いで」という短い狙い指示で足ります。これが、コンテキストが効いている状態です。ただし、第1章のような大きな単位は、いきなり全部書かせると、できあがってから大きく直すことになりがちです。そこで、まず見出し構成を提案させて方向を合わせ、固まってから書かせます（タスクを刻んで進める、3-1-6 の考え方です）。第1章は本の顔なので、ここでは力を入れて（モデルと努力レベルを上げて）書かせます。あとは、AIに任せること自体のリスク（もっともらしい誤り）に備えて、検証ゲートで完成条件と照らし、出典を裏取りします。検証では、3-4-2 で学んだサブエージェントに下見のレビューをさせ、最終判断は自分でします。

## 実践: 第1章を書いて検証ゲートで仕上げる

### Step 1: 完成条件をチェックリストにする

書き始める前に、第1章が「何ができていれば完成か」を、自分が点検できるチェックリストにします。これは Part1 で学んだ、アウトカムから逆算する完成条件です。AIに丸ごと渡す指示ではなく、あとで出力を照らすための自分用のものさしです。

例（自分のテーマに合わせて作ります）:

- [ ] 想定読者がつまずく一点が、具体例つきで解説されている
- [ ] 一般論で終わらず、実務で使える踏み込みがある
- [ ] 事実・数字・固有名詞に出典がある
- [ ] 文体ルールに沿っている（敬体・初心者向けなど）

### Step 2: 第1章に力を入れる設定にする

第1章は本の顔です。読者が最初に開き、続きを読むかを決める章なので、深さと正確さに力を入れたいところです。そこで、3-1-3 で学んだモデルと努力レベル（effort）を、ここで実際に上げます。まずモデルを重い側に切り替えます。

```text
/model opus
```

あわせて、答える前にできるだけ深く考えさせたいので、努力レベルも最大まで上げます。

```text
/effort max
```

重い側のモデルと高い努力レベルは、じっくり考えてから書くぶん、込み入った説明や構成で質が上がりやすくなります（そのぶん時間とコストは増えます）。あとで短い言い回しの修正だけをするようなときは、軽い側に戻してかまいません。タスクの重さに道具を合わせる 3-1-3 の使い分けを、本づくりで実際に使う場面です。

!!! note "補足"
    選べるモデルや努力レベルの段階は、プランや時点で変わります（2026年6月時点で Pro の既定は Sonnet 4.6）。一覧に重い側のモデルが無ければ、`/effort` を選べる範囲でいちばん高い段階に上げるだけでもかまいません。大事なのは「本の顔だから力を入れる」と意識して設定を選ぶことです。

### Step 3: まず見出し構成を提案させる（本文はまだ書かせない）

`my-book` で起動し、いきなり本文を書かせず、まず章の中の見出し構成だけを提案させます。役割や文体はファイルに任せ、プロンプトでは「まだ書かず、構成から」という進め方を番号付きで指定します。

```text
第1章を書きたいです。まだ本文は書かず、次の手順で、まず見出し構成だけを提案してください。
1. CLAUDE.md を読み込む（誰に・何を・狙い・完成条件）
2. OUTLINE.md を読み込む（第1章がどの章で、前後とどうつながるか）
3. 第1章で扱う事実・数字・固有名詞の一次情報を、Web で調べる（WebFetch / WebSearch）
そのうえで、第1章を構成する見出しの案と、各見出しで何を書くかの方針を、箇条書きで示してください。
```

CLAUDE.md・OUTLINE.md・rules はすでにあるので、役割や文体を並べ立てる必要はありません。返ってくるのは、前提と一次情報を踏まえた見出し構成の案です。最初の丸投げのときと違い、本文を書く前に方向を確かめられます。

### Step 4: 構成を直して、固まったら執筆させる

提案された構成を、Step 1 のチェックリストや自分の狙いと照らして点検します。ずれていれば、具体的に伝えて直させます。何度かやり取りして構成が納得できる形になってから、本文を書かせます。

```text
（構成への修正があれば伝える。例:「2つ目の見出しは、具体例から入る並びにしてください」）
この構成でいきましょう。各見出しを順に書いて、chapters/01-（章タイトル）.md に保存してください。
- 一般論で終わらせず、実務で使える踏み込みを入れる
- 事実・数字・固有名詞は、調べた一次情報の出典を示す
- 迷う点があれば、勝手に決めず AskUserQuestion で質問する
```

構成が固まっているので、本文は狙いに沿って書かれます。これが、いきなり丸ごと書かせるのとの違いです。

### Step 5: 検証ゲート（サブエージェントの下見 → 自分で最終判断）

出てきた第1章を、Step 1 のチェックリストと照らします（Part3 で学んだ検証ゲート）。ここで、3-4-2 で学んだ組み込みサブエージェントを使います。自分でいきなり通読する前に、別の文脈で動くサブエージェントに第1章を読ませ、完成条件と照らして「満たせていない点」を指摘させます。レビューの観点として、Step 1 のチェックリストをそのまま渡します。

```text
chapters/01-（章タイトル）.md を、サブエージェントにレビューさせてください。
次の完成条件と一項目ずつ照らして、満たせていない点と該当箇所を、指摘だけ返してください（書き換えはしない）。
- 想定読者がつまずく一点が、具体例つきで解説されている
- 一般論で終わらず、実務で使える踏み込みがある
- 事実・数字・固有名詞に出典がある
- 文体ルール（敬体・初心者向け）に沿っている
```

サブエージェントは第1章を別の文脈で読み、指摘の箇条書きだけをメインに返します。長い本文を読み込んでも、メインの会話（このあとの修正に使う文脈）は膨らみません。これが 3-4-2 で学んだ「別働きに任せて要点だけ受け取る」使い方の、レビューへの応用です。

ただし、指摘はうのみにしません。**最終判断は自分**です。返ってきた指摘を Step 1 のチェックリストと突き合わせ、本当に直すべきかを決めます。とくに出典は、そのまま信じません。AI はもっともらしい出典を作ることがあります。「この章の数字と出典の一次情報を示して」と調べさせ、示されたページを自分で開いて、本当にそう書いてあるかを確かめます。

直すべき点が決まったら、期待と実際のズレを具体的に伝えて直させます。

```text
「想定読者がつまずく一点」が一般論になっています。
初心者が最初に間違えやすい具体例を1つ入れて、その直し方まで書いてください。
```

合格するまで、章を小さく区切って一段ずつ直します。

### Step 6: 最初の丸投げ版と読み比べる

仕上がった第1章（`chapters/01-….md`）と、`claude-practice` に残しておいた丸投げの下書き（`book-draft1.md`）を読み比べます。深さ・狙い・正しさのどれが、どう良くなったかを言葉にしてみてください。違いを生んだのは AI の賢さではなく、前提・目次・文体という文脈と、検証ゲートです。

## まとめ

- 第1章は本の顔。モデルと努力レベルを上げて力を入れる（3-1-3 の使い分けを実際に使う場面）
- 前提・目次・文体がファイルにあれば、指示は短い狙い指示で足りる（コンテキストが効いている）。ただし大きい章は、いきなり書かせず見出し構成を提案させてから書く（刻んで進める）
- 検証ゲートでは、サブエージェントに下見レビューさせて指摘を受け取り、最終判断は自分でする（3-4-2 の応用）。出典は一次情報で裏取りする
- 同じテーマでも、丸投げと比べて深さ・狙い・正しさが上がる。差は文脈と検証から生まれる
