# 3-5-3 rules で文体を用意する

!!! note "前提知識"
    このセクションは 3-5-2「OUTLINE.md で目次を作る」と 3-3-3「rules で前提を分割する」、3-2-2「コンテキストを整える」、3-1-5「中断・巻き戻し・再開」の内容を前提としています。

!!! note "このハンズオンで使う機能"
    `.claude/rules/` と `@import`（Part3 で学習）を使います。文体・トーン・禁則・用語をルールファイルにまとめ、CLAUDE.md から取り込んで、すべての章に効かせます。

## このセクションで学ぶこと

- 本の文体・トーン・禁則・用語を `.claude/rules/` のルールファイルにまとめる
- CLAUDE.md から `@import` でそのファイルを取り込む
- 常時オンの前提（CLAUDE.md）と、詳細な文体ガイド（rules）の使い分けを理解する
- 前提・目次・文体をファイルに置けば、記憶が 0 に戻る新しいセッションでも自動で効くと理解する
- 区切りのいいところで `/rename` で名前を残し、`/exit` で終了して開き直し、`/resume` で前のセッションに戻れることを体験する

前提・目次の次は、本全体で文章の調子をそろえる文体ルールを用意します。

---

## 導入: 章ごとに文体がバラつく問題

章を書くたびに「です・ます調で」「専門用語は避けて」と毎回指示するのは大変ですし、指示し忘れると章ごとに調子がバラつきます。本は1冊を通して文体がそろっていることが大事です。

文体やトーン、使ってよい用語・避けたい表現は、量が増えがちな「詳細なルール」です。これを CLAUDE.md 本体に全部書くと、CLAUDE.md が長くなって肝心の前提が埋もれます。そこで、文体ルールは `.claude/rules/` の別ファイルに切り出し、CLAUDE.md からは `@import` で取り込みます。CLAUDE.md は前提を簡潔に、rules は詳細を担当する、という分担です（Part3 で学んだ rules の実践です）。

## 実践: 文体を rules に切り出して @import する

### Step 1: 文体ルールをルールファイルに書く

`my-book` で起動し、文体・トーン・禁則・用語を1つのルールファイルにまとめさせます。置き場所は `.claude/rules/` です。

```text
この本の文体ルールを .claude/rules/writing-style.md にまとめてください。
次を含めてください。
- 文体・トーン（例: 敬体、初心者に語りかける調子）
- 避けたい表現・禁則（例: 専門用語を説明なしで使わない）
- 用語の統一（例: 「○○」と「△△」は「○○」に統一）
```

好みの文体（敬語の調子、見出しの付け方など）があれば、自分の言葉で材料として伝えます。返ってきた内容は読んで、自分の本の調子に合うよう直します。

!!! warning "注意"
    文体ルールは、点検できる具体性で書くと効きます。「読みやすく」のような曖昧な指示より、「一文を短く、専門用語は初出で一言補う」のように具体的に書きます。あとで（3-5-4 で第1章を書くときなど）文体が効いていないと感じたら、ルールが曖昧になっていないかを見直し、期待した調子と実際の文章のどこが違うかを Claude に具体的に伝えて直します。

### Step 2: CLAUDE.md から @import で取り込む

`.claude/rules/` に置いたファイルは起動のたびに自動で読み込まれますが、ここでは取り込みを明示する `@import` も試します。CLAUDE.md の中に、ルールファイルへの参照を1行加えてもらいます。

```text
CLAUDE.md に、@.claude/rules/writing-style.md を読み込む一行を加えてください。
そのうえで、CLAUDE.md 本体は前提だけの簡潔な状態に保ってください。
```

これで、前提（CLAUDE.md）と詳細な文体（rules）が、起動時にまとめて効くようになります。

### Step 3: セッションを切り替えても前提が効くことを確かめる

ここまでで、本の前提（CLAUDE.md）・目次（OUTLINE.md）・文体（rules）を、すべてファイルとして my-book に置きました。なぜファイルに置くのかを、実際にセッションを切り替えて確かめます。

Claude Code は、新しいセッションを始めるたびに、それまでの会話の記憶は 0 に戻ります。一方で、CLAUDE.md・OUTLINE.md・`.claude/rules/` のファイルは、起動のたびに自動で読み込まれます。会話の記憶が消えても、ファイルに書いた前提・目次・文体は失われません。毎回踏まえてほしいことを、会話ではなくファイルに置いているのは、このためです。

**1. いまの使用量を見る**

長く作業すると、コンテキスト（AI が一度に読む範囲。3-2）が膨らみます。切り替える前に、いまの使用量を見ます。

```text
/context
```

会話の履歴や読み込んだファイルが、それぞれどれだけ占めているかが内訳で表示されます（コンテキスト管理で見たものです）。コンテキストが埋まってくると、精度や速度が落ちます。

**2. セッションに名前をつける**

文体づくりが一区切りついたので、いまのセッションに名前をつけて、あとで見分けられるようにします。

```text
/rename 本の文体づくり
```

`/rename` は現在のセッションに名前をつけ、プロンプトバーにその名前を表示します（2026年6月時点）。名前を省くと、会話の履歴から自動でつけられます。名前を残しておくと、あとで一覧から探すときに見分けやすくなります。

**3. いったん終了して、開き直す**

セッションを終了します。

```text
/exit
```

ターミナルに戻ったら、もう一度 `claude` と打って起動します。

```text
claude
```

新しいセッションが始まり、さきほどまでの会話の記憶はありません。それでも、CLAUDE.md・OUTLINE.md・rules はファイルなので自動で読み込まれ、本の前提・目次・文体は最初から効いています。`/context` を打つと、これらが読み込まれているのが内訳に見えます。

**4. 前のセッションに戻れることを確かめる**

終了したセッションは消えていません。`/resume` で開きます。

```text
/resume
```

過去のセッションの一覧（ピッカー）が開きます。さきほど名前をつけた「本の文体づくり」が並んでいるはずです。矢印キーで選んで Enter を押すと、そのセッションの文脈ごと戻れます。Part3 の基本操作で `claude --resume` として学んだ再開を、セッションの中からは `/resume` で開ける、という関係です。

**5. 新しいセッションへ**

戻れることを確認したら、また区切りよく進められます。次の作業に移るときは、`/clear` で会話を空にすれば、前提はファイルに残ったまま新しく始められます（無関係な作業に切り替える `/clear` はコンテキスト管理で扱いました）。前のセッションは `/resume` の一覧に残っているので、必要になればいつでも戻れます。

!!! success "確認"
    名前をつけたセッションが `/resume` の一覧に表示されて戻れること、終了して開き直した新しいセッションでも CLAUDE.md・OUTLINE.md・rules の前提が最初から効いていることを確認できれば成功です。

!!! tip "区切りでセッションを切り替える"
    長く作業を続けてコンテキストが膨らんできたら、章を書き終えたなどの区切りのいいところで、`/rename` で名前を残してからセッションを切り替えるのがおすすめです。前提・目次・文体はファイルにあるので、新しいセッションでも失われません。会話だけを軽くして、すっきりした状態で次に進めます。

## まとめ

- 文体・トーン・禁則・用語は量が増えるので、CLAUDE.md 本体に書かず `.claude/rules/` に切り出す
- CLAUDE.md は前提を簡潔に、rules は詳細な文体を担当する分担にする
- ルールが効いていれば、毎回トーンを指示しなくても、章ごとの調子がそろう
- 前提・目次・文体をファイルに置いたので、記憶が 0 に戻る新しいセッションでも自動で読み込まれて効く
- 区切りのいいところで `/rename` で名前を残し、`/exit` で終了して開き直し、`/resume` で前のセッションに戻れる。コンテキストが膨らんだら名前をつけて新しいセッションに切り替えるとよい
