## 導入: 丸投げに足りなかったのは「前提」

最初に本を丸投げしたとき、誰に向けるか・何を中心にするかを何も渡しませんでした。だから Claude は解釈で埋め、狙いからずれた“それっぽい本”を返しました。

足りなかったのは「**前提**」です。「この本は誰のためのもので、何を、どんな狙いで伝え、何ができたら完成か」。これを毎回プロンプトに長々と書くのは大変ですし、書き忘れもします。そこで、本の前提を `CLAUDE.md` に一度書いておきます。Claude は起動のたびにこれを読むので、以降は短い指示でも前提を踏まえて動きます（Part3 で学んだ CLAUDE.md の実践です）。

## 実践: 本の前提を CLAUDE.md にする

### Step 1: 本のプロジェクト `my-book/` を作って開く

本専用のフォルダを新しく作ります（名前は自由ですが、本研修では `my-book` とします）。これは、丸投げで使った練習用のフォルダ `claude-practice` とは別の、これから育てていく本のプロジェクトです。フォルダを作ったら、`code .` で VS Code で開きます。

```bash
mkdir my-book
cd my-book
code .
```

`code .` で `my-book` が VS Code で開くので、以降はこの VS Code の統合ターミナル（メニューの「ターミナル」→「新しいターミナル」）で作業します。統合ターミナルに `claude` と打って Enter を押し、`my-book` を作業場所として Claude Code を起動します。

`my-book` は新しく始める本のプロジェクトなので、まだ中身は空です。これから前提・目次・文体・本文を足していくと、左のファイルツリーにそれらが増えていくのを目で追えます。前のセクションまでで考えたテーマ・想定読者・狙いは、このあと自分の言葉で Claude に伝えます（`claude-practice` の `theme.md` は自分用のメモとして見返すだけでよく、`my-book` に持ち込む必要はありません）。

### Step 2: `/init` で CLAUDE.md の雛形を作る

Claude Code で `/init` と打ちます。`/init` は、いまのプロジェクトを見て CLAUDE.md の雛形を作るコマンドです。`my-book` はまだ中身が薄いので、できる雛形も最小限です。ここでは「CLAUDE.md という前提ファイルの器ができた」ことを確認できれば十分で、中身はこのあと自分の言葉で埋めます。

```text
/init
```

### Step 3: 「誰に・何を・狙い・完成条件」を書く

ここがこのセクションの肝です。本の前提を、次の4点で Claude に下書きさせ、自分で読んで直し、`CLAUDE.md` に確定させます。前のセクションまでで考えたテーマ・想定読者・狙いを、自分の言葉で書いて渡すのがコツです。丸投げで物足りなかった点も一言添えると、それを避ける前提にできます。

```text
これから「（テーマ）」の入門書を書きます。想定読者は（例: ○○）、
いちばん伝えたいのは（例: △△）です。これを踏まえて、本の前提を
CLAUDE.md にまとめてください。次の4点を含めてください。
- 誰に: 想定読者（前提知識・困りごと）
- 何を: この本で扱う中心テーマと範囲
- 狙い: 読み終えた読者がどうなってほしいか
- 完成条件: 各章が「何ができていれば完成か」の方針
判断に迷う点があれば、勝手に決めず、AskUserQuestion で質問してください。
```

返ってきた下書きは、そのまま採用せず必ず自分で読みます。「想定読者が広すぎる」「狙いが弱い」と感じたら、具体的に伝えて直させます（例: 「想定読者を“まったくの初心者”に絞って」）。CLAUDE.md は長く書くほど効くものではないので、要点だけを簡潔に保ちます（目安は200行以内）。

!!! tip "ヒント: 迷ったら質問させる（AskUserQuestion）"
    Claude には、判断に迷ったとき、勝手に決めずに「**選択肢つきの質問**」をあなたに返す仕組みがあります（AskUserQuestion。2026年6月時点。各質問に2〜4個の選択肢が並び、おすすめの印や「その他（自由入力）」も選べます）。最初の丸投げで困ったのは、曖昧な部分を Claude が思い込みで埋めて的を外したことでした。プロンプトに「判断に迷う点は AskUserQuestion で質問して」と名前を挙げて頼むと、思い込みで進める代わりに、選択肢つきの質問で要所を確認してくれます（ただ「質問して」とだけ書くより、この仕組みを名指しするほうが確実です）。とくに Plan モード（Part3 で学習）と相性がよく、作り始める前に必要なことを聞いてくれます。

### Step 4: `/clear` のあとも効くことを確かめる

前提が本当に効いているかを確かめます。`/clear` で会話を空にしてから、前提に関わる短い質問をします。

```text
/clear
```

```text
この本の想定読者と狙いを、一言で説明して。
```

会話履歴は空になっているのに、Claude が CLAUDE.md を読んで想定読者と狙いを答えれば成功です。最初の丸投げでは毎回ゼロから説明が要りましたが、いまは前提がプロジェクトに常駐しています。

!!! warning "注意"
    `/clear` のあとに前提を踏まえない答えが返るときは、CLAUDE.md が `my-book` の直下に保存されていない、または別の場所で起動している可能性があります。`/memory` で、いま読み込まれている CLAUDE.md を確認できます。ずれていたら、「`my-book` の中の CLAUDE.md に前提を書きたい」と伝えて置き直してもらいます。

## まとめ

- 丸投げに足りなかったのは前提。「誰に・何を・狙い・完成条件」を `CLAUDE.md` に置くと、起動のたびに Claude がそれを踏まえる
