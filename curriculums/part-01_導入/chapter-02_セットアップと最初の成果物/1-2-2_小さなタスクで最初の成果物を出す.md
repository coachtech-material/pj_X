# 1-2-2 小さなタスクで最初の成果物を出す

!!! note "前提知識"
    このセクションは 1-2-1「Claude Code のインストールと認証」の内容を前提としています。

## このセクションで学ぶこと

- 小さなタスクを Claude Code に依頼し、成果物（ファイル）を1つ作る流れ
- AIが変更の前に確認を求め、許可を得てから実行すること
- 出てきた成果物を確認し、必要なら直してもらうこと

起動した Claude Code に小さなタスクを1つ任せ、AIが確認してから実行する流れを体験して、最初の成果物を手元に残します。

---

## 導入: まず小さく1つ任せてみる

Claude Code が起動できたら、次は実際に1つ任せてみます。難しいことはしません。これから本研修を通して育てていく「記事のテーマ」を決め、それを整理したメモを作ってもらいます。小さな依頼ですが、これだけで「依頼する → AIが確認を求める → 承認する → 成果物が残る」という、Claude Code の最も基本的な流れをひととおり体験できます。

---

## このセクションで作るもの

このあと Part を進めながら、あなたは1つのブログ記事を題材にして学んでいきます。次のセクション（1-3-1）でその記事づくりに初挑戦し、Part3・Part4 で作り込み、Part5 で公開します。その出発点として、ここでは **記事にしたいテーマのメモ** を作ります。

テーマは、あなたの関心や仕事に近いもので、短いブログ記事1本にできそうな題材を選んでください。たとえば次のようなものです。

- 自分の職種・業界を、これから学ぶ人に向けて紹介する
- 普段の業務で使っているちょっとしたコツを共有する
- 関心のあるテーマ（趣味・最近学んでいること）の入門解説

完璧なテーマである必要はありません。研修を通して育てていくので、いまは「これについてなら少し書けそう」と思えるものを1つ決めれば十分です。

## 確認してから実行する仕組み

Claude Code は、ファイルを作る・書き換えるといった操作の前に、必ず「これを実行してよいか」とあなたに確認を求めます。あなたが許可（承認）すると、初めて実際にファイルへ手を入れます。確認なしに勝手に進むことはありません。

この「確認して実行する」仕組みがあるおかげで、AIに任せても、何が行われるかを把握しながら進められます。承認のやり方や権限の細かい仕組みは Part3 で詳しく扱います。いまは「変更の前に確認が入る。許可すれば進む」とだけ押さえておけば十分です。

---

## 実践: 小さなタスクを依頼して成果物を残す

### Step 1: Claude Code を起動する

1-2-1 と同じ手順でターミナルを開き、`claude` と打って Enter を押して起動します。前回ログインを済ませているので、すぐに入力画面（プロンプト）が表示されます。

```bash
claude
```

!!! note "補足"
    ここでは、ターミナルが最初に開いた場所（多くは、あなたのユーザーフォルダ＝ホーム）で起動します。これから作るファイルは、その場所に作られます。「どの場所で起動し、どこにファイルができるか」という考え方は Part2（2-1）でしっかり扱うので、いまはそのまま進めて構いません。

### Step 2: テーマのメモを作ってもらう

入力画面に、次のように依頼を打ち込み、Enter を押します。`「（ここにテーマ）」` の部分を、先ほど「このセクションで作るもの」で決めた自分のテーマに置き換えてください。

```text
claude-practice というフォルダを作り、その中に theme.md というファイルを作ってください。
内容は、私がブログ記事にしたいテーマ「（ここにテーマ）」について、
・なぜ関心があるか
・誰に向けて書きたいか
・記事で触れたい論点
を、それぞれ簡単な箇条書きで整理したメモにしてください。
```

Claude Code は、依頼を理解すると、フォルダとファイルを作る準備を始め、どんな内容のファイルを作るかを画面に示します。

### Step 3: 提案された変更を承認する

Claude Code は、ファイルを作る前に「この内容で作成してよいか」と確認を求めてきます。画面に、許可する／しないの選択肢が番号付きで表示されるので、案内に従って許可（「はい」に当たるもの）を選びます。多くの場合、その番号を選ぶか Enter を押すと先に進みます。選択肢の細かい意味は Part3 で扱います。

承認すると、Claude Code が実際に `claude-practice` フォルダと `theme.md` を作成します。

!!! note "補足"
    Claude が画面に示すメモの文面は、依頼やそのときの状況によって毎回少しずつ変わります。ここで大事なのは、文面が見本と一字一句同じことではなく、「あなたのテーマを整理したメモのファイルが1つ作られる」ことです。気に入らなければ、このあとの Step 5 で直してもらえます。

### Step 4: できたファイルを確認する

作成が終わったら、ファイルが本当にできているかを自分の目で確かめます。ふだんファイルを見る画面（macOS は Finder、Windows はエクスプローラー）で、自分のユーザーフォルダ（ホーム）を開きます。その中に `claude-practice` フォルダがあり、さらにその中に `theme.md` があるはずです。`theme.md` を開くと、あなたのテーマが箇条書きで整理されています。

これが、あなたが Claude Code に作らせた最初の成果物です。

### Step 5: 必要なら直してもらう

メモを読んで、直したいところがあれば、続けて Claude Code に伝えます。たとえば次のように頼みます。

```text
「誰に向けて書きたいか」を、もう少し具体的な読者像にしてください。
```

Claude Code は、また変更内容を示して確認を求めてきます。承認すれば `theme.md` が更新されます。思いどおりになるまで、この「伝える → 確認 → 承認」を何度でも繰り返せます。これが、AIに任せて成果物を仕上げていくときの基本的なやり取りです。

確認が終わったら、`/exit` と打って Enter を押し、Claude Code を終了します。作った `theme.md` は、次のセクション以降でも使うので、消さずに残しておいてください。

次の状態になっていれば、このセクションは完了です（Claude が作ったメモの文面そのものは、人によって違って構いません）。

- [ ] 記事にしたいテーマを1つ決めた
- [ ] Claude Code に依頼し、確認を承認して `theme.md` を作成した
- [ ] Finder／エクスプローラーで `theme.md` を開き、テーマが整理されているのを確認した
- [ ] （必要に応じて）直しを依頼し、メモを更新できた

## まとめ

- Claude Code への依頼は、やりたいことを文章で伝えるだけ。AIが自分でファイルを作り、成果物として残す
- AIはファイルを作る・変える前に必ず確認を求め、承認して初めて実行する（仕組みの詳細は Part3）
- 出てきた成果物は自分の目で確認し、直したいところは「伝える → 確認 → 承認」を繰り返して仕上げていく
- ここで作ったテーマのメモは、このあとの記事づくりの出発点になる

---

次のセクションからは、Chapter 1-3 に入ります。いま決めたテーマで、今度は「ちゃんとした記事を1本書いて」と一息に丸投げしてみます。すると、出てきた記事が浅かったり狙いからずれたりすることを、身をもって体験します。その失敗が、AIにうまく任せるための考え方を学ぶ出発点になります。
