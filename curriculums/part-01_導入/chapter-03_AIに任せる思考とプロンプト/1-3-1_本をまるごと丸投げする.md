# 1-3-1 本をまるごと丸投げする

この Chapter では、AIにうまく任せるための「考え方」を学びます。まず本を一息に丸投げして「思いどおりにいかない」ことを体験し、その教訓として、プロンプトとリスク、仮説で当てる進め方、構造化とアウトカムから決める完成条件を順に押さえます。

| セクション | テーマ | 種類 |
|---|---|---|
| 1-3-1 | 本をまるごと丸投げする | ハンズオン |
| 1-3-2 | プロンプトのフレームワークとAIに任せるリスク | 概念 |
| 1-3-3 | 仮説で当てる | 概念 |
| 1-3-4 | 構造化とアウトカムから決める完成条件 | 概念 |

**この Chapter の進め方**: まず手を動かすこのセクションで「うまくいかない」を体験し、続く概念セクションでその理由と対策を学びます。手を動かすのはこのセクションだけで、残りは読んで理解する概念です。ここで学んだ考え方を使って本をきちんと書き始めるのは Part3 になります。

!!! note "前提知識"
    このセクションは 1-2-3「小さなタスクで最初の成果物を出す」の内容を前提としています。

!!! note "このハンズオンで使う機能"
    Part1 のセットアップで学んだ「依頼する・確認を承認する・成果物を残す」流れだけを使います。あえて段取りも前提づくりもしません（うまくいかなさを体験するのが狙いです）。

## このセクションで学ぶこと

- 段取りせずに一息で「○○について本を書いて」と丸投げするとどうなるか
- いまの Claude なら“それっぽい本”は出るが、深さ・狙い・正しさが物足りないこと
- その物足りなさを言葉にして書き出すこと

あえて段取りをせずに本を丸投げし、出力が思いどおりにならないことを体験します。この「うまくいかない」感覚が、次のセクションからの学びの出発点になります。

!!! note "補足"
    このハンズオン以降、Claude に作らせる文章やコードは、同じ依頼でも人や実行のたびに変わります。本研修のコード例・出力例は「こう返ることがある」という一例で、あなたの手元と一字一句同じにはなりません。大事なのは“同じ文面になること”ではなく、各ステップのゴール（観察できる状態）に届くことです。例と違っても、自分の出力に合わせて読み替えて進めてください。

## 導入: 「本を1冊書いて」で、良い本は出るか

前のセクションで、Claude Code に依頼すれば成果物が返ってくることを体験しました。では、もっと大きなお願い、たとえば「○○について本を1冊書いて」と一息に頼んだら、満足のいく本が出てくるのでしょうか。

このセクションでは、あえてそれを段取りせずにやってみます。狙いは、良い本を完成させることではありません。丸投げするとどう外れるのかを、自分の手で確かめることです。ここでの「うまくいかなさ」が、AIへの上手な任せ方を学ぶ強い動機になります。

## このハンズオンの題材

題材は、前のセクションで `theme.md` に整理した、あなたのテーマです。このテーマは本研修を通して使い続けます。ただし、いま丸投げするファイルは“失敗を見るための下書き”であって、本そのものをここで育てるわけではありません。本のプロジェクトは Part3 で新しく立ち上げ、そこから本腰を入れて育てます（題材＝テーマは同じ、置き場所＝フォルダは別、と覚えてください）。

- いま: 砂場のフォルダ `claude-practice` に丸投げして、うまくいかないことを体験する（この下書きは“before”として残す）
- Part3: 本のプロジェクトを新しく作り、前提・目次・文体を整えて第1章を書き、その手順をスキルに残す
- Part4: 仕様駆動と仕組み化で、残りの章まで書き切る
- Part5: 書き上げた本を公開する

つまり、テーマはこれから何度も立ち返りますが、今回の下書きはあくまで出発点です。今回うまくいかないほど、この先で整えていく意味がはっきりします。

## 実践: 段取りせず一息に丸投げする

### Step 1: Claude Code を起動する

前のセクションと同じ場所でターミナルを開き、`claude` と打って Enter で起動します。

```bash
claude
```

### Step 2: 一息に「本を書いて」と頼む

ここがこのハンズオンの肝です。段取りをいっさいせず、次のように一息で丸投げします。`「（テーマ）」` は自分のテーマに置き換えてください。読者・章立て・狙い・長さなどは、あえて何も指定しません。

```text
「（テーマ）」について、入門書を1冊書いて、
claude-practice フォルダの中に book-draft1.md として保存してください。
```

Claude Code は本文を書き、確認を求めてきます。前のセクションと同じように承認して、`book-draft1.md` を作成させます。1冊ぶんなので、章ごとの見出しがついた、それなりの分量のファイルになるはずです。

!!! warning "注意"
    作成された `book-draft1.md` が `claude-practice` の中に見当たらない、または別の場所にできてしまったときは、Claude Code を起動した場所が前のセクションのときと違っている可能性があります（起動した場所にファイルが作られます。詳しくは Part2 で扱います）。その場合は、「`claude-practice` の中に作ってほしかった」のように、期待した結果と実際の様子を Claude にそのまま伝えれば、置き直してくれます。

### Step 3: 出てきた本を読む

作成された `book-draft1.md` を、Finder／エクスプローラーで開いて読んでみます（`claude-practice` フォルダの中にあります）。ひととおり目を通してください。

一見すると、章立ても整い、それらしい体裁の本になっているはずです。いまの Claude は、丸投げでも“それっぽい本”を返せます。けれども、自分が「こういう本にしたかった」と思っていたものと比べると、いくつも物足りなさが見えてくるはずです。

### Step 4: 物足りなさを書き出す

感じた物足りなさを、具体的に言葉にします。次の3つの観点で、気づいた点を手元のメモ（紙でも、`theme.md` への追記でも構いません）に書き出してみてください。

- **深さ**: どこかで読んだような一般論ばかりで、踏み込みが浅い。あなたが本当に伝えたい勘所まで届いていない
- **狙い**: 想定していた読者や、いちばん伝えたかったことと合っていない。誰向けの本かが曖昧
- **正しさ**: 事実や数字、固有名詞があやしい。出典が示されておらず、そのまま信じてよいか分からない

書き出せたら、`/exit` で Claude Code を終了します。`book-draft1.md` は、あとで Part3 できちんと書く第1章と見比べるために、消さずに残しておいてください。

## 丸投げが外れる理由

同じ Claude Code が、前のセクションでは役立つメモを作ってくれたのに、今回は物足りない本を返しました。能力が足りないわけではありません。理由は、こちらの頼み方にあります。

「入門書を1冊書いて」とだけ伝えたとき、誰に向けるか、何を中心に据えるか、どんな章立てにするか、どこまで踏み込むかを、あなたは何も指定していません。指定がない部分は、AIが自分で解釈して埋めます。その解釈が、あなたの頭の中にある狙いと一致する保証はありません。だから、ずれます。そして本のように大きな仕事ほど、埋められた箇所が積み重なり、ずれも大きくなります。

この「曖昧さをAIが解釈で埋める」という仕組みと、その埋め方をこちらから的確に導く方法が、次のセクション以降のテーマです。

## まとめ

- 段取りせず「本を1冊書いて」と丸投げすると、いまの Claude は“それっぽい本”を返すが、深さ・狙い・正しさが物足りないものになりやすい
- 原因はAIの能力不足ではなく、頼み方の曖昧さ。指定しなかった部分は、AIが自分の解釈で埋める。大きな仕事ほどそのズレは大きくなる
- 題材のテーマはこの先も使い続け、本のプロジェクトは Part3 で新しく立ち上げて育て、Part4 で書き切り、Part5 で公開する。今回うまくいかないほど、この先の学びがはっきりする

---

次のセクションでは、なぜ丸投げが外れたのかを「指示が曖昧だとAIが解釈で埋めて的を外す」という観点から掘り下げます。そのうえで、曖昧さを埋めて狙いを伝えるプロンプトのフレームワーク（役割・文脈・指示・制約・出力形式など）と、AIに任せること自体のリスク（誤りを自信ありげに返す、確認なしに進む）を押さえます。
