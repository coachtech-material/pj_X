# 1-3-1 ブログ記事を丸投げする

この Chapter では、AIにうまく任せるための「考え方」を学びます。まず記事を一息に丸投げして「思いどおりにいかない」ことを体験し（1-3-1）、その教訓として、プロンプトとリスク（1-3-2）、仮説で当てる進め方（1-3-3）、構造化とアウトカムから決める完成条件（1-3-4）を順に押さえます。

| セクション | テーマ | 種類 |
|---|---|---|
| 1-3-1 | ブログ記事を丸投げする | ハンズオン |
| 1-3-2 | プロンプトのフレームワークとAIに任せるリスク | 概念 |
| 1-3-3 | 仮説で当てる | 概念 |
| 1-3-4 | 構造化とアウトカムから決める完成条件 | 概念 |

**この Chapter の進め方**: 1-3-1 で「うまくいかない」を実際に体験し、1-3-2 から 1-3-4 でその理由と対策を学びます。手を動かすのは 1-3-1 だけで、残りは読んで理解する概念です。ここで学んだ考え方を使って記事を実際に作り直すのは Part3（3-5）になります。

!!! note "前提知識"
    このセクションは 1-2-2「小さなタスクで最初の成果物を出す」の内容を前提としています。

!!! note "このハンズオンで使う機能"
    1-2-2 で学んだ「依頼する・確認を承認する・成果物を残す」流れを使います。ここで丸投げする記事の題材は、3-5-1 で手順立てて作り直し、4-4 でその記事を起点に学習ドキュメントへ広げて執筆を仕組み化し、5-2-5 で公開する、同じテーマの題材です（テーマはあなたが 1-2-2 で選んだもの）。

## このセクションで学ぶこと

- 段取りせずに一息で「ちゃんとした記事を書いて」と丸投げするとどうなるか
- 出てきた記事が、浅かったり狙いからずれたりすること
- そのズレを言葉にして書き出すこと

あえて段取りをせずに記事を丸投げし、出力が思いどおりにならないことを体験します。この「うまくいかない」感覚が、次のセクションからの学びの出発点になります。

---

## 導入: 「ちゃんとした記事を書いて」で、良い記事は出るか

1-2-2 で、Claude Code に依頼すれば成果物が返ってくることを体験しました。では、もっと大きなお願い、たとえば「ちゃんとした記事を1本書いて」と一息に頼んだら、満足のいく記事が出てくるのでしょうか。

このセクションでは、あえてそれを段取りせずにやってみます。狙いは、良い記事を完成させることではありません。丸投げするとどう外れるのかを、自分の手で確かめることです。ここでの「うまくいかなさ」が、AIへの上手な任せ方を学ぶ強い動機になります。

---

## このハンズオンの題材

題材は、1-2-2 で `theme.md` に整理した、あなたのテーマです。このテーマの記事は、本研修を通してずっと使い続けます。

- いま（1-3-1）: 段取りせず丸投げして、うまくいかないことを体験する
- 3-5-1: 手順を立てて、1本きちんと作り直す
- 4-4: その記事を起点に、執筆を仕組み化して学習ドキュメント（章・節）へ広げる
- 5-2-5: できあがった学習ドキュメントを公開する

つまり、これから何度も立ち返る題材です。今回うまくいかなくても、まったく問題ありません。

## 丸投げ前の確認

始める前に、次がそろっているか確認します。

- [ ] Claude Code にログイン済みで、`claude` で起動できる（1-2-1）
- [ ] 記事にしたいテーマを決めてあり、`theme.md` が `claude-practice` フォルダにある（1-2-2）

## 実践: 段取りせず一息に丸投げする

### Step 1: Claude Code を起動する

1-2-2 と同じ場所（ホーム）でターミナルを開き、`claude` と打って Enter で起動します。

```bash
claude
```

### Step 2: 一息に「記事を書いて」と頼む

ここがこのハンズオンの肝です。段取りをいっさいせず、次のように一息で丸投げします。`「（テーマ）」` は自分のテーマに置き換えてください。読者・長さ・構成・狙いなどは、あえて何も指定しません。

```text
「（テーマ）」について、ちゃんとした記事を1本書いて、
claude-practice フォルダの中に article-draft1.md として保存してください。
```

Claude Code は記事を書き、確認を求めてきます。1-2-2 と同じように承認して、`article-draft1.md` を作成させます。

!!! warning "注意"
    作成された `article-draft1.md` が `claude-practice` の中に見当たらない、または別の場所にできてしまったときは、Claude Code を起動した場所が 1-2-2 のときと違っている可能性があります（起動した場所にファイルが作られます。詳しくは Part2 の 2-1 で扱います）。その場合は、「`claude-practice` の中に作ってほしかった」のように、期待した結果と実際の様子を Claude にそのまま伝えれば、置き直してくれます。

### Step 3: 出てきた記事を読む

作成された `article-draft1.md` を、Finder／エクスプローラーで開いて読んでみます（`claude-practice` フォルダの中にあります）。最後まで目を通してください。

一見すると、それらしい体裁の記事になっているはずです。けれども、自分が「こういう記事にしたかった」と思っていたものと比べると、どこか物足りなさを感じるところがあるはずです。

### Step 4: 狙いとのズレを書き出す

感じた物足りなさを、具体的に言葉にします。次のような観点で、気づいた点を3つほど、手元のメモ（紙でも、`theme.md` への追記でも構いません）に書き出してみてください。

- **浅い**: どこかで読んだような一般論ばかりで、踏み込みが足りない
- **狙いからずれている**: 想定していた読者や、いちばん伝えたかったことと合っていない
- **過不足がある**: 触れてほしい話がなかったり、逆に不要な話が多かったりする

書き出せたら、`/exit` で Claude Code を終了します。`article-draft1.md` は、3-5-1 で作り直したものと見比べるために、消さずに残しておいてください。

## なぜ、こうなるのか

同じ Claude Code が、1-2-2 では役立つメモを作ってくれたのに、今回は物足りない記事を返しました。能力が足りないわけではありません。理由は、こちらの頼み方にあります。

「ちゃんとした記事を書いて」とだけ伝えたとき、「ちゃんとした」が何を指すか、誰に向けるか、何を中心に書くかを、あなたは何も指定していません。指定がない部分は、AIが自分で解釈して埋めます。その解釈が、あなたの頭の中にある狙いと一致する保証はありません。だから、ずれます。

この「曖昧さをAIが解釈で埋める」という仕組みと、その埋め方をこちらから的確に導く方法が、次のセクション以降のテーマです。

---

## まとめ

- 段取りせず「ちゃんとした記事を書いて」と丸投げすると、一見それらしくても、浅い・狙いからずれる・過不足がある記事になりやすい
- 原因はAIの能力不足ではなく、頼み方の曖昧さ。指定しなかった部分は、AIが自分の解釈で埋める
- この丸投げの記事は、3-5-1 で作り直し、4-4 でその記事を起点に学習ドキュメントへ広げて仕組み化し、5-2-5 で公開する。今回うまくいかないほど、この先の学びがはっきりする

---

次のセクションでは、なぜ丸投げが外れたのかを「指示が曖昧だとAIが解釈で埋めて的を外す」という観点から掘り下げます。そのうえで、曖昧さを埋めて狙いを伝えるプロンプトのフレームワーク（役割・文脈・指示・制約・出力形式など）と、AIに任せること自体のリスク（誤りを自信ありげに返す、確認なしに進む）を押さえます。
