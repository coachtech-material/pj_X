# pj_X｜エンジニア教育カリキュラムの設計（いいコンサルタントの設計）

COACHTECH のカリキュラム刷新プロジェクト（pjX）のドキュメントリポジトリ。
AI の進化に伴い、コードを書くだけでなく上流工程（要件定義の前の工程）まで関われるエンジニアを育てるカリキュラムを設計する。

キックオフミーティングの整理内容（元はスプレッドシート）を Markdown 化して管理している。

| ファイル | 内容 |
|---|---|

| [02_ペルソナ.md](02_ペルソナ.md) | 想定する受講者のタイプ（A・B・C）と共通前提 |

## 閲覧について

- ドキュメントは **GitHub上でそのまま閲覧する**（Markdownがレンダリング表示される。スマホはGitHubアプリでも可）。
- 閲覧にはこのリポジトリへのアクセス権が必要。メンバーには Settings → Collaborators and teams から閲覧権限（Read）を付与する。

## 運用ルール

- **正とするのは Markdown ファイル**。`元スプシ/` は変換時点のアーカイブであり、以後は更新しない。
- 論点のステータス（未決・仮決・仮合意・宿題・要確認・検討中・未着手）は [06_論点.md](06_論点.md) で管理する。
- **MVP対象外の項目は削除せず [07_MVP対象外.md](07_MVP対象外.md) に移す**。学習項目の番号は元スプシとの対応を保つため欠番のまま詰めない。
- まとまった修正はPull Request経由で行い、マイルストーンごとに `vN-名前` 形式のタグを打つ。修正前後の差分はタグ間のCompare（例: [v0→v1](https://github.com/estra-inc/pj_X/compare/v0-kickoff...v1-mvp)）で見る。

## 到達レベルの凡例

ドキュメント全体で使う到達レベルの略記。

| 略記 | 名称 | 意味 |
|---|---|---|
| L1 | 現場に出せる | 卒業時の目標。報酬をもらって案件に入り、上流の初動ができる |
| L2 | 中堅コンサル | 案件で信頼を得て単価を上げ、上流に深く関わり、自分で設計できる |
| L3 | ベイカレント級 | 高度な設計・複雑な案件・PMまで。技術とコンサルの両面で高水準 |

※ 上記とは別に、[04_学習項目.md](04_学習項目.md) の「レベル0〜5」はビジネス系スキルの階層（学ぶ順序）を表す。
